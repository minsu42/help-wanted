## Context

### 무엇이 바뀌었나

2026-08-10, 사용자가 **의뢰서를 확정**했다. 그 결정이 청취의 타입 표면을 세 곳에서
바꾼다.

| 확정된 것 | 타입에 미치는 영향 |
| ---- | ---- |
| 자동 기록 **7항목** (`의뢰 종류·대상·규모·장소·기한·경로·**특징 및 약점**`) | **`SlotName`이 6→7** (ADR-001 D1 번복) |
| 각 항목 상태 표시 **확정/모호/미확인**, **플레이어 수정 불가** | **저장 어휘와 표시 어휘가 갈린다** — 새 타입이 필요하다 |
| 플레이어 입력은 **위험도 등급 `D/C/B/A/S` 하나뿐** | **등급 타입 신설**, 그리고 자유 텍스트가 청취에서 완전히 사라진다 |

함께 **삭제된 것**: 시스템 추천 등급 · 권장 인원 · 자유 서술 특이사항 · 전술/장비/시각
지시 · **자유 서술을 판독하는 LLM 대비 추출**. 자유 메모는 필요하면 **개인 수첩**으로만
주어지며 **게임 판정에 쓰지 않는다.**

### 판정이 어떤 모양이 됐는가 — 타입 결정의 근거

```
실제 위험  T   콘텐츠별 명시. D=3 C=4 B=5 A=6 S=7. 숨김 — 파견 후 공개
대비       C   자동 기록된 관련 사실의 충실도. 규칙이 계산한다. LLM이 없다
파티 역량  P

판정:  D = P + C − T
```

플레이어가 매긴 등급은 **`D`의 항이 아니다** — 지원·배정에 영향을 주고, 결과는
`P + C − T`가 낸다. **이 비대칭이 D5의 이유다**: 등급은 판정에 직접 들어가지 않지만
하류가 읽는 값이므로 타입에 존재해야 하고 저장되어야 한다.

### 제약

1. **결정론** — 같은 시드 + 같은 입력이면 항상 같은 결과 (기둥 5)
2. **기둥 6** — *내가 쓴 것이 사람을 죽인다.* `미상`(태만)과 `막힘`(불가항력)의 구별이
   P2 책임 귀속의 유일한 근거다 (ADR-001 D2)
3. **실제 위험은 숨김** — 파견 후에만 공개된다. **세이브를 열어보는 것으로 새면 안 된다**
4. **LLM은 판정 경로에 없다** — 게임 상태에 닿는 LLM 출력이 0개다 (ADR-003 확정 개정)
5. **밸런스 하드코딩 금지** — `T` 값·`C` 가중치는 `quest-templates.json`·`balance.json`
6. **런타임 의존성 0개**

## Decision

### D1. 칸 어휘를 7개로 확장한다 — `특징 및 약점`을 신설

```ts
/**
 * 의뢰가 가질 수 있는 빈칸의 전체 목록. **닫힌 유니온이다** (ADR-001 D1의 성질 유지).
 *
 * 2026-08-10: 의뢰서 자동 기록 7항목 확정으로 `'weakness'`가 신설됐다.
 */
export type SlotName =
  | 'kind' | 'target' | 'scale' | 'place' | 'deadline' | 'route'
  | 'weakness';   // 특징 및 약점 — 2026-08-10 신설

export const SLOT_NAMES: readonly SlotName[] = [
  'kind', 'target', 'scale', 'place', 'deadline', 'route',
  'weakness',   // ← 반드시 맨 뒤 (아래 RNG 순서 참조)
];
```

**`weakness`는 다른 여섯과 성격이 다르다.** 나머지는 *무슨 일인가*를 좁히지만, 이 칸은
*"햇빛을 꺼린다"*, *"왼팔을 못 쓴다"* 처럼 **파티가 준비할 거리**를 준다. 그래서
**대비 `C`를 가장 크게 올리는 항목이며**, `quest-templates.json`의 `weight`가 다른 칸보다
높게 잡히는 유일한 칸이다.

#### RNG 소비 순서에서는 **맨 뒤**에 넣는다

ADR-001 D6이 `SLOT_NAMES`의 배열 순서를 **저장 포맷의 일부처럼 취급한다**고 못박았다.
새 칸을 중간에 끼우면 그 뒤 모든 칸의 뽑기가 밀리고 **기존 시드가 전부 다른 세계를
만든다.**

**맨 뒤에 넣으면 기존 여섯 칸의 뽑기 순서가 보존된다** — `weakness`가 열리지 않는
의뢰 종류에서는 소비가 0이므로 **시드가 아예 안 갈린다.**

> **실비용은 지금 0이다** (세이브 0개, 구현 0줄). 그래도 규칙을 못박는 이유:
> **다음 칸이 추가될 때는 비용이 0이 아니다.** 이 ADR이 정하는 것은 `weakness`의
> 자리가 아니라 **"새 칸은 맨 뒤에 붙인다"는 규칙**이다.

> **명명 결정 — 런타임 리터럴은 `'weakness'`로 확정한다.**
> 확정 설계의 한국어는 「특징 **및** 약점」인데 리터럴은 `'weakness'`로 잡았다.
> `'trait'`을 쓰지 않은 이유는 **`Client.traits`와 grep이 섞이기 때문**이다
> (ADR-001 Alternatives가 `traits`의 소비처를 늘리는 것을 이미 기각했다).
> 대신 영문 리터럴만 보면 「특징」 쪽이 약해진다. 한국어 표시명은 `text.json`이
> 소유하므로 **표시에는
> 영향이 없고 코드 리터럴만의 문제**다.

### D2. `Limiter`에서 `'question'`을 제거한다 — ADR-001 D3의 명시적 번복

```ts
/** 칸이 더 열리지 않은 이유. **2값이다.** */
export type Limiter =
  | 'knowledge'    // 의뢰인이 모른다 (무지)
  | 'disclosure';  // 알지만 말하지 않는다 (은폐)
```

**근거는 두 겹이고 둘 다 이미 일어난 일이다:**

1. **v6.1 R4** — 묻기가 무료가 되고 질문 깊이 등급이 폐기됐다. 플레이어는 칸을 짚을
   뿐이고 깊이는 칸의 다음 단계로 자동 결정된다. *"뭉툭하게 물었다"* 는 **사건이
   발생하는 분기가 판정에 없다**
2. **의뢰서 확정 설계** — 플레이어의 입력이 위험도 등급 하나로 줄었다. 청취 전체에
   **플레이어의 표현력이 벽이 되는 지점이 남아 있지 않다**

ADR-001은 이 값을 넣으면서 *"2값으로 두면 `knowledge`로 뭉개게 되고, 이 저장소가
소문 시스템에서 이미 한 번 낸 사고와 같은 형태가 된다"* 고 적었다. **그 걱정은 옳았고
이제 대상이 없다** — 뭉갤 세 번째 경우가 존재하지 않는다.

> **도달 불능 값을 타입에 남겨 두는 것이 더 비싸다.** 남겨 두면 (1) 구현자가 그 분기를
> 처리하는 코드를 쓰고, (2) `text.json`이 나오지 않을 문안 7종을 갖게 되고,
> (3) 테스트가 도달할 수 없는 경우를 검증하려다 가짜 통과를 만든다.

### D3. 칸 상태는 **저장 5종 / 표시 3종**으로 분리한다 — **이 ADR에서 가장 중요한 결정이다**

의뢰서가 `확정/모호/미확인` 3종으로 보여준다는 확정 설계는 **표시 규격이지 저장
규격이 아니다.** 둘을 갈라 놓는다.

#### 저장 — 5종을 반드시 유지한다 (ADR-001 불변)

ADR-001 D2·D4의 `SlotState` 4종 + `Limiter`가 만드는 **구별 가능한 5종**이다.
**타입의 모양을 바꾸지 않는다** — 평탄화하지 않고 `(state, limiter?)` 쌍을 유지한다.

| # | `(state, limiter)` | 뜻 |
| ---- | ---- | ---- |
| 1 | `('unknown', —)` | **미상** — 묻지 않았다. **플레이어의 태만** |
| 2 | `('blocked', 'knowledge')` | **막힘(무지)** — 물었으나 의뢰인이 모른다 |
| 3 | `('blocked', 'disclosure')` | **막힘(은폐)** — 알지만 말하지 않는다 |
| 4 | `('vague', —)` | **어렴풋** |
| 5 | `('certain', —)` | **확실** |

#### 표시 — 3종은 **파생 뷰**다. 저장하지 않는다

```ts
/**
 * 의뢰서에 **찍혀 보이는** 것. **저장 대상이 아니다** — 칸 상태에서 파생한다.
 *
 * 리터럴이 `SlotState`의 어느 값과도 겹치지 않는 것은 **의도**다.
 * 겹치면 잘못된 자리에 대입해도 컴파일이 통과한다.
 */
export type SheetMark = 'confirmed' | 'ambiguous' | 'unfilled';

export function sheetMark(p: SlotProgress): SheetMark {
  if (p.state === 'certain') return 'confirmed';   // 확정
  if (p.state === 'vague')   return 'ambiguous';   // 모호
  return 'unfilled';                                // 미확인 ← 1·2·3을 전부 덮는다
}
```

**`'unfilled'`(미확인)가 저장 3종(`미상`·`막힘(무지)`·`막힘(은폐)`)을 한꺼번에 덮는다.**
이 함수는 **한 방향으로만 흐른다** — 역함수가 없고, 있어서도 안 된다.

#### 왜 표시 3종을 저장에 쓰면 기둥 6이 무너지는가

> **의뢰서에 보이는 것으로 저장하면 `미상`과 `막힘`이 한 값으로 합쳐진다.**
> 그리고 그 둘의 차이는 **P2에서 책임과 억울함을 가르는 유일한 근거다.**

구체적으로 무엇이 죽는지 적는다. 파티가 죽어 돌아왔고 `경로` 칸이 비어 있었다:

| 실제로 있었던 일 | 저장 5종 | 표시 3종만 저장하면 |
| ---- | ---- | ---- |
| 플레이어가 **경로를 묻지 않았다** | `미상` | `미확인` |
| 물었고 의뢰인이 **정말 몰랐다** | `막힘(무지)` | `미확인` |
| 물었고 의뢰인이 **알면서 숨겼다** | `막힘(은폐)` | `미확인` |

왼쪽이면 P2가 *"당신은 묻지 않았다"*, *"물을 만큼 물었으나 그는 몰랐다"*,
**"그는 당신에게 거짓말을 했다"** 를 각각 말할 수 있다. **오른쪽이면 셋 다 「미확인」
한 줄이고, 게임이 플레이어에게 할 말이 사라진다.** 기둥 6(*내가 쓴 것이 사람을 죽인다*)과
기둥 7(*모든 해결은 새 문제를 만든다*)이 동시에 딛고 선 것이 정확히 이 구별이다.

**그리고 이 손실은 복구 불가능하다** — 표시로 저장한 순간 정보가 사라지고, 시드가
같아도 되살릴 수 없다(청취는 플레이어 입력에 의존하므로 재계산이 아니라 재플레이가
필요하다).

> **⚠ 이 실수는 이 저장소에서 재발하기 쉬운 것으로 이미 지목돼 있다.**
> ADR-001 D2가 *"`roadmap.md`의 P1 절이 슬롯을 3상태로 적고 있었다(`blocked` 누락).
> **같은 실수가 재발하기 쉬운 지점이다**"* 라고 경고했다.
> **의뢰서가 3종으로 보여준다는 확정 설계가 그 실수를 다시 초대한다** — 화면이 3종이니
> 타입도 3종이면 되겠다는 것이 자연스러운 오독이다. 이 D3이 존재하는 이유가 그것이다.

### D4. 재현 키는 `(칸, 행동, 재료?)` 시퀀스다 — **여기서 소유하고 끝낸다**

```ts
/** 청취 한 수(手). **이 시퀀스가 재현 키의 전부다.** */
export interface IntakeMove {
  readonly slot: SlotName;
  readonly action: IntakeAction;
  readonly materialId?: string;   // 재료(단서 등)를 쓴 경우에만
}
```

이 한 줄이 **세 문서에 흩어져 세 번 낡았다**:

| 시점 | 재현 키 | 왜 죽었나 |
| ---- | ---- | ---- |
| 최초 | 매칭된 질문 id | 질문 카탈로그 모델 폐기 |
| GDD 3차 | 분류 결과 `(노드 id, 화법)` | v6.1이 분류를 폐기 |
| v6.1~현재 | **`(칸, 행동, 재료?)` 시퀀스** | — |

ADR-001 「다음 ADR 후보」, ADR-002 Context, ADR-003 D4가 각자 이 줄의 사본을 들고
있었고 **한때 서로 어긋났다.** 이제 **소유자는 이 D4 하나**이고 나머지는 참조다.

**이것이 순수한 플레이어 입력이라는 점이 결정적이다.** ADR-003 확정 개정으로 LLM이
판정 경로에서 완전히 빠졌으므로 **재현에 비결정 요소가 0개다.** ADR-002 D2(최종 상태
직접 저장)의 감사 로그가 이 타입을 그대로 쓴다.

### D5. 위험도 등급은 **세 값이 타입에서 구별**되어야 한다

```ts
/** 위험도 등급. **필요한 파티 수준**을 뜻한다. */
export type RiskGrade = 'D' | 'C' | 'B' | 'A' | 'S';
```

세 값이 **서로 다른 자리**에 산다. 한 필드로 뭉치면 P2가 죽는다.

| 값 | 어디에 | 누가 정하나 | 저장 |
| ---- | ---- | ---- | ---- |
| **주장 등급** `statedGrade` | `Contract` | 의뢰인 (틀릴 수 있다. 거짓일 수 있다) | ✅ |
| **판정 등급** `playerGrade` | 의뢰서 (플레이어 측) | **플레이어 — 의뢰서의 유일한 입력** | ✅ **반드시** |
| **실제 위험** `T` | 의뢰 데이터 | 콘텐츠 (`D=3 C=4 B=5 A=6 S=7`) | ⚠ **평문 금지 (D6)** |

**`playerGrade`가 `Contract`가 아니라 플레이어 측에 있는 이유**는 ADR-001 D4가 정한
분리 그대로다 — `Contract`는 **진실**이고, 플레이어가 매긴 등급은 **진실이 아니라
판단**이다. 진실 옆에 두면 세이브에 정답이 섞이는 길로 돌아간다.

> **판정에 직접 들어가지 않는데 왜 저장하는가** — 결과는 `D = P + C − T`가 내고
> 등급은 지원·배정에만 영향을 준다. 그래도 저장한다:
> **판정에 영향이 없어도 하류가 읽는 값이면 저장한다.**
> P2 결과 대조가 「주장 / **내 판정** / 실제」 3항을 나란히 놓는데, 가운데 항이 없으면
> 대조가 2항이 되고 **플레이어가 무엇을 틀렸는지 말해줄 수 없다.**
> (이 논증은 ADR-002 D9가 폐기된 「단정」에 대해 쓴 것을 그대로 이식한 것이다.)

### D6. 실제 위험 `T`를 세이브에 평문으로 두지 않는다

**템플릿 id + 시드로 재구성한다.** ADR-002 D9의 해당 절이 이 결정의 소유자이며,
여기서는 타입 측 결과만 적는다:

- `SaveFileV1`의 DTO에 **`T`에 해당하는 숫자 필드를 만들지 않는다**
- 대신 `questKind`(템플릿 키)와 `rngState`가 이미 저장되고, `fromSave(file, config)`가
  주입받은 `config`에서 다시 뽑는다 (ADR-002 D4의 설정 주입 경로 그대로 — **새 경로를
  만들지 않는다**)
- 도메인 타입에서는 `T`가 계속 존재한다. **DTO 경계에서만 사라진다**

**근거**: `localStorage`를 열어보는 것만으로 정답이 보이면 *"실제 위험은 숨김"* 이
텍스트 에디터 하나로 무너지고, 청취라는 시스템 전체가 무의미해진다.
**완벽한 방어가 아니라는 것도 함께 적는다** — 템플릿은 공개 번들이므로 작정하면
알아낼 수 있다. ADR-002 D6의 원칙 그대로다: **막을 수 있는 척하지 않고, 우연히
보이는 일만 없앤다.**

### D7. 의뢰서는 **편집 가능한 문서가 아니라 파생 뷰 + 필드 하나**다

```ts
/**
 * 의뢰서. **7칸은 전부 파생이고 저장되지 않는다.**
 * 플레이어가 넣는 값은 `playerGrade` 하나뿐이다.
 */
export interface CommissionSheet {
  readonly contractId: string;
  /** 7칸의 표시. `slotProgress`에서 매번 계산한다 (D3) */
  readonly marks: ReadonlyMap<SlotName, SheetMark>;
  /** **플레이어가 넣는 유일한 값** (D5). 도장 전에는 미정일 수 있다 */
  readonly playerGrade?: RiskGrade;
}
```

**자유 서술 필드가 없다.** 개인 수첩은 별개 개념이며 **게임 판정에 쓰지 않으므로
도메인 타입에 들어오지 않는다** — 순수 프레젠테이션 상태다.

**`marks`를 저장하지 않는 이유**는 D3이 전부다. 그리고 **대비 `C`도 저장하지 않는다** —
`C`는 자동 기록된 사실의 충실도이므로 `slotProgress` + `weight`에서 **규칙이 계산하는
순수 함수의 출력**이고, 저장하면 가중치 튜닝이 과거 세이브에 안 먹는다 (ADR-002 D4의
같은 논증).

## Alternatives Considered

| 안 | 왜 기각했나 |
| ---- | ---- |
| **칸 상태를 표시 3종으로 통일** (화면이 3종이니 타입도 3종) | **D3 전체가 이것의 기각 기록이다.** `미상`/`막힘(무지)`/`막힘(은폐)`가 한 값으로 합쳐지고 **기둥 6·7이 딛고 선 구별이 복구 불가능하게 사라진다.** 가장 유혹적이고 가장 비싼 안이다 |
| **`SheetMark`를 `SlotState`와 같은 리터럴로** (`'certain'`/`'vague'`/`'unknown'`) | 표시 타입과 저장 타입이 **컴파일러에게 구별되지 않는다.** 잘못된 자리에 대입해도 통과하고, 위 안으로 미끄러지는 경사면이 된다. 리터럴을 일부러 겹치지 않게 고른 것이 방어의 전부다 |
| **`weakness`를 `SLOT_NAMES` 중간에 (의미상 `target` 옆에) 삽입** | ADR-001 D6이 배열 순서를 저장 포맷의 일부로 못박았다. 중간 삽입은 뒤 칸의 RNG를 전부 민다. 지금은 비용이 0이지만 **규칙으로 세워 둬야 다음 번에 안 는다** |
| **`Limiter`의 `'question'`을 도달 불능인 채로 남겨 둠** | 도달 불능 값은 처리 코드·문안·가짜 통과 테스트를 낳는다. D2 참조. 그리고 **타입이 세계에 대해 거짓말을 하게 된다** |
| **`playerGrade`를 `Contract.statedGrade`와 같은 필드로** (플레이어가 덮어쓴다) | P2의 3항 대조가 2항이 된다. 그리고 `Contract`(진실)에 플레이어 판단이 섞여 ADR-001 D4의 분리가 무너진다 |
| **`T`를 세이브에 값으로 저장** | 세이브를 열면 정답이 보인다. D6 |
| **대비 `C`를 세이브에 저장** (계산 비용 절약) | 계산은 싸고, 저장하면 가중치 튜닝이 과거 세이브에 안 먹는다 (ADR-002 D4). **저장하는 것은 판정의 입력이지 파생값이 아니다** |
| **의뢰서 자유 서술을 남기고 LLM이 대비를 추출** | **사용자가 명시적으로 삭제했다.** 그리고 그것이 살아 있으면 ADR-003의 *"게임 상태에 닿는 LLM 출력이 0개"* 가 다시 거짓이 된다 — 추출된 대비는 `C`를 통해 `D = P + C − T`에 직접 들어간다 |

## Consequences

### 좋아지는 것

- **ADR-001·002·003에 흩어져 서로를 가리키던 ⚠ 상자들이 한 곳에서 닫힌다** — 재현 키
  (세 문서), `'question'`(두 문서), 칸 어휘(두 문서)
- **LLM이 판정 경로에서 완전히 빠진 상태가 타입으로 증명된다** — 청취 타입 어디에도
  LLM 출력이 들어오는 필드가 없다
- 표시와 저장이 갈리면서 **의뢰서 화면이 저장 스키마를 인질로 잡지 않는다** — 화면이
  4종·5종 표시로 바뀌어도 저장은 안 움직인다
- `weakness`가 맨 뒤라 **`weakness`를 열지 않는 의뢰 종류에서는 시드가 안 갈린다**

### 대가와 위험

1. **⚠ `weakness`를 여는 의뢰 종류에서는 시드가 갈린다.** 소비가 하나 늘기 때문이다.
   **지금은 비용이 0이다** (세이브 0개). 시드를 하드코딩한 테스트가 생긴 뒤라면
   *"테스트를 고쳤다"* 가 아니라 **"스키마가 바뀌었다"** 로 기록할 것 (ADR-001의 같은
   경고)
2. **`text.json` 문안이 는다.** 칸 7 × `(reach, limiter)` 조합. `Limiter`가 2값이 되어
   조합은 줄지만 칸이 늘어 상쇄된다. **`weakness`는 문안 질감이 다른 칸과 다르다** —
   *"모른다"* 보다 *"그건 왜 묻소"* 계열이 자연스럽다
3. **`quest-templates.json`이 `weakness`의 `weight`를 따로 잡아야 한다.** 이 칸이 `C`를
   가장 크게 올리므로 **밸런스의 지렛대가 여기 몰린다** — ADR-001이 경고한 3:1 가중치
   상한을 다시 봐야 한다
4. **`sheetMark()`가 한 방향 함수라는 것을 사람이 지켜야 한다.** 컴파일러는 역함수를
   쓰는 것을 막지 못한다. **정적 검사로 방어한다** (Verification)
5. **`T` 재구성 경로가 `fromSave`에 붙는다.** ADR-002 D4의 설정 주입을 그대로 쓰므로
   새 경로는 아니지만, **복원이 `quest-templates.json`에 의존하게 된다** — 템플릿 키가
   사라진 세이브는 복원 불가다 (ADR-002 D7대로 새 회차로 시작한다)

### 되돌리는 법

- **D1**: `'weakness'`를 유니온과 배열 **맨 뒤에서** 지우면 나머지 여섯의 순서가 그대로
  살아난다 — 맨 뒤에 넣은 것이 롤백 계획이기도 하다
- **D2**: `'question'`을 되살리려면 **질문 깊이 등급이 함께 부활해야 한다.** 값만
  되돌리는 것은 의미가 없다
- **D3**: 되돌릴 수 없다 — 표시 3종으로 저장한 세이브는 정보가 이미 소실됐다.
  **이 방향의 비가역성이 D3을 이 ADR에서 가장 중요한 결정으로 만드는 이유다**

## Verification

> **번호가 아니라 성질로 적는다.** 이 저장소는 AC 번호 참조가 반복적으로 썩었다 —
> ADR-002 Verification 말미의 ⚠ 절이 그 이력이다. **번호는 GDD 개정마다 움직이고
> 성질은 안 움직인다.**

| 무엇 | 어떻게 |
| ---- | ---- |
| **저장이 5종을 구별한다** | 같은 칸을 세 경로(안 묻기 / 무지로 막힘 / 은폐로 막힘)로 만들고 **저장→복원 후 세 값이 서로 다른지**. 하나라도 같으면 실패 |
| **표시는 3종으로 뭉친다** | 위 세 값에 `sheetMark()`를 적용하면 **전부 `'unfilled'`** |
| **표시에서 저장으로 가는 경로가 없다** | 정적 검사 — `SheetMark`를 인자로 받아 `SlotState`/`SlotProgress`를 만드는 함수가 **존재하지 않는다**. 그리고 세이브 DTO에 `SheetMark`가 **등장하지 않는다** |
| **`Limiter`에 `'question'`이 없다** | 정적 검사 + 전 조합 탐색 — `(knows, tells)` 전 조합에서 나오는 `limiter`가 2값 안에 있는지 |
| **새 칸이 기존 시드를 밀지 않는다** | `weakness`를 열지 않는 템플릿으로 같은 시드를 돌려 **`weakness` 도입 전후 결과가 바이트 단위로 같은지** |
| **RNG가 데이터 배열 순서에 의존하지 않는다** | `quest-templates.json`의 `opensSlots` 배열을 뒤섞어도 결과가 같은지 (ADR-001 D6의 성질을 7칸에서 재확인) |
| **세 등급이 구별되어 왕복한다** | 주장 `A` / 판정 `C` / 실제 `T=5`(=B)로 서로 다르게 두고 저장→복원. **셋이 각각 원래 값인지.** 한 필드로 뭉갠 구현은 왕복 항등만으로는 안 잡힌다 |
| **`T`가 세이브 텍스트에 없고, 그럼에도 복원 후 같다** | 두 조건을 **한 테스트에서** 본다 — 직렬화 문자열에 값이 없고 `fromSave` 후 `T`가 원본과 같은지. 따로 보면 "그냥 지운" 구현이 통과한다 |
| **대비 `C`가 순수 함수다** | `C` 계산 모듈이 `Rng`도 `fetch`도 import하지 않는다 (정적 검사). 같은 `slotProgress`면 항상 같은 `C` |
| **판정에 LLM이 없다** | 게이트웨이 목을 **서로 다른 두 응답 집합**으로 바꿔 같은 `(칸, 행동, 재료?)` 시퀀스를 재생 → **칸 상태·`C`·`D` 전부 동일**. 달라지는 것은 대사 문자열뿐 |
| **의뢰서에 플레이어 입력 필드가 하나뿐이다** | 정적 검사 — `CommissionSheet`에 `readonly`가 아닌/플레이어가 쓰는 필드가 `playerGrade` 외에 없다 |
