# ADR-001 — 통제된 AI 의뢰인 에이전트

| 항목 | 내용 |
|---|---|
| 상태 | Accepted |
| 날짜 | 2026-08-10 |
| 결정자 | 프로젝트 팀 |
| 관련 GDD | `ai-client-agent.md`, `intake-dialogue.md` |

## Context

Help Wanted의 핵심은 플레이어가 한 문장 자유 입력으로 의뢰인을 심문하고 협상하는 것이다. AI가 대사만 만들면 자유 입력이 게임 상태에 영향을 주지 못하고, AI가 진실·경제·생환까지 소유하면 환각과 비결정성 때문에 공정성이 무너진다.

## Decision

AI는 **자연어 이해, 도구 선택, 대화 기억과 캐릭터 연기**를 담당하고, 규칙 엔진은 **진실, 공개 조건, 경제 상한, 상태 변경과 파견 결과**를 담당한다.

```text
한 문장 발화
  → AI 구조화 해석
  → 허용 ID와 자료 지식 검증
  → 규칙 엔진 판정
  → 서명된 도구 영수증
  → AI 캐릭터 대사
  → 검증 후 화면 반영
```

### D1. AI는 상태를 직접 쓰지 않는다

게임 상태 변경은 규칙 엔진이 발급한 `ToolReceipt`로만 적용한다. AI 대사에 “은화 100닢을 주겠다”가 있어도 협상 영수증이 없으면 보수는 변하지 않는다.

### D2. 미공개 사실 원문은 AI에 주지 않는다

AI에는 공개 사실, 인물 성향, 감정, 대화 이력과 허용 도구만 제공한다. 숨은 사실은 도구가 공개를 승인한 시점에만 결과로 전달한다.

### D3. 자료 근거는 물리 선택이 확정하고, AI 해석은 보조한다

> **개정 (2026-08-10).** 원문은 *"별도의 근거 선택 입력은 두지 않는다"* 였다.
> 그 설계에서는 AI가 인용을 놓치면 퍼즐 판정 자체가 사라져, **핵심 판정이 모델 품질에
> 인질로 잡힌다.** 진술 쪽지와 백과사전 문장을 직접 고르는 대조 도장을 도입해 뒤집었다.

플레이어가 진술 쪽지 하나와 `KnowledgeEntry` 하나를 직접 선택하고 대조 도장을 찍는다. `compareClaim`이 그 쌍의 유효성을 확정하고, 확정된 `slot`과 `knowledgeId`는 AI 해석 결과에 **강제로 병합**된다. AI가 같은 지식을 문장에서 뽑아내면 보강이 되고, 놓쳐도 판정은 그대로 선다.

AI의 `citedKnowledgeIds` 추출은 유지한다. 다만 그것은 대조를 거치지 않은 자유 발화에서만 단독으로 쓰이며, 어느 경로든 현재 보이는 자료에 존재하는 ID만 통과한다. AI가 존재하지 않는 규정을 인식하거나 동의해도 하드 판정에는 효력이 없다.

### D4. 어조는 연기 변수이지 단독 해답이 아니다

AI가 분류한 `supportive | neutral | hostile`은 표정, 경계와 인내에 제한적으로 사용한다. 사실 공개는 지식과 검증된 모순 조건이 결정한다.

### D5. AI는 본선 경로이고, 규칙 폴백으로 완주할 수 있다

> **개정 (2026-08-10).** 원문은 *"AI는 필수 코어다 — 연결되지 않으면 턴을 진행하지 않는다"*
> 였다. 그 규칙은 **심사자가 링크를 여는 순간 Worker가 죽어 있으면 게임이 첫 화면에서
> 끝난다**는 뜻이고, `technical-preferences.md`의 「폴백 없는 LLM 의존 금지」와도 충돌했다.

의뢰인의 대사 품질과 자연어 이해의 본선은 원격 AI다. 다만 `createResilientAgent`가 헬스체크 실패와 턴 실패를 잡아 규칙 기반 에이전트(`createDevelopmentAgent`)로 내려가고, 한 번 내려간 세션은 그 상태를 유지한다. 폴백 모드에서도 심문·대조·협상·의뢰서·파견의 전 경로를 완주할 수 있다.

**대체하지 않는 것**은 입력 방식이다. 폴백에서도 플레이어는 여전히 한 문장을 자유 타이핑하며, 태도·화법 선택 버튼은 어느 모드에서도 생기지 않는다. 폴백 중임은 화면에 명시한다 — 심사자가 AI 응답과 규칙 응답을 혼동해서는 안 된다.

### D6. Worker가 보안 경계다

- API 키와 시스템 프롬프트는 Worker에만 둔다.
- IP 레이트 리밋, 세션 호출 상한과 허용 모델 목록을 적용한다.
- 브라우저는 공급자 API를 직접 호출하지 않는다.

### D7. 턴은 멱등이다

모든 턴은 `sessionId + turnId`를 가진다. 같은 요청을 재전송해도 상태를 두 번 변경하지 않고 기존 영수증을 반환한다.

## Consequences

### 장점

- 자유 발화가 실제 게임 상태와 연결된다.
- AI 환각이 의뢰인의 실패나 보상 오류를 만들지 않는다.
- 플레이어가 오직 한 문장만 입력해도 질문·근거·협상을 표현할 수 있다.
- 도구 영수증으로 테스트와 시연 설명이 가능하다.

### 비용

- 한 턴에 해석·검증·판정·대사 생성 단계를 조율해야 한다.
- 사건 콘텐츠의 사실 ID와 자료 지식 ID 정합성을 관리해야 한다.
- 폴백 경로의 규칙 기반 해석기를 사건 데이터와 함께 유지보수해야 한다 — 새 사건의 키워드가 빠지면 폴백만 조용히 나빠진다.

## Verification

- 미공개 사실이 프롬프트·응답·DOM에 포함되지 않는다.
- AI 문장만으로 게임 상태가 변하지 않는다.
- 같은 `turnId` 재전송이 상태를 두 번 바꾸지 않는다.
- 문장 속 유효한 자료 인용은 AI 표현이 달라도 같은 공개 판정을 얻는다.
- 존재하지 않는 자료 주장은 어떤 하드 판정도 열지 못한다.
- AI 연결 실패 시 입력 문장과 이전 상태가 보존되고, 규칙 폴백으로 3사건을 완주할 수 있다.
- 폴백으로 내려간 세션은 화면에 폴백 모드임을 표시한다.
