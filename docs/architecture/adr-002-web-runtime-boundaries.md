# ADR-002 — 웹 런타임과 계층 경계

| 항목 | 내용 |
|---|---|
| 상태 | Accepted |
| 날짜 | 2026-08-10 |
| 관련 기준 | `AGENTS.md`, `vite.config.ts` |

## Context

프로젝트는 이미 TypeScript, Vite, DOM/CSS와 순수 도메인 함수로 구성되어 있다. 새 콘셉트는 자유 입력의 포커스·캐럿 유지, 네트워크 에이전트 호출, 서류 상태의 즉시 반영을 요구하지만 게임 엔진이나 UI 프레임워크를 추가할 이유는 없다.

## Decision

### D1. 기술 기준 유지

- TypeScript 5.5.4 strict
- Vite 7.3.6
- DOM + CSS
- Vitest + happy-dom
- `vite.config.ts`의 `base: "./"`
- 런타임 npm 의존성 0개

### D2. 계층

```text
src/domain/        사건·심문·의뢰서·파견 순수 규칙
src/data/          사건·자료집·파티·밸런스 데이터
src/llm/           Worker 게이트웨이와 스키마 검증
src/presentation/  DOM 화면·스타일·입력 상태
workers/           프롬프트·도구 오케스트레이션·공급자 호출
```

`src/domain/**`은 `fetch`, DOM, 모델 이름을 import하지 않는다.

### D3. 자유 입력 부분 갱신

대화 턴 중 전체 화면을 다시 그리지 않는다. 입력창 값, 포커스, 선택 범위와 IME 조합 상태를 보존한 채 대화 기록·표정·의뢰서 후보만 부분 갱신한다.

### D4. 숨은 진실과 공개 상태 분리

클라이언트 도메인은 사건 진실을 판정에 사용할 수 있지만 프레젠테이션 모델에는 공개 사실만 전달한다. DOM 속성, 주석, 데이터셋에 미공개 값을 넣지 않는다.

### D5. 성능 예산

- 초기 전송 gzip 1MB 이하
- JS 200KB 이하, CSS 200KB 이하, 이미지 500KB 이하
- 규칙 조작 100ms 이내
- AI 전송 후 2초 이내 대기 연출
- AI 응답 8초 목표
- 브라우저 탭 200MB 이하

## Consequences

- 기존 코드와 에셋의 재사용이 가능하다.
- 자유 입력 화면은 기존 전체 재렌더 방식에서 부분 갱신으로 개정해야 한다.
- 미공개 상태 누출을 정적·통합 테스트로 별도 검증해야 한다.
- Worker와 클라이언트가 같은 스키마 검증을 중복 수행한다.

## Verification

- `npm run check` 통과.
- 대화 응답 중 입력창 포커스·캐럿·조합 중인 한글이 보존된다.
- `src/domain/**`에 `fetch`와 DOM import가 없다.
- 빌드 결과가 크기 예산을 통과한다.
- 실제 Pages 하위 경로에서 모든 에셋이 로드된다.
