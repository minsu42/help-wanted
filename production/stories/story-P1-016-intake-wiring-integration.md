## Context

이 저장소는 자동 테스트가 모두 통과한 상태에서 **화면 사이의 선을 두 번 잃었다.**

1. 가장 흔한 파견 경로가 결과 대조 화면을 통째로 건너뛰었다
2. SVG를 직접 누르면 `HTMLElement` 가드 때문에 클릭이 무시됐다

둘 다 개별 모듈 테스트로는 잡히지 않았다. 따라서 이 스토리는 커버리지 보강이 아니라
**P1 완료 기준 그 자체**다. 청취·수첩·의뢰서·하루 진행·저장·LLM 폴백이 실제 브라우저에서
한 선으로 이어지는지 확인하고, 증거가 없으면 P1은 완료가 아니다.

## Acceptance Criteria

### A. 주 동선 완주 — BLOCKING

- [ ] 실제 브라우저에서 **의뢰인 3명 고정 순서 → 칸 질문 → 막힘 확인 → 일깨우기 또는
      들이대기 → 자동 기록 갱신 → 등급 선택 → 도장 → 하루 마감 → 저장 → 재적재**가
      실제 클릭으로 완주된다
- [ ] 같은 동선을 키보드만으로 완주한다. 포커스가 화면 교체 뒤 사라지거나 뒤 화면으로
      새지 않는다
- [ ] 아무것도 묻지 않고 등급도 고르지 않은 의뢰서를 포함해도 하루가 끝난다
- [ ] 인내 0으로 퇴장한 의뢰인의 의뢰서도 도장되고 다음 의뢰인으로 이어진다
- [ ] 세 번째 도장 뒤 `advanceDay`와 저장이 각각 1회이며, 재적재 후 다음 날 첫
      의뢰인 화면에서 시작한다

### B. 계층 사이 불변식 — BLOCKING

- [ ] 칸 클릭 한 번이 `respond()` 한 번과 자동 기록 한 번만 만든다. 이전 화면의
      리스너가 남아 중복 처리하지 않는다
- [ ] 5종 저장 상태가 화면의 3표기로 접혀도 저장·재적재 뒤 원래 5종 구별이 보존된다
- [ ] 청취 산출 외의 경로로 자동 기록 7항목을 바꿀 수 없다
- [ ] `미상`과 `막힘`이 흑백 화면에서도 구별되고, 실제 저장에서는 서로 다른 값이다
- [ ] 기색 표정이 얼버무림 대사보다 먼저 나타나며, 표정만으로 무지/은폐를 구별할 수 없다

### C. LLM 차단 및 누출 방지 — BLOCKING

- [ ] 프록시를 완전히 차단한 상태에서도 A절 동선이 동일하게 완주된다
- [ ] 서로 다른 두 LLM 응답 집합으로 같은 입력 시퀀스를 재생했을 때 칸 상태·인내·
      의뢰서·다음 날 상태·세이브 바이트가 동일하다
- [ ] 네트워크 요청에 미공개 `fact`와 실제 위험 `T`가 없다. `topic`과 허용된 선택지
      식별자만 전달된다
- [ ] 모델이 화이트리스트 밖 선택지 id, 빈 `say`, 스키마 밖 필드를 반환해도 규칙
      상태가 오염되지 않고 폴백으로 계속된다

### D. 파견 전 비밀과 입력 표면 — BLOCKING

- [ ] 실제 위험 `T`가 화면 텍스트·DOM 속성·데이터셋·주석·네트워크 페이로드·세이브
      JSON 어디에도 나타나지 않는다
- [ ] 복원 후에는 원본과 같은 `T`가 재구성된다. 비밀을 단순 삭제해서 통과하지 않는다
- [ ] 청취·의뢰서 주 동선에 `input[type=text]`·`textarea`·`contenteditable`이 0개다
- [ ] 추천 등급이 화면·DOM·툴팁·`aria-*`·코드 계산 함수 어디에도 없다
- [ ] 진행률 바·체크박스·완료 점수(`3/7`, `%`)가 없다

### E. 회귀와 성능

- [ ] `npm run check`가 통과하고 기존 3일판의 배포 가능한 경로가 깨지지 않는다
- [ ] 초기 전송 gzip 예산을 통과한다. LLM SDK는 브라우저 번들에 들어가지 않는다
- [ ] 규칙 조작은 100ms 안에 반영된다. LLM 응답 대기는 2초 안에 생각 연출을 시작하고
      8초에 폴백한다
- [ ] 1280×720과 좁은 화면에서 가로 스크롤 없이 도장까지 도달한다
- [ ] 브라우저 콘솔에 처리되지 않은 예외·거절·접근성 오류가 없다

## Verification Matrix

| 경계 | 자동 | 실제 브라우저 | 증거 |
| ---- | ---- | ---- | ---- |
| 칸 클릭 → 판정 → 자동 기록 | 통합 테스트 | 실제 SVG/텍스트 클릭 | 스크린샷 + 이벤트 로그 |
| 막힘 → 수첩 → 재료 → 재판정 | 통합 테스트 | 유효/무효 재료 각각 | 인내 전후 캡처 |
| 등급 → 도장 → 다음 의뢰인 | 통합 테스트 | 마우스 + 키보드 | 3계약 연속 영상/로그 |
| 하루 마감 → 저장 → 재적재 | DTO/어댑터 테스트 | 새로고침 | 저장 전후 해시 |
| LLM 정상/차단 | 두 응답 목 | DevTools 네트워크 차단 | 상태/세이브 비교 |
| `T` 미노출 | 정적 grep | DOM·Network·Storage 전수 검색 | 검색 결과 0건 |

## Implementation Notes

- 테스트 하나에 모든 주장을 몰아넣지 않는다. 경계별 통합 테스트와 하나의 브라우저
  완주 시나리오를 함께 둔다
- happy-dom의 `.click()`만으로 완료 처리하지 않는다. 실제 브라우저에서는 자식 SVG,
  글자 노드, 도장 프레임을 각각 눌러 `Element.closest('[data-action]')` 경로를 검증한다
- 상태 비교는 화면 문자열이 아니라 직렬화 가능한 규칙 상태와 세이브 바이트로 한다.
  LLM 문장은 의도적으로 달라도 된다
- 수동 증거에는 실행 커밋, 브라우저/뷰포트, 시드, 프록시 상태, 테스트한 입력 시퀀스를
  기록한다. 재현 정보가 없으면 증거로 인정하지 않는다
