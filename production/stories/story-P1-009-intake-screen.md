# Story P1-009: 청취 화면 — 창과 종이

> **Phase**: P1 | **Status**: Ready | **Layer**: Presentation | **Type**: UI
> **GDD**: `design/gdd/intake-system.md` (v6.2) U1 · U2 · U4 · U5 · V1 · V2 · V3 · V5 · R9
> **Art**: `design/art/art-bible.md` §5.1 · §5.2 · §5.7 · §5.9
> **ADR**: ADR-003 (LLM 경계) · ADR-001/004 (칸 타입)
> **Created**: 2026-08-10

## Context

**창구가 비어 있었다.** `src/presentation/ui/CounterScreen.ts`는 3일 마감판의
흥정 한 막만 만들었고, 그 앞에 와야 할 **청취**가 통째로 없다. story-007이
스스로 *"19개 스토리 중 개정 폭이 가장 큰 스토리"* 라고 적어 둔 자리가 여기다.

이 스토리가 세우는 것은 화면 하나가 아니라 **두 레지스터의 경계**다.

| 영역 | 무엇 | 레지스터 |
| ---- | ---- | ---- |
| 상단 **35~40%** | 창틀 + 의뢰인 상반신 + 대사띠 + **인내 표시기** | **창** |
| 카운터 상판 | 얇은 띠 — 경계선 | 경계 |
| 하단 **60~65%** | **의뢰서(중앙)** + 수첩(옆) | **종이** |

**둘은 섞이지 않는다.** 창은 **읽는 곳**이고 종이는 **누르는 곳**이다 (§5.9).
인물을 클릭할 수 없는 것이 규칙이며, 클릭 가능해지는 순간 창구가 길드 홀처럼
*"가서 말을 거는 화면"* 이 되고 질문이 다시 **메뉴**가 된다 — v1~v5가 다섯 번
실패한 그 지점이다.

그리고 이 화면의 중심 주장은 하나다: **칸을 누르는 것이 곧 질문이다.**
의뢰서는 결과 표시판이 아니라 **인터페이스**다. `[질문한다]` 버튼은 존재하지
않는다.

> **`--seal`(붉은 봉랍)이 이 화면에 등장하는 횟수는 0이다.** 인내가 바닥나도,
> 헛발을 디뎌도, `S` 등급을 찍어도 붉은색을 쓰지 않는다 — 인내 소진은 위험이
> 아니라 **압박**이다 (아트 바이블 §4 · §5.7).

## Acceptance Criteria

- [ ] 화면이 **창(상단 35~40%) / 카운터 상판 / 종이(하단 60~65%)** 셋으로 갈리고, 1280×720에서 실측 비율이 그 범위 안이다 (U1 · 아트 §5.9)
- [ ] 창을 가리고 봤을 때 화면이 여전히 **"서류를 쓰는 화면"** 으로 읽힌다 — 의뢰서가 단일 요소로서 최대 면적이다 (아트 §5.1 설계 테스트)
- [ ] **인물이 클릭 대상이 아니다** — 창 영역에 `data-action`이 0개이고, 인물·창틀에 hover 커서 변화가 없다 (아트 §5.9)
- [ ] **인내 표시기가 창 쪽에 있다.** 잉크 눈금 3개 뭉치이며, 헛발 시 눈금에 **줄이 그어져** 흔적이 남는다 (아트 §5.7)
- [ ] *(정적)* 인내 표시기 DOM에 `<progress>`·게이지·백분율·숫자 카운터가 없고, `--seal`이 쓰이지 않는다 (아트 §5.7)
- [ ] **칸을 누르는 것이 곧 질문이다** — 의뢰서 칸이 `data-action="ask"`를 갖고, 화면 어디에도 `[질문한다]` 버튼이 없다 — **AC-UI-01** (V1 · 아트 §5.1)
- [ ] 누를 수 있는 칸이 정적 산문과 구별된다 — **색이 아닌 수단으로** (V1 · 아트 §5.5 원리)
- [ ] 칸의 hover 신호가 **「질문할 수 있다」로만** 읽힌다 — 연필 아이콘·편집 밑줄·텍스트 캐럿 커서 금지 (아트 §5.2 파생 규칙)
- [ ] *(정적)* 칸 표시 DOM에 `<input type=checkbox>`·`<progress>`가 **0개**다 — **AC-UI-04** (V1)
- [ ] *(정적 + 실브라우저)* **완료 점수 표기가 없다** — `2.5/3`·`3/7`·`%` 형태의 진척 표기가 화면·DOM에 0개다 (U1 · V1)
- [ ] **최근 1~2교환만 크게** 보이고 이전 교환은 접힌다. 항상 펼쳐진 전체 로그가 존재하지 않는다 (U1)
- [ ] 과거 진술 열람 경로가 **수첩 「들은 것」 하나뿐**이다 — 대사띠에 스크롤 로그가 없다 (U1)
- [ ] 다섯 칸 상태가 **색 없이** 구별된다 (V2):
      `미상`=점선·잉크 없음 / `막힘(무지)`=실선+둥근 얼룩 / `막힘(은폐)`=실선+짧은 사선 / `어렴풋`=자간 넓게 / `확실`=자간 기본·한 단계 굵게
- [ ] **`미상` vs `막힘`이 문장을 읽지 않고 훑어도 갈린다** — 흑백(`grayscale(1)`) 스크린샷으로 판정한다 (V2, **수동-BLOCKING**)
- [ ] **기색 표정이 얼버무림 대사보다 먼저** 나타난다 — **AC-UI-07** (V3, **수동-BLOCKING**)
- [ ] 기색은 *"뭔가 있다"* 까지만 전한다 — 표정만으로 무지/은폐가 구별되지 않는다 (V3 · 아트 §5.9 규칙 3)
- [ ] 상황이 주는 행동이 대사띠 아래에 뜨고 **보통 1~2개**다. 줄 재료가 없으면 `[일깨운다]`가 **뜨지 않는다** — **AC-R9-01** (R9)
- [ ] `[일깨운다]`·`[들이댄다]` → 수첩이 열리고 재료 선택 → **내 대사가 화면에 나온다** — **AC-UI-02** (U2, **수동-BLOCKING**)
- [ ] **선택지가 시간으로 사라지지 않는다** — 타이머·카운트다운이 0개다 (U2)
- [ ] **실패가 실패처럼 그려지지 않는다** — 붉은 테두리·흔들림 애니메이션·오류 문구·실패음이 0개다. 기계적 신호는 인내 눈금 하나뿐이다 (U4)
- [ ] *(정적)* 화면 전체에 텍스트 입력 요소가 **0개**다 — `input[type=text]`·`textarea`·`contenteditable` — **AC-UI-06** (U2 · U5)
- [ ] *(정적)* `--seal`이 이 화면의 CSS·DOM에 **0회** 등장한다 (아트 §4 · §5.7)
- [ ] 게이트웨이 차단 상태로 **청취 → 보수 → 도장이 완주된다** — 달라지는 것은 대사 문자열뿐 — **AC-UI-03** (ADR-003 D5, **수동-BLOCKING**)
- [ ] 키보드 단독으로 칸 짚기·행동 선택·수첩 재료 선택이 완주된다. 점멸 없음 (U5)
- [ ] `aria-live="polite"`가 **의뢰인 응답 도착**과 **인내 변화**를 알린다 (U5)
- [ ] *(정적)* 반응 계층(V5)을 통째로 꺼도 청취 → 기록 → 도장이 완주된다 — **AC-V5-02**
- [ ] *(정적)* 폴백 문안·반응 문안 중 **빈칸이나 안 물은 칸을 언급하는 것이 0개**다 — **AC-V5-01** (V5 가드레일)
- [ ] 클릭 → 화면 반영 100ms 이내. **LLM 대화 경로는 예외** — 2초 내 「생각한다」 연출 시작, 8초 초과 시 폴백 (`technical-preferences.md`)

> **실브라우저 검증은 권장이 아니라 완료 기준이다.** 이 저장소는 전 스위트가
> 초록인 채로 두 번 버그를 냈다 — **382개 통과 중에 결과 대조 화면이 주 동선에서
> 통째로 건너뛰어졌고**, **407개 통과 중에 SVG 클릭이 무시됐다**
> (`target instanceof HTMLElement`가 `SVGRectElement`를 배제했다). 둘 다
> 브라우저를 열어야만 보였다. 위 **수동-BLOCKING** 항목은 자동 테스트로 대체할
> 수 없다.

## Implementation Notes

- 파일: `src/presentation/ui/IntakeScreen.ts` (신설) + `src/presentation/styles/intake.css`
- **story-007이 세운 화면 모듈 규약 4개를 그대로 따른다**:
  1. `mountIntakeScreen(root, deps) => ScreenHandle` — `destroy()`가 리스너와 DOM을 정리
  2. **리스너는 루트 하나에만** 걸고 `data-action`으로 위임
  3. 상태 변화는 전체 재렌더. **연속 입력 위젯이 없으므로 부분 갱신을 쓰지 않는다**
  4. 바깥 세계(판정, 화면 전환)는 **주입받는다**
- ⚠ **위임 핸들러에서 `target instanceof HTMLElement`를 쓰지 말 것.** 잉크 얼룩·
  사선·인내 눈금을 SVG로 그리면 그 순간 클릭이 조용히 죽는다 — **이 저장소가
  407개 통과 상태에서 실제로 낸 버그다.** `closest('[data-action]')`을
  `Element`에서 출발시킨다
- **칸의 다섯 상태는 CSS 클래스로만 가른다** (`.slot--unknown` / `--blocked-ignorance`
  / `--blocked-concealment` / `--vague` / `--certain`). 인라인 스타일로 색을 찍으면
  색맹 모드 검증이 무의미해진다
- **기색은 렌더 순서가 아니라 시간 순서다.** 같은 재렌더 안에서 표정 DOM을 먼저
  붙여도 사람 눈에는 동시다 — 표정 전환 후 **한 박자** 뒤에 대사띠를 채운다.
  이 한 박자가 V3의 전부다
- 인물 얼굴은 38×38 원본의 **정수배 확대만** (기본 5×). `image-rendering: pixelated`는
  **창 내부에만** 걸고 **글자에는 절대 걸지 않는다** (아트 §5.9)
- 창틀은 §7의 나무 9-slice(`ui-panel.png` 계열)를 **재사용한다** — 새 재질을 만들면
  창구와 길드 홀이 다른 건물로 읽힌다
- 접힌 과거 교환은 **DOM에서 지우지 않고 접는다.** 지우면 `aria-live` 뒤의 맥락이
  사라지고, 남겨 두면 「들은 것」과 이중 관리가 된다 — 접기만 한다
- 반응 계층(V5)은 **대기열**이다. 턴 사이에 끼어들지 않는다 (프로토 5 3회차)

## QA Test Cases

- **Manual: 칸이 곧 질문인가**
  - Setup: 새 의뢰인 착석, 선제 진술 직후
  - Verify: `미상` 칸을 클릭하면 즉시 그 칸을 묻고 대사가 돌아온다. 화면 어디에도 `[질문한다]` 버튼이 없다
  - Pass: 질문이 의뢰서 **밖의 메뉴**로 존재하지 않는다
- **Manual: 색맹 검증 — `미상` vs `막힘`**
  - Setup: 한 의뢰서에 다섯 상태가 모두 나온 시점에서 스크린샷
  - Verify: `filter: grayscale(1)`를 걸고 다시 본다
  - Pass: **문장을 읽지 않고** 빈칸(점선)과 잉크 묻은 칸(얼룩/사선)이 갈린다. 얼룩과 사선도 서로 갈린다
- **Manual: 기색이 대사보다 먼저인가**
  - Setup: 은폐형 의뢰인(관리/귀족)의 `막힘(은폐)` 칸을 처음 묻는다
  - Verify: 표정 변화 → **한 박자** → 얼버무림 대사
  - Pass: 순서가 뒤집히거나 동시에 오지 않는다. 표정만으로는 무지인지 은폐인지 알 수 없다
- **Manual: 실패가 실패처럼 보이지 않는가**
  - Setup: 틀린 재료로 들이댄다 (헛발)
  - Verify: 붉은 테두리·흔들림·오류 문구·실패음이 없다. 인내 눈금 하나에 줄이 그어진다
  - Pass: 화면이 *"틀렸습니다"* 라고 말하지 않고 **사람이 식는다**
- **Manual: 창은 읽는 곳인가**
  - Verify: 인물·창틀·대사띠 배경을 클릭·더블클릭한다
  - Pass: 아무 일도 일어나지 않는다. hover 커서도 변하지 않는다
- **Manual: 게이트웨이 차단 완주**
  - Setup: DevTools 네트워크 차단 또는 목 게이트웨이를 오류로 고정
  - Verify: 칸 짚기 → 응답 → 행동 → 보수 → 도장까지 클릭으로 완주
  - Pass: 판정·인내 회계가 동일하고 대사 문자열만 폴백이다
- **Manual: 키보드 단독**
  - Verify: 마우스를 쓰지 않고 칸 짚기 → 행동 선택 → 수첩 재료 선택까지 도달
