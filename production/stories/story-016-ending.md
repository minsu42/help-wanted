# Story 016: 엔딩 + 최종 결산

> **Day**: 3 (오전) | **Status**: Ready | **Layer**: Polish | **Type**: UI
> **Estimate**: 1h
> **Spec**: 인라인 정의. 상위 근거는 `design/gdd/game-concept.md` Session-Level 루프

## Context

15일차의 자연스러운 정지점이다. 심사위원이 **끝까지 갔다는 감각**을 받아야 하며,
끝이 없으면 20~40분 세션이 그냥 멈춘 것처럼 느껴진다.

## Acceptance Criteria

- [ ] 15일이 끝나면 결산 화면으로 전이한다
- [ ] 최종 명성, 최종 자금, 길드 등급, 길드원 수를 표시한다
- [ ] **죽은 사람들의 이름을 전부 나열한다** — 몇 명이 아니라 누구였는지
- [ ] 각 사망자에 대해 `Memory`에서 뽑은 한 문장을 붙인다 (Story 006 템플릿)
- [ ] 명성 구간에 따라 길드의 운명 텍스트가 달라진다 (최소 3종)
- [ ] 다시 시작 버튼이 있고, 누르면 **새 시드로** 완전히 새 회차가 시작된다
- [ ] 시드를 표시한다 — 같은 시드로 재현할 수 있어야 한다

## Implementation Notes

- 파일: `src/presentation/ui/EndingScreen.ts`
- **사망자 명단이 이 화면의 핵심이다.** 숫자로 "사망 2명"이라고 쓰면 아무 감정도 남지
  않는다. 이름과 그가 마지막으로 무엇을 겪었는지가 있어야 컨셉의 목표 문장
  (*"이 숲이 위험하다는 걸 알고도 보상이 좋아서 신입을 보냈다. 안 돌아왔다."*)이
  회수된다
- 운명 텍스트는 손으로 3개를 쓰되 각각 2~3문장을 넘기지 않는다. 산문 금지 규칙의
  예외로 취급하는 유일한 지점이며, 그래서 짧아야 한다
- Story 015가 잘렸다면 자금을 최종 점수에 반영해 흥정의 의미를 남긴다
- 시드 표시는 심사·디버깅 양쪽에 쓰인다. 동영상 촬영 시 좋은 회차를 재현할 수 있다

## QA Test Cases

- **Manual: 15일 종료 전이**
  - Setup: 15일까지 진행
  - Verify: 결산 화면이 뜬다
  - Pass: 16일차가 존재하지 않는다
- **Manual: 사망자 명단**
  - Setup: 2명 이상 사망한 회차
  - Verify: 모든 사망자의 이름과 문장이 나온다
  - Pass: 숫자 요약이 아니라 개별 항목으로 나열된다
  - Edge: 사망자 0명이면 그에 맞는 문구가 나온다 (빈 목록이 아니라)
- **Manual: 운명 분기**
  - Setup: 낮은 명성 / 중간 / 높은 명성 회차
  - Verify: 서로 다른 운명 텍스트
  - Pass: 3종이 실제로 구분된다
- **Manual: 시드 재현**
  - Setup: 표시된 시드를 기록하고 같은 시드로 재시작
  - Verify: 1일차 의뢰와 명부가 동일
  - Pass: 완전히 같은 회차가 재현된다
