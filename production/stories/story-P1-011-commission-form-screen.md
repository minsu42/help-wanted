# Story P1-011: 의뢰서 화면 — 일곱은 자동, 하나는 내 것

> **Phase**: P1 | **Status**: Ready | **Layer**: Presentation | **Type**: UI
> **GDD**: `design/gdd/commission-form.md` R1~R8 · F1 · F2 · F3 /
> `design/gdd/intake-system.md` (v6.2) R1 · V1 · V2 · U2
> **Art**: `design/art/art-bible.md` §5.1 · §5.2 · §5.7
> **ADR**: ADR-001/004 (칸 타입 · `RiskGrade` · `CommissionSheet`) · ADR-003 (LLM 경계)
> **Created**: 2026-08-10

## Context

**이 화면이 기둥 6(*내가 쓴 것이 사람을 죽인다*)의 실체다.**

비율이 곧 설계다 — **자동 기록 7 : 플레이어 입력 1.**

| | **자동 기록 칸** | **판단 칸** |
| ---- | ---- | ---- |
| 무엇 | 종류 · 대상 · 규모 · 장소 · 기한 · 경로 · 특징 및 약점 (**7**) | **위험도 등급 `D/C/B/A/S`** (**1**) |
| 누가 | **청취 판정이 실시간으로** | **플레이어가 직접** |
| 고칠 수 있나 | **아니오** | 예 (도장 전까지 무제한) |
| 잉크 | `--ink-faint` (흐린 잉크) | `--ink` (본문 잉크) |

**화면의 거의 전부가 흐린 잉크이고 짙은 잉크는 딱 한 곳이다** (아트 §5.2).
기둥 6이 시각적으로 이보다 선명해질 수 없다.

**왜 7항목을 못 고치게 하는가**: 고칠 수 있으면 *"트롤 3마리"* 를 *"고블린 1마리"*
로 바꿔 적을 수 있고, 그 순간 이 게임은 **잘못된 정보를 임의로 만들어 쓰는
게임**이 된다. 거짓말은 **판단 칸에서만** 가능해야 한다 — 위험도를 낮춰 적는 것은
거짓이 아니라 **판단**이며, 그 구별이 기둥 6이 억울함이 되지 않게 막는다.

**그리고 이 화면은 청취와 같은 화면의 하단이다.** 청취가 끝난 뒤 여는 별도
화면이 **아니다** (R4). 칸이 열리는 즉시 여기가 갱신되고, 그 칸을 누르는 것이
곧 다음 질문이다 (청취 V1).

> **AC-CF-21은 죽었다** *(2026-08-10)*. 원문은 *"붉은 잉크(단정)와 검은 잉크(사실)가
> 색 + 표기 이중으로 구별된다"* 였다. **청취 R13(단정)이 폐기되면서 잉크 이원 표기
> 자체가 사라졌으므로 검증할 대상이 없다.** 그 자리를 「자동 기록 수정 불가」 검증이
> 대신하며, 그것이 원래 요구에 더 정확하다. **이 스토리는 붉은 잉크를 구현하지
> 않는다** — `--seal`은 이 화면에서 0회다 (등급 도장에도 쓰지 않는다, 아트 §5.7).

## Acceptance Criteria

### A. 자동 기록 7항목

- [ ] 서식이 **의뢰 종류와 무관하게 항상 7항목**을 인쇄한다. 다루지 않는 항목도 `미확인`으로 남고 **사라지지 않는다** — **AC-CF-03** (R2)
- [ ] *(정적 + 실브라우저)* 자동 기록 영역의 `input`·`textarea`·`contenteditable`이 **0개**이고, 클릭·더블클릭·키 입력으로 값이 바뀌지 않는다 — **AC-CF-01** (R1)
- [ ] *(정적 + 실브라우저)* **의뢰서 화면 전체의 텍스트 입력 요소가 0개**다. 등급 선택은 **버튼/라디오**이고 자유 서술 칸이 존재하지 않는다 — **AC-CF-02** (R1 · 청취 U2)
- [ ] *(정적)* **칸 값의 유일한 기록자가 청취 판정이다** — 플레이어 입력이 7항목 값에 도달하는 코드 경로가 **0개**다 — **AC-CF-21 / AC-R13-04** (R1)
- [ ] 청취에서 칸이 열리는 **즉시** 표기가 갱신된다 — 별도 확정 조작이 없다 — **AC-CF-04** (R4)
- [ ] 갱신이 **같은 화면 하단**에서 일어난다 — 의뢰서를 여는 별도 화면 전환이 존재하지 않는다 (R4)
- [ ] 5상태가 **확정 / 모호 / 미확인** 3표기로 접힌다: `확실`→확정 · `어렴풋`→모호 · `미상`·`막힘(무지)`·`막힘(은폐)`→**전부 미확인** (R3)
- [ ] **접히는 것은 표기뿐이다** — 세이브에서 5종이 구별 보존된다 (직렬화 왕복 검사) — **AC-CF-05** / **AC-DET-04** (R3)
- [ ] 자동 기록이 `--ink-faint`, 등급이 `--ink`로 그려진다 — 화면에 짙은 잉크가 **한 곳뿐**이다 (아트 §5.2)
- [ ] **자동 기록 칸이 고칠 수 있는 것처럼 보이지 않는다** — 커서 변화·hover 밑줄·연필 아이콘이 0개. 단 **hover 신호는 「질문할 수 있다」로 읽힌다** (아트 §5.2 · 청취 V1)
- [ ] *(정적 + 실브라우저)* 지적 문구가 0개다 — *"규모를 안 물으셨습니다"*·*"진술과 기록이 어긋납니다"* 류가 화면·DOM·툴팁에 없다 (R2 · Edge Cases)
- [ ] *(정적)* 진행률 바·체크박스·완료 점수(`3/7` 류)가 **0개**다 — **AC-UI-04** (청취 V1 · 아트 §5.1)

### B. 등급 — 유일한 플레이어 입력

- [ ] 위험도 등급을 **`D/C/B/A/S` 버튼 또는 라디오**로 고른다. 타이핑이 아니다 — **AC-UI-06** (R5)
- [ ] 도장 전까지 **횟수 제한 없이** 다시 고를 수 있고 비용이 없다 — **AC-CF-09** (R5)
- [ ] 도장 이후 등급과 자동 기록이 **불변**이 된다 — 재선택 UI가 사라지거나 비활성된다 — **AC-CF-10** (R5 · Edge「도장 이후」)
- [ ] *(정적 + 실브라우저)* **추천 등급이 어디에도 없다** — 화면·DOM·툴팁·`aria` 속성 어디에도 시스템이 제안한 등급 값이 없고, **코드에 추천 계산 함수가 존재하지 않는다** — **AC-CF-06** (R6 · F1)
- [ ] 등급 칸이 비어 있을 때 **어떤 글자도 미리 들어 있지 않다** — 점선 빈칸이며 흐린 추천값이 깔려 있지 않다 (아트 §5.2 「추천값 미리 채우기」 폐기)
- [ ] **의뢰인의 주장 등급이 청취 시작 전부터 항상 표시**되고, 플레이어의 판정과 **다른 칸에 나란히** 보인다 — **AC-CF-07** (R6)
- [ ] *(BLOCKING)* **실제 위험 `T`가 파견 전에 노출되지 않는다** — 화면, DOM(속성·데이터셋·주석 포함), 세이브 파일, 네트워크 페이로드 어디에도 없다 — **AC-CF-08** (R6)
- [ ] *(정적)* 등급 도장에 `--seal`을 쓰지 않는다 — `S`를 찍어도 세피아다 (아트 §5.7 · §4)

### C. 도장 — 언제나 찍힌다

- [ ] **전 항목 `미확인`이어도 도장이 찍힌다.** 경고·차단·확인 대화상자가 없다 — **AC-CF-11** (R7)
- [ ] **등급을 안 골라도 도장이 찍힌다.** 게시물의 등급 칸이 비고, 지원 판정에서 `S`로 간주된다 — **AC-CF-12** (R7)
- [ ] **의뢰인이 인내 소진으로 퇴장한 뒤에도** 등급 기입과 도장이 가능하다 — **AC-CF-13 / AC-EDGE-02** (청취 R7)
- [ ] *(정적)* 도장 경로에 `confirm()`·모달·2단계 확인이 0개다. 대신 **손을 얹는 한 박자** 연출이 있다 (R7 · 청취 V5)
- [ ] 등급 미기재 상태가 *"위험 없음"* 이 아니라 **비어 있는 것**으로 인쇄된다 — 화면이 `D`나 `-`로 대체하지 않는다 (R7)

### D. 배선 (**수동-BLOCKING**)

- [ ] 실브라우저: **청취 → 자동 기록 갱신 → 등급 선택 → 도장 → 게시**가 실제 클릭으로 완주된다 — **AC-CF-19**
- [ ] 실브라우저: **LLM 게이트웨이 차단 상태**에서 위 동선이 **동일하게** 완주된다 — 대사 문자열만 폴백으로 바뀐다 — **AC-CF-20**
- [ ] 실브라우저: 어떤 조작 시퀀스로도 7항목 값이 청취 산출 이외의 것으로 바뀌지 않는다 — **AC-CF-21**
- [ ] 키보드 단독으로 등급 선택 → 도장이 완주된다 (청취 U5)
- [ ] 클릭 → 화면 반영 100ms 이내

> **실브라우저 검증은 권장이 아니라 완료 기준이다.** 이 저장소는 **382개 통과 중에
> 결과 대조 화면이 주 동선에서 통째로 건너뛰어졌고**, **407개 통과 중에 SVG 클릭이
> 무시됐다** (`target instanceof HTMLElement`가 `SVGRectElement`를 배제했다).
> 커버리지 %를 올렸어도 둘 다 못 잡는다 — **실패는 커버리지 부족이 아니라 계층
> 사이의 구멍에서 나왔다.** D절 전체와 **AC-CF-08**은 자동 테스트로 대체할 수 없다.

## Implementation Notes

- 파일: `src/presentation/ui/CommissionFormView.ts` (신설) — P1-009의
  `IntakeScreen` **하단에 마운트되는 부분 모듈**이다. 독립 화면이 아니다
- 화면 모듈 규약 준수: 리스너는 `IntakeScreen` 루트 하나에 위임.
  칸은 `data-action="ask"`(질문), 등급은 `data-action="grade"` + `data-grade`,
  도장은 `data-action="seal"`
- ⚠ **`target instanceof HTMLElement` 금지.** 도장·얼룩·사선을 SVG로 그리면 클릭이
  조용히 죽는다. `closest('[data-action]')`을 `Element`에서 출발
- **`T`는 렌더 함수의 인자에 넣지 않는다.** 이것이 AC-CF-08을 지키는 유일하게 싼
  방법이다 — 넘겨 놓고 "안 그린다"고 약속하면 다음 사람이 디버그용 `data-*`에
  실어 보낸다. 화면이 받는 것은 `{ slots, statedGrade, playerGrade, sealed }`이고
  **진실 측 값은 타입 수준에서 도달 불가**여야 한다
- **`sheetMark()`(5→3 접기)는 도메인이 소유한다** (P1-001). 화면이 직접 접으면
  같은 규칙이 두 곳에 생기고 저장 구별이 조용히 무너진다
- **추천 계산 함수를 "만들었다가 안 쓰는" 것도 위반이다** (AC-CF-06은 *"코드에 추천
  계산 함수가 존재하지 않는다"* 를 요구한다). 죽은 코드로 남기지 말고 넣지 마라
- 등급 선택은 **라디오 그룹**이 접근성에 가장 싸다 (`role="radiogroup"`,
  화살표 키 이동). 다만 시각은 라디오 원형이 아니라 **눌러 찍은 잉크**여야 한다
- 도장은 **손을 얹는 한 박자 → 찍힘** 두 단계다. 이 한 박자가 확인 대화상자를
  대신하므로 **없애면 R7이 무너진다**
- 등급 기준표(F1)는 이 화면이 아니라 **길드마스터북 첫 장**에 있다 — 화면에
  기준표를 붙이면 그것이 사실상 추천이 된다
