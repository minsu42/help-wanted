# Story P1-005: 인내와 두 개의 열쇠 — 일깨우기 · 들이대기

> **Phase**: P1 | **Status**: Ready | **Layer**: Domain | **Type**: Logic
> **GDD**: `design/gdd/intake-system.md` (v6.2) R5 · R6 · R7 · Edge Cases 「인내」·「막힘」
> **ADR**: ADR-001 (슬롯 타입) / ADR-004 (Accepted — 칸 어휘 7개)
> **Created**: 2026-08-10

## Context

**이 스토리가 기둥 1(*아는 자가 이긴다*)의 코드상 실체다.** 청취에서 벽이 확인된
칸을 뚫는 유일한 두 경로이며, 둘 다 **내가 이미 가진 것**을 소모한다.

두 열쇠는 **같은 자원을 정반대 방향으로 쓴다.**

| | **일깨우기** (R5) | **들이대기** (R6) |
| ---- | ---- | ---- |
| 언제 | `막힘(무지)` 칸에만 | `막힘(은폐)` 칸에만 |
| 무엇을 하나 | 내가 아는 걸 **준다** | 내가 아는 걸 **무기로 쓴다** |
| 맞아야 하는 것 | **내용** — `hintTags` 교집합 | **범주** — `leverageTag == keyLeverage` |
| 재료 출처 | **밖에서 온 것뿐** (P1: 길드마스터북) | **어디서든** — 이 대화에서 들은 것도 |
| 올리는 것 | `knows[칸]` | `tells[칸]` |

**비용 구조가 이 시스템의 전부다: 성공은 무료이고, 헛발만 인내 −1이다.**
묻기·캐묻기·넘어가기·위험도 등급 기입은 하나도 인내를 쓰지 않는다. 그러므로
플레이어를 조이는 것은 **행동의 양이 아니라 오답의 수**다. v6에서 「하루 응대권 9」
가 하던 총량 방어선은 v6.1에서 소멸했고, 그 자리를 **지식의 희소성 + 헛발 벌점**
둘이 이어받았다 (Tuning Knobs 「완성 한계의 산정」).

**인내는 의뢰인 한 사람의 참을성이고 기본값 3이다** — 하루 행동 칸(#27, P3)과
별개 항목(#40)이다. v6.1이 *"개칭"* 이라고 적었던 것은 틀렸고, GDD가
2026-08-10에 정정했다.

**순수 도메인이다.** `src/domain/intake.ts`는 `Rng`도 `fetch`도 import하지 않는다
(R10). 무작위는 의뢰 실현(F1) 시점에만 있고, 이 스토리의 전이는 전부 결정론이다.

## Acceptance Criteria

### 열쇠 판정

- [ ] `hintTags`가 하나라도 겹치는 재료로 일깨우면 **인내 소모 없이** `knows[칸]`이
      그 단계로 오르고 칸이 즉시 채워진다 — **AC-R5-01**
- [ ] `hintTags` 교집합이 공집합이면 아무 칸도 열리지 않고 **인내 −1**, 칸 상태는
      `막힘(무지)` 그대로다 — **AC-R5-01**
- [ ] `leverageTag == keyLeverage`인 재료로 들이대면 **인내 소모 없이** `tells[칸]`이
      오르고 칸이 즉시 채워진다 — **AC-R6-01**
- [ ] 틀린 `leverageTag`로 들이대면 `막힘(은폐)` 유지 + **인내 −1** + **같은 칸에
      재시도가 가능**하다 (문이 영구히 닫히지 않는다) — **AC-R6-01**
- [ ] 의뢰인의 `keyLeverage`가 `없음`(갱단)이면 **플레이어가 가질 수 있는 모든 재료를
      전수 대입해도** 단 하나도 열리지 않는다 — **AC-R6-02**
- [ ] 일깨우기는 `막힘(무지)` 칸에만, 들이대기는 `막힘(은폐)` 칸에만 적용된다.
      반대로 호출하면 상태·인내 **둘 다 불변**이고 오류가 아니다 (호출 자체가 막힌다)

### 재료 출처 경계 — **정적 검사**

- [ ] **이 대화에서 얻은 사실은 일깨우기 후보 목록에 나타나지 않는다.** 목록 생성
      함수가 「들은 것」 묶음을 원천적으로 참조하지 않는다 — **AC-R5-02** *(정적)*
- [ ] 들이대기 후보 목록은 **「들은 것」·길드마스터북 양쪽 모두**에서 나온다 — R6
- [ ] `막힘(무지)` 칸에 줄 재료가 하나도 없으면 `[일깨운다]` 행동이 **뜨지 않는다.**
      빈 목록을 띄우지 않는다 — **AC-R9-01**

### 무료 행동

- [ ] 묻기·캐묻기는 인내를 쓰지 않는다. 벽이 확인된 칸을 다시 물으면 **상태·인내
      둘 다 불변**이다 (응답 문자열만 짧아진다) — **AC-R4-02**
- [ ] 넘어가기는 언제나 가능하고 인내를 쓰지 않는다 — **AC-R7-01**
- [ ] **위험도 등급 기입은 인내를 쓰지 않는다** — Edge Cases 「인내」
      *(R13 폐기 후의 정합 조항. 인내를 쓰는 행동은 헛발 둘뿐이다)*

### 인내 0 — 순서가 규칙이다

- [ ] 인내 1에서 헛발이 나면 **그 실패의 대사와 기록을 정상 처리한 뒤에** 의뢰인이
      퇴장한다. 마지막 반응이 씹히지 않는다 — **AC-EDGE-01**
- [ ] 의뢰인 퇴장 후에도 **위험도 등급 기입과 도장이 가능**하다 — **AC-EDGE-02**
      (짝: `commission-form.md` AC-CF-13)
- [ ] 퇴장 후 묻기·일깨우기·들이대기는 **불가능**하다 (사람이 없다). 그러나 이것이
      막다른 길이 아님을 상태로 증명한다 — 계약은 계속 진행 가능하다 (기둥 5)
- [ ] 인내는 **음수가 되지 않는다.** 0에서 더 깎이는 경로가 없다 (경계값 검사)
- [ ] 인내 초기값이 `balance.json`의 `intake.patience`에서 온다. **코드에 3이 박혀
      있지 않다** *(정적)* — Forbidden Patterns 「밸런스 숫자 하드코딩 금지」

### 결정론

- [ ] 같은 `(칸, 행동, 재료)` 시퀀스는 **LLM 유무와 무관하게** 같은 칸 상태와 같은
      인내 잔량을 만든다 — **AC-R10-01**
- [ ] *(정적)* `src/domain/intake.ts`에 `fetch`·LLM 게이트웨이·`Math.random` import가
      없다 — R10

## Implementation Notes

- 파일: `src/domain/intake.ts` (신설). 노브는 `src/data/balance.json`의 `intake` 절.
- **왜 매칭 조건을 둘로 나누는가**: 일깨우기는 *"무엇에 대한 것인가"*, 들이대기는
  *"누구에게 통하는가"* 다. **전자는 칸을 읽는 일이고 후자는 사람을 읽는 일이다.**
  구현상으로도 서로 다른 곳을 본다 — 일깨우기는 `slot.hintTags`(칸이 소유),
  들이대기는 `client.keyLeverage`(사람이 소유). **두 판정을 한 함수로 합치지 마라.**
  합치면 인자 하나로 분기하는 함수가 되고, 그 순간 어느 쪽이 칸을 보고 어느 쪽이
  사람을 보는지가 코드에서 사라진다.
- **순서가 중요한 곳이 정확히 하나 있다**: 인내 0 처리다. `헛발 처리 → 대사/기록
  확정 → 인내 감소 → 퇴장 판정` 순으로 간다. 인내를 먼저 깎고 퇴장을 먼저 판정하면
  마지막 실패의 반응이 통째로 씹히고, 플레이어는 *"뭐라고 했는지도 못 들었는데
  나갔다"* 를 겪는다. **GDD가 AC-EDGE-01을 따로 세운 이유가 이것이다.** 함수는
  `{ 새 상태, 이번 턴의 이벤트 목록, 퇴장 여부 }`를 한 번에 돌려주고, 퇴장은
  **이벤트 목록의 마지막 항목**이지 앞선 이벤트를 지우는 플래그가 아니다.
- **`막힘(무지)`과 `막힘(은폐)`을 절대 한 값으로 뭉개지 마라.** 이 저장소는 소문
  네트워크에서 *"입을 다물었다"* 와 *"아는 게 없다"* 를 한 문안으로 뭉갰다가 버그를
  냈다 (`rumorNothingToTell`). 두 열쇠의 적용 대상이 정확히 이 구별이므로, 뭉개면
  **두 열쇠가 하나로 붕괴한다.**
- **후보 목록 생성은 판정과 분리한다.** `일깨우기 후보(수첩, 칸)` / `들이대기
  후보(수첩, 의뢰인)` 두 함수가 따로 있고, R9의 「줄 게 있을 때만 뜬다」는 UI가 아니라
  **이 함수의 반환이 비었는지**로 결정된다. UI가 판단하면 규칙이 화면에 새어 나간다.
- **후보 목록은 유효/무효를 표시하지 않는다** (U3, AC-UI-05). 도메인이 `isValid`
  같은 필드를 실어 보내면 UI가 안 쓰기로 해도 DOM에 남는다. **아예 계산하지 마라.**
- **Q8은 열려 있다 — 여기서 닫지 마라.** *"인내 소진 퇴장 시 계약의 거취"* 는
  ① 의뢰서만 남는다 ② 제안액을 남기고 간다 ③ 의뢰 철회 셋 중 미정이다.
  구현은 **세 답이 전부 도달 가능한 모양**으로 둔다 — 퇴장은 `client.present = false`
  같은 **상태 플래그 하나**로만 표현하고, 계약 객체를 삭제하거나 제안액을 지우는
  코드를 지금 쓰지 않는다. 프로토는 ①로 동작한다.

- **인내 3이 맞는 값인가** — Q1, 프로토 4회차. 이 스토리는 **노브를 만들 뿐 값을
  결정하지 않는다**
