# Story P1-013: LLM 연기 배선 — 게이트웨이 ↔ 청취

> **Phase**: P1 | **Status**: Ready | **Layer**: Integration | **Type**: Integration
> **GDD**: `design/gdd/intake-system.md` (v6.2) R11 · R10 · Edge Cases 「같은 의뢰인의 재방문」
> **ADR**: ADR-003 D3·D5·D6 (**D4는 폐기 — 아래 참조**)
> **Created**: 2026-08-10

## Context

**게이트웨이는 이미 있다.** `src/llm/gateway.ts`와 `workers/intake-proxy/worker.js`는
커밋 `911e448`로 들어와 있고 `validateTurn`을 양쪽에서 두 번 한다. **없는 것은
청취 화면과 그것을 잇는 선 하나뿐이다.** 이 스토리는 코드를 쓰는 것이 아니라
**배선하는 것**이다.

**LLM의 소관은 대사 생성 하나다.** 의뢰인의 대사, 그리고 **길드마스터 자신의
대사**(행동 → 문장). 이해도 분류도 대비 추출도 없다 (R11).

> ### ⚠ 기록해야 할 정정 — **ADR-003 D4(자유 서술 분류)는 2026-08-10부로 폐기다**
>
> D4는 *"입력은 이제 `(slot, depth)` 분류 결과다"* 를 전제로 결정론을 다시
> 정의했다. **확정 설계가 자유 텍스트 입력과 LLM 대비 추출을 함께 삭제하면서 그
> 문장이 가리키는 것이 세상에 없어졌다.** 그러므로:
>
> - **LLM은 게임 상태에도 판정에도 전혀 닿지 않는다.** 상태에 닿는 출력이
>   `(slot, depth)` 하나였는데 **그 하나마저 사라져 0이 됐다**
> - **「대비 추출용 ADR」이 필요 없다.** ADR-003의 「되살아나는 조건」이 의뢰서
>   자유 서술 국면에서 한 번 발동했다가 **입력 자체가 삭제되면서 철회됐다** —
>   그 국면용 ADR은 쓰지 않는다
> - 재현 키는 원래대로 **`(칸, 행동, 재료?)`** 다. LLM이 판정 뒤에 서므로
>   결정론을 재정의할 이유가 없다 (R10)
>
> 다음 사람에게: 의뢰서에 자유 서술을 다시 넣자는 제안은 새 아이디어가 아니라
> **이미 기각된 것의 재발**이다.

## Acceptance Criteria

- [ ] 청취 판정이 **끝난 뒤에** `requestTurn()`이 불린다 — 판정 함수가 게이트웨이를
      import하지 않는다 *(정적: `src/domain/**`에 `src/llm/` import 0건)* (R10 · D3)
- [ ] 의뢰인의 대사가 LLM에서 온다 — 판정 결과 `(칸, 도달, 사유, 직업)`이
      `TurnRequest`로 실린다 (R11 · D3)
- [ ] **플레이어(길드마스터)의 대사도 LLM에서 온다** — `GeneratedTurn.options`가
      화면의 선택지가 되고, 각 선택지는 **반드시 `nodeId` 또는 `clueId`를 가진다**
      (R11 · D3)
- [ ] 화이트리스트 밖 id가 달린 선택지는 화면에 도달하지 못한다 — 목 게이트웨이가
      없는 id를 돌려주는 테스트로 확인. **클라이언트 검증만으로 성립해야 한다**
      (Worker를 목으로 바꿔도 뚫리지 않을 것) (D3)
- [ ] **AC-R11-01** *(정적 — 페이로드 검사)* 요청 페이로드에 **미공개 칸의 `fact`가
      없다.** `candidates[]`에 `topic`만 있고, `knows`/`tells` 원본·거짓말 성향·
      도달하지 못한 칸의 값이 **한 필드도 실리지 않는다** (D6)
- [ ] *(회귀)* `topic`만 실어 보낸 후보의 **내용어가 응답 문장에 등장하지 않는다** —
      프로토 3회차 사고의 회귀 케이스다 (ADR-003 Verification)
- [ ] 시스템 프롬프트에 **나쁜 예와 좋은 예가 둘 다** 들어 있다 — ① 후보를 자기
      궁금증으로 읽어 길드마스터에게 되묻는 나쁜 예, ② 역할이 갈린 좋은 예.
      *"암시로는 안 막힌다"* — **금지 문구만 있고 예시가 없으면 이 AC는 불합격이다**
      (R11)
- [ ] **AC-R11-02** 게이트웨이를 **완전히 차단**해도 **판정·인내 회계가 바이트 단위로
      동일**하다. 달라지는 것은 **대사 문자열뿐**이다 — 같은 `(칸, 행동, 재료?)`
      시퀀스를 LLM 목 / 차단 두 경로로 돌려 상태를 비교한다 (D5)
- [ ] **AC-EDGE-03** 타임아웃(8초) → 판정은 이미 확정, 폴백 문안으로 대사.
      **인내 복원·상태 되돌리기 로직이 존재하지 않는다** *(정적)*
- [ ] 폴백 문안은 `text.json`(story-006 조립 엔진)에서 온다 — **새 문안 엔진을 만들지
      않는다.** WONTFIX가 번복되어 폴백으로 존속하는 그 코드다 (D5)
- [ ] **AC-UI-03** *(수동-BLOCKING)* 실브라우저: 게이트웨이 차단 상태로
      **청취 → 보수 → 도장이 완주된다**
- [ ] 대화 이력이 **계약 단위로 초기화**된다 — 같은 의뢰인이 다시 와도 `history`가
      빈 채로 시작한다 (Edge Cases 「같은 의뢰인의 재방문」)
- [ ] 응답 대기가 **스피너가 아니다** — 2초 내 「의뢰인이 생각한다」 질감(뜸·시선·
      필기)이 뜨고, 8초를 넘기면 폴백으로 간다 (D7)
- [ ] 기동 시 `checkHealth()`가 한 번 돌고, 죽어 있으면 **한 번만** 알린 뒤 폴백
      모드로 전체 진행이 가능하다 (D5)

## Implementation Notes

- 파일: 청취 화면 모듈(프레젠테이션) + 얇은 어댑터. **`src/llm/gateway.ts`는 손대지
  않는 것이 기본이다** — 고쳐야 한다면 그것은 이 스토리의 범위가 아니라 결함 신고다
- `TurnRequest.saidFact`는 **방금 판정으로 공개가 허가된 사실 하나**다. 허가되지
  않은 것이 여기 들어가는 순간 AC-R11-01이 깨진다 — **판정 출력에서만 채우고,
  `Contract.slots`에서 직접 읽지 않는다**
- **페이로드 검사는 문자열 grep이 아니라 구조 검사로 쓴다.** 필드 이름을 화이트
  리스트로 고정하고 그 밖의 키가 있으면 실패시키는 편이, 값에 우연히 안 걸리는
  검사보다 오래 산다
- 프롬프트의 좋은 예/나쁜 예는 **Worker가 소유한다** (`worker.js`의 `PERSONA` 옆).
  클라이언트에 내려가면 안 된다 (D2)
- 대기 연출은 V3의 침묵 질감과 **같은 자리**다. 새 위젯을 만들지 말고 그 층을 쓴다
- 화면 규약은 story-007이 세운 것을 그대로 따른다 — `mount*Screen`/`destroy()`,
  루트 1개 위임, `data-action`
