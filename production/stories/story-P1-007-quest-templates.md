# Story P1-007: 의뢰 템플릿 v6.1 — 7칸 스키마와 설명 가능한 위협

> **Phase**: P1 | **Status**: Ready | **Layer**: Data | **Type**: Config/Data
> **GDD**: `design/gdd/intake-system.md` (v6.2) R1 · R2 · F1 · F3 · Tuning Knobs ·
> `design/gdd/commission-form.md` F1 · F3
> **ADR**: ADR-001 / **ADR-004 (Accepted — 칸 어휘 7개. 이 스토리가 그 변경의
> 데이터 측이다)**
> **Created**: 2026-08-10

## Context

**`src/data/quest-templates.json`은 지금 stale하다.** 파일은 `"version": 2`를
선언하고 있고, `_comment`가 *"재작성 v6가 소유한다"* 라고 적혀 있지만 실제 내용은
**칸 3개(대상·규모·장소)** 뿐이다. GDD는 그 사이에 **7칸 어휘**로 확정되었고
(`특징 및 약점` 신설, 2026-08-10), `w[칸]` 기본값이 바뀌었으며, `실제 위협 T`가
콘텐츠별 명시 값으로 승격되었다.

**이 스토리는 v2 → v6.1 스키마 교체다.**

그리고 **새로 실리는 것 넷이 이 스토리의 진짜 무게다**:

| 새 필드 | 왜 |
| ---- | ---- |
| **실제 위협 `T`** | `assignment-dispatch.md` F3의 `D = P + C − T` 입력. 콘텐츠별 명시 (생성식 없음) |
| **그 `T`를 설명하는 진실** | **`T`가 왜 그 값인지를 사람이 읽을 수 있게** |
| 알아낼 수 있는 사실 목록 | `C`의 분모 `n`(의뢰서 F3)과 진실 항목의 정의 |
| 길드마스터북 참조 기준 | 이 의뢰를 뚫는 데 필요한 재료가 책에 있는지 |

> **왜 「`T`를 설명하는 진실」이 데이터 필드인가**: **아무도 설명할 수 없는 `T`는
> 플레이어가 도저히 추론할 수 없는 난이도이고, 그 순간 청취는 장식이 된다.**
> 의뢰서 F1이 *"플레이어는 숨겨진 숫자를 맞히는 것이 아니라, 알아낸 사실을 이
> 기준에 대입한다"* 라고 못박은 것이 정확히 이 문제다. `T = 6`(A급)인 의뢰라면
> **A급인 이유가 슬롯의 사실 안에 실제로 있어야** 한다 — *"트롤 3마리, 폐광 안"*
> 처럼. 사실과 `T`가 어긋나면 플레이어는 옳게 추론하고도 죽는다.
>
> **그래서 검증이 빌드를 깬다.** 취향 문제가 아니라 **콘텐츠 결함**이다.

## GDD 요구 인용

- **청취 R1** — *"**칸 어휘는 7개다**: 의뢰 종류 · 대상 · 규모 · 장소 · 기한 · 경로 ·
  특징 및 약점"* / *"**7개는 어휘의 전부이지 매 의뢰의 칸 수가 아니다.**"*
- **청취 R2** — *"각 칸은 **2단**이다: `어렴풋` 사실 하나, `확실` 사실 하나."*
- **청취 F1** — *"**RNG 소비 순서 고정**: 칸은 **스키마 순서**로 소비한다:
  종류 → 대상 → 규모 → 장소 → 기한 → 경로 → 특징 및 약점"* /
  *"**새 칸은 반드시 스키마 맨 뒤에 붙인다.** 중간에 끼우면 그 뒤 칸 전부의 RNG
  소비 위치가 밀려 **같은 시드가 다른 의뢰를 낳는다.**"*
- **청취 F3** — *"`w[칸]`은 종류별로 정한다 (조사: 대상 3 / **특징 및 약점 3** /
  규모 2 / 장소 1 — 기한·경로는 그 템플릿이 열 때만)"*
- **청취 Tuning Knobs** — 의뢰당 칸 수 기본 **3**(종류 외), 범위 2~5 ·
  `w[칸]` 최대:최소 **3:1 이하**
- **청취 R11** — *"프롬프트에는 **공개가 허가된 내용만** 싣는다 (ADR-003 D6) —
  미공개 칸은 `topic`(물어볼 거리의 이름)으로만 표현하고 `fact`를 주지 않는다."*
- **의뢰서 F1** — *"**실제 위협도 `T` 매핑** — 의뢰마다 숨은 값이며, P1은
  **콘텐츠별로 명시**한다 (생성식 없음): D=3 · C=4 · B=5 · A=6 · S=7"*
- **의뢰서 F3** — *"분모 `n`은 「그 의뢰의 진실 항목 수」다 — 서식의 7항목이 아니다."*
- **의뢰서 Tuning Knobs** — 진실 항목 수 `n` 기본 **3~4**, ***"`n ≥ 3` 권장"***
  (`n=1`이면 `C`가 0/2/4만 나와 판단이 거칠어진다)
- **의뢰서 AC-CF-08** *(BLOCKING)* — *"**실제 위험 `T`가 파견 전에 노출되지 않는다**
  — 화면, DOM, 세이브 파일, 네트워크 페이로드 어디에도 없다."*

## Acceptance Criteria

### 스키마 교체

- [ ] `"version"`이 **2 → 6.1**로 바뀌고, `_comment`가 v6.2 GDD와 `특징 및 약점`
      신설을 반영한다 (현재 `_comment`는 v6를 가리키며 stale하다)
- [ ] 칸 어휘가 **7개**다: `종류 · 대상 · 규모 · 장소 · 기한 · 경로 · 특징 및 약점` —
      청취 R1
- [ ] *(BLOCKING)* **파일 내 칸 순서가 위 스키마 순서와 정확히 일치한다.** 검증이
      순서를 비교하고, 어긋나면 **빌드 실패** — 청취 F1
- [ ] 칸별 필드: `weight` · `hintTags[]` · `steps` = **2단 `[어렴풋, 확실]`** —
      청취 R2
- [ ] step 필드: `topic` · `fact` · `leverageTag`(`null` 허용). **`topic`이 LLM
      프롬프트에 가는 유일한 값**이다 — 청취 R11 · ADR-003 D6
- [ ] `w[칸]` 기본값: **대상 3 / 특징 및 약점 3 / 규모 2 / 장소 1** — 청취 F3
- [ ] *(검증)* 한 템플릿 안에서 `max(w) / min(w) ≤ 3`이다 — 청취 Tuning Knobs
- [ ] 의뢰당 실제 칸 수(종류 제외)는 **기본 3**, 범위 2~5. 7은 어휘이지 칸 수가
      아니다 — 청취 R1 · Tuning Knobs

### 의뢰 종류 4종

- [ ] `조사` · `퇴치` · `호위` · `수색` 넷이 존재한다. 각 종류가 여는 칸 집합을
      명시한다 (예: 호위는 `경로`·`기한`이 열리고, 퇴치는 `특징 및 약점`이 중심)
- [ ] 각 종류마다 시나리오가 **2개 이상** 있고, `fits`(어울리는 직업)가 지정된다
- [ ] `특징 및 약점` 칸이 **적어도 퇴치·수색에서** 열린다. 이 칸이 대비 `C`를 가장
      크게 올리므로, 어느 종류에서도 안 열리면 신설의 의미가 없다

### **실제 위협 `T`와 그것을 설명하는 진실** — 새로 실리는 것

- [ ] 모든 시나리오가 **`threat` (실제 위협 `T`)** 를 정수로 명시한다.
      허용값 **3(D) / 4(C) / 5(B) / 6(A) / 7(S)** — 의뢰서 F1. **생성식은 없다**
- [ ] 모든 시나리오가 **`threatRationale`** — *그 `T`를 설명하는 진실* — 을 갖는다.
      이것은 **그 의뢰의 슬롯 `fact`들이 실제로 담고 있는 내용을 근거로** 쓰인다
- [ ] 모든 시나리오가 **`truthSlots[]`** — *알아낼 수 있는 사실 목록* — 을 갖는다.
      이것이 의뢰서 F3의 분모 `n`이다. **`n ≥ 3`** *(검증 경고: `n < 3`)*
- [ ] 모든 시나리오가 **`handbookRefs[]`** — *길드마스터북 참조 기준* — 을 갖는다.
      이 의뢰의 막힌 칸을 뚫는 데 쓸 수 있는 책 항목 `id` 목록
- [ ] 모든 시나리오가 `statedRisk` (의뢰인의 주장 등급)를 갖는다. **`threat`와
      달라도 된다 — 그것이 은폐형의 정상 실현이다** (의뢰서 Edge 「주장이 실제와
      정반대」)

### **`T` ↔ 진실 정합 — 빌드 게이트**

- [ ] *(정적, **BLOCKING — 빌드 실패**)* `threat`와 `threatRationale`·`truthSlots`가
      **일치하지 않으면 빌드가 깨진다.** 최소 검사 셋:
      - `threatRationale`이 비었거나 공백이면 **실패**
      - `threatRationale`이 근거로 든 슬롯 이름이 `truthSlots`에 없으면 **실패**
      - `truthSlots`에 실린 칸이 그 시나리오의 `slots`에 없으면 **실패**
      - `threat`가 3~7 밖이면 **실패**
- [ ] *(정적)* `handbookRefs[]`의 모든 `id`가 `handbook` 배열에 실재한다.
      **없는 id를 참조하면 빌드 실패** — 오타 하나가 그 의뢰를 통째로 안 열리는
      의뢰로 만든다

> **근거를 다시 적는다**: **아무도 설명할 수 없는 `T`는 플레이어가 추론할 수 없는
> 난이도이고, 그러면 청취가 장식이 된다.** 의뢰서 F1의 다리는 코드가 아니라 사람이
> 놓는다 — 그 사람이 놓을 다리의 반대편 기둥이 `threatRationale`이다.
> **검증이 없으면 이 필드는 3주 안에 빈 문자열이 된다.**

### 은닉

- [ ] *(정적, BLOCKING)* `threat`·`threatRationale`은 **파견 결과 이전에 어떤
      경로로도 클라이언트 화면·DOM·세이브·LLM 페이로드에 도달하지 않는다** —
      의뢰서 **AC-CF-08**
- [ ] *(정적)* LLM 프롬프트 조립 경로가 **미공개 칸의 `fact`를 싣지 않는다.**
      `topic`만 간다 — **AC-R11-01**

### 결정론

- [ ] 같은 시드 + 같은 템플릿 → 같은 `knows`/`tells` 실현 — **AC-DET-01**
- [ ] **템플릿의 칸 배열 순서를 바꿔도 같은 시드면 같은 실현** (RNG 순서는 스키마가
      고정하지 배열이 고정하지 않는다) — **AC-F1-03**

## Implementation Notes

- 파일: `src/data/quest-templates.json` · 검증 `tools/validate-templates.ts`(가칭)를
  `npm run check`에 물린다.
- **파일의 칸 순서와 RNG 소비 순서가 같다는 것이 이 스키마의 가장 위험한 성질이다.**
  칸을 중간에 끼우면 **그 뒤 칸 전부의 RNG 위치가 밀려 같은 시드가 다른 의뢰를 낳는다.**
  `특징 및 약점`을 맨 뒤에 둔 이유가 이것이고, 앞으로도 같다. *(GDD가 정직하게
  적었듯 지금은 세이브가 0개라 **이번 추가의 실제 비용은 0**이다 — 규칙을 적어 두는
  것은 세이브가 생긴 뒤에 같은 판단을 다시 하지 않기 위해서다.)*
  → **구현 요구**: RNG 소비는 **코드의 상수 배열**(`SLOT_ORDER`)을 순회하고
  JSON 키 순서를 신뢰하지 않는다. AC-F1-03이 그것을 고정한다.
- **`topic`과 `fact`의 경계를 데이터 작성자가 잊는다.** `topic`은 *"물어볼 거리의
  이름"* 이지 대답이 아니다 — *"그 생김새"* 는 맞고 *"발가락이 셋"* 은 틀렸다.
  프로토 3회차에서 후보에 `fact`를 실었더니 **의뢰인이 묻지도 않은 사실을 먼저
  말했다** (R11 주석). 검증에 *"`topic` 길이 상한"* 같은 거친 방어라도 두면 좋다.
- **`leverageTag: null`을 성실히 쓰라.** 모든 사실이 무기가 되면 들이대기가
  *"아무거나 던지기"* 가 된다. 현재 v2 데이터는 `어렴풋` step이 전부 `null`이고
  `확실` step이 전부 태그를 갖는 규칙적 패턴인데, **이 패턴 자체가 공략집이다** —
  깨라.
- **`truthSlots`는 `slots`의 부분집합이지 같은 것이 아니다.** 의뢰서 F3이
  *"그 의뢰에 실제로 존재하는 사실만 센다 (경로가 없는 의뢰에서 `경로: 미확인`은
  감점이 아니다)"* 라고 못박았다. 열리지만 진실 항목이 아닌 칸이 있을 수 있다.
- **`statedRisk`와 `threat`의 차이가 곧 그 의뢰의 드라마다.** 주장 `C` / 실제 `A`는
  은폐형의 정상 실현이며 흔하다. **일부러 여러 조합을 심어라** — 전부 일치시키면
  의뢰인의 주장이 정보가 아니라 정답 표시기가 된다.
