# Story P1-004: 청취 판정 — `respond()`와 정보 충실도

> **Phase**: P1 | **Status**: Ready | **Layer**: Domain | **Type**: Logic
> **GDD**: `design/gdd/intake-system.md` (v6.2) R4 · R10 · F2 · F3
> **ADR**: ADR-001 D2·D3·D4 / ADR-003 (LLM은 판정 경로에 없다) / ADR-004 D2·D4 (Accepted)
> **Created**: 2026-08-10

## Context

**이것이 청취의 심장이다.** 칸을 짚는 것이 곧 질문이고, 그 질문에 무엇이 돌아오는지를
정하는 함수가 여기 있다. `technical-preferences.md`의 **필수 테스트 4번**(*청취 판정*)이
이 모듈이다.

**판정은 세 갈래뿐이고, 순서가 규칙의 전부다:**

```
① knows[s] < L  →  모른다      (무지 — 일깨우기로 뚫는다)
② tells[s] < L  →  얼버무린다  (은폐 — 들이대기로 뚫는다)
③ 그 외         →  말한다
```

**①이 ②보다 위인 것이 이 함수에서 가장 중요한 한 줄이다** — *모르는 것은 숨길 수도
없다.* 순서를 뒤집으면 무지한 의뢰인이 은폐형으로 보이고, 플레이어는 통할 리 없는
들이대기에 인내를 갈아 넣는다. **그리고 그것이 이 저장소가 이미 한 번 낸 사고의
형태다** — 소문 네트워크에서 *"입을 다물었다"* 와 *"아는 게 없다"* 를 한 문안으로
뭉갰고 버그가 됐다 (`rumorNothingToTell`). GDD가 *"**청취는 그 규칙을 처음부터 지고
출발한다**"* 고 적은 것이 이 지점이다.

**그리고 이 모듈은 아무것도 모른다.** `Rng`도 `fetch`도 import하지 않는다 — 무작위성은
의뢰 실현(F1, P1-002)에서 이미 끝났고, LLM은 판정 경로에 **존재하지 않는다**
(R11 · ADR-003 확정 개정). 그래서 `(칸, 행동, 재료?)` 시퀀스가 그대로 재현 키가 된다
(ADR-004 D4).

## GDD 요구 인용

- **F2** — *"`respond(칸 s, 다음 단계 L) = knows[s] < L → '모른다' / tells[s] < L →
  '얼버무린다' / 그 외 → '말한다'`. **경계**: `L = vague`(1) 또는 `certain`(2).
  `none = 0`."*
- **R4** — *"**①이 ②보다 위다 — 모르는 것은 숨길 수도 없다.**"*
- **R4** — *"묻기의 목적은 자원 소비가 아니라 **장애물의 정체 확인(진단)** 이다 —
  진단이 유료면 진단만 하다 끝난다. `미상→어렴풋`·`어렴풋→확실` 모두 무료다."*
- **R4** — *"벽이 확인된 칸을 같은 방식으로 다시 조르면 […] 무료지만 **응답이
  말라간다**"* — 상태·인내 불변.
- **R10** — *"상태 전이의 입력은 **플레이어가 누른 것**이다 — `(칸, 행동, 재료?)`.
  […] `src/domain/intake.ts`는 **`Rng`도 `fetch`도 import하지 않는다.**"*
- **F3** — *"`completeness = Σ(w[칸] × score(state[칸])) / Σ(w[칸])`,
  `score: 확실 1.0 / 어렴풋 0.5 / 막힘 0.0 / 미상 0.0`"*.
- **F3** — *"분모 0이면 1.0 고정, **`종류`는 가중합에서 제외**. **`막힘`과 `미상`이
  둘 다 0점인 것은 의도**다 — 정보량은 같고, 차이는 **책임 귀속**에만 쓴다 (P2)."*
- **AC-R4-01** — *"**`knows`가 우선**함을 둘 다 낮은 케이스로 확인한다."*
- **AC-F3-01** — *"워크드 예제: 대상3 확실 / 규모2 어렴풋 / 장소1 미상 → **0.667**."*
- **AC-F3-02** — *"종류 외 칸 0개 → `completeness = 1.0`."*

## Acceptance Criteria

- [ ] `src/domain/intake.ts`가 신설되고 **순수 함수만** 담는다 — 상태도 난수도 시간도 받지 않는다
- [ ] **AC-R4-01** — `respond(slot, L)`의 3분기가 F2와 일치하고, **`knows`와 `tells`가 둘 다 낮은 케이스에서 `'모른다'`가 나온다.** ①이 ②보다 위임을 이 케이스가 증명한다
- [ ] `L ∈ {vague=1, certain=2}` 전 조합 × `(knows, tells) ∈ {none,vague,certain}²` **9×2 = 18조합 전수**를 표 테스트로 고정한다
- [ ] 판정 결과가 `SlotProgress`로 옮겨질 때 사유가 맞다 — `'모른다'` → `('blocked','knowledge')`, `'얼버무린다'` → `('blocked','disclosure')`, `'말한다'` → `('vague'|'certain', —)` (ADR-001 D3)
- [ ] 전 조합에서 나오는 `limiter`가 **2값 안에 있다** — `'question'`이 어디서도 나오지 않는다 (ADR-004 D2)
- [ ] **AC-R4-02** — 묻기·캐묻기가 인내를 쓰지 않는다. **벽이 확인된 칸을 다시 물으면 상태·인내가 불변**이다 (응답 고갈은 연출층이며 판정이 아니다)
- [ ] **AC-EDGE-05** — 이미 채워진 칸을 다시 물으면 상태 불변, 비용 없음
- [ ] **AC-F3-01** — 워크드 예제: 대상 `w=3` 확실 / 규모 `w=2` 어렴풋 / 장소 `w=1` 미상 → `(3×1.0 + 2×0.5 + 1×0.0) / 6 = 4/6 = 0.667`
- [ ] **AC-F3-02** — 종류 외 칸 0개 → **분모 0 → `completeness = 1.0`** (0으로 나누지 않는다)
- [ ] `종류`(`kind`) 칸이 **가중합의 분자·분모 양쪽에서 제외**된다. 분모에서만 빼는 구현은 실패한다
- [ ] `막힘(무지)`·`막힘(은폐)`·`미상` 셋이 **`completeness`에서 전부 0점**이다 — **이것은 의도이며 버그로 고치면 안 된다.** 그 차이는 P2 책임 귀속에만 쓴다
- [ ] **AC-R10-01** — 같은 `(칸, 행동, 재료?)` 시퀀스는 **LLM 유무와 무관하게** 같은 칸 상태를 만든다
- [ ] *(정적 테스트)* **`src/domain/intake.ts`가 `Rng`를 import하지 않는다** (R10)
- [ ] *(정적 테스트)* **`src/domain/intake.ts`가 `fetch`를 import·호출하지 않는다** — `src/domain/**` 전체의 규약이다 (technical-preferences Forbidden Patterns)
- [ ] `completeness`가 **저장되지 않는다** — 매번 `slotProgress` + `weight`에서 계산된다. 저장하면 가중치 튜닝이 과거 세이브에 안 먹는다 (ADR-004 D7)
- [ ] `npx tsc --noEmit` 무경고

## Implementation Notes

- 파일: `src/domain/intake.ts` (신설)
- **정적 검사를 주석이나 코드 리뷰에 맡기지 않는다.** 파일 소스를 읽어 `import`
  구문을 검사하는 **실제 테스트**로 만든다. `negotiation.ts`가 순수 함수라는 것은
  시그니처가 증명했지만, 여기서는 **모듈 경계 자체가 요구사항**이다 (R10)
- **`respond()`는 `SlotTruth`가 아니라 `Pick<SlotTruth, 'knows'|'tells'>`를 받는다.**
  `negotiation.ts`가 `NegotiationClient`로 좁힌 것과 같은 이유 — **판정이 읽는 것이
  그 둘뿐임을 타입이 못박는다.** `valueKey`와 `weight`는 판정에 영향을 주지 않는다는
  것이 이 좁힘으로 컴파일러의 보장이 된다
- `Reach`를 **숫자로 비교하기 위한 사다리 함수**가 필요하다 (`none=0`, `vague=1`,
  `certain=2`). 이것을 `intake.ts` 안에 두지 말고 `slots.ts`(P1-001)에 두는 것을
  검토할 것 — `SlotTruth`를 만드는 쪽(P1-002의 클램프)도 같은 비교를 한다
- **`completeness`의 분모 0 케이스를 `1.0`으로 고정하는 것이 왜 옳은가**: 잴 칸이
  없으면 *"정보가 부족하다"* 가 아니라 *"부족할 것이 없다"* 다. `0.0`으로 두면
  칸 없는 의뢰가 자동으로 최악의 지원 판정을 받는다
- ⚠ **`Q6`은 이 스토리가 풀지 않는다.** `completeness`(가중 평균, 지원 판정용)와
  대비 `C`(진실 항목별 충실도, 파견 판정용)를 하나로 합칠 것인가는 **P2 착수 시
  `assignment-dispatch` 스펙이 소유한다.** 여기서는 **`completeness`만** 만들고
  `C`를 만들지 않는다. 지금 합치면 P2가 되돌려야 하고, 지금 `C`를 미리 만들면
  **답이 안 난 질문에 코드로 답한 것이 된다**
- 인내 회계(헛발 −1, 0에서 퇴장)는 이 모듈의 이웃이다. **`respond()` 안에 넣지
  않는다** — 인내는 일깨우기·들이대기의 결과에 반응하고 `respond()`는 그 둘을
  모른다 (R4: 묻기는 무료)

## Out of Scope

- **일깨우기(R5)·들이대기(R6) 판정** — `hintTags` 겹침 / `leverageTag` 매칭.
  재료(길드마스터북)가 없으면 만들 수 없다
- **인내 회계와 퇴장 처리** (AC-EDGE-01·02) — 별도 스토리
- **선제 진술(R3)** — 착석 시 `min(knows, tells)`까지 자동 진술. 대사 생성과 묶인다
- **대비 `C`** — Q6 미해결. **P2 소관**
- **LLM 게이트웨이·대사 생성** (R11) — 판정 경로 밖이다. 이 모듈은 문자열을 만들지 않는다
- **응답 고갈 연출** (R4 후반) — 프레젠테이션. 판정은 불변이므로 여기서 다루지 않는다
- 청취 화면 배선 (AC-UI-01~07) — 프레젠테이션 스토리. **실브라우저 검증이 완료
  기준이다** (technical-preferences 「브라우저 실검증 의무」)
