## 이 문서를 읽는 법

**날짜가 없다.** 시간 제약을 해제했으므로 일정 대신 **순서와 의존 관계**로 계획한다.
각 단계는 앞 단계가 끝나야 시작할 수 있고, 완료 기준을 통과해야 다음으로 간다.

각 단계는 이렇게 적혀 있다:

- **왜 이 순서인가** — 앞뒤가 바뀌면 무엇이 무너지는가
- **들어가는 것** — 구현 항목
- **완료 기준** — 이걸 못 보이면 안 끝난 것이다
- **먼저 쓸 문서** — 구현 전에 필요한 스펙

## 전체 구조

```
  P0 정리
   │
   ├─ P1 청취 + 의뢰서          ─┐
   ├─ P2 책임 (의뢰서 → 결과)    ├─ 세로 슬라이스
   └─ P3 압박 (처리량 + 고정비)  ─┘
   │
  ╔═══════════════════════════════╗
  ║  GATE — Core Hypothesis 검증  ║   ← 여기서 게임의 생사가 갈린다
  ╚═══════════════════════════════╝
   │
   ├─ P4 사람 (가치관·관계·상실)
   ├─ P5 세력 평판
   ├─ P6 세계 변화
   ├─ P7 메인 스토리 3막
   └─ P8 폴리시 · 오디오 · 접근성
```

**P1~P3이 세로 슬라이스다.** 여기까지 만들고 플레이테스트해서 Core hypothesis를
검증한 뒤에 P4 이후로 간다. **게이트를 건너뛰지 않는다** — P6(세계 변화)은 가장
비싼 단계인데, 창구가 재미없으면 그 비용이 전부 낭비된다.

## 경진대회 제출에 대하여 (2026-08-09 결정)

### 배포 채널 — **GitHub Pages 고정. 재검토하지 않는다.**

**이 프로젝트는 NAN2026 예선 제출용이다.** 배포는 무조건 GitHub Pages다.

이 결정이 닫는 것:

- **「넘을 수 없는 제약」 1번(서버가 없다)은 영구 제약이다.** 런타임 LLM 호출·서버측
  검증·커스텀 HTTP 헤더(COOP/COEP, 따라서 SharedArrayBuffer·WASM 멀티스레드)는
  **재검토 대상이 아니다.** 세이브 스캐밍 방어를 서버로 푸는 길도 영구히 없다 —
  *"금지가 아니라 무의미하게 만든다"* 가 유일한 방법으로 확정된다.
- 시장조사(`design/research/interrogation-games-market-2026-08-09.md` §2)가 열어 둔
  *"Steam이면 웹 전제를 재검토할 수 있다"* 는 **소멸했다.**
- `vite.config.ts`의 **`base: "./"`** 는 영구 필수 설정이다.

### ⚠ 그런데 이 결정이 새 리스크를 만든다 — 심사자는 완주하지 않는다

**캠페인은 8~15시간인데, 예선 심사에서 실제로 플레이되는 것은 첫 20~30분이다.**

로드맵의 P1~P3 → GATE 순서는 *"이 게임이 재미있는가"* 를 검증하는 순서이고, 그건 옳다.
그러나 **그것은 *"첫 30분이 심사에서 이기는가"* 를 검증하는 순서가 아니다.** 둘은 다른
질문이며, 지금 이 문서는 후자를 어디서도 묻지 않는다.

이미 있는 부분적 방어 두 개:
- 아래 **「제출용 단계를 따로 두지 않는다」 + 「`main`은 항상 배포 가능」** — 아무 날에
  마감이 와도 내보낼 것이 있다
- **첫 화면 1초 / 초기 전송 1MB 예산** — 심사자는 링크를 열고 로딩을 기다려 주지 않는다.
  `technical-preferences.md`의 성능 예산이 여기서 **심사 리스크**가 된다

**부족한 것 — 각 단계의 완료 기준에 넣을 것:**

> **첫 세션(1일차)이 그 자체로 완결된 인상을 주는가.**
> 8~15시간의 1/30만 보고 판단하는 사람에게 *"이 게임이 무엇인지"* 가 전달되어야 한다.

P1의 마르타 시나리오가 사실상 이 역할을 하고 있으므로 구조는 이미 있다. **명시되지
않았을 뿐이다** — GATE 통과 기준에 *"처음 30분만 플레이한 사람도 Core hypothesis 문장을
말할 수 있는가"* 를 추가할 것.

> 다음 사람에게: **완주 가능성과 첫인상은 다른 작업이다.** 로드맵 전체가 전자를 향해
> 정렬되어 있으므로, 후자를 잊기 쉽다.

---

마감이 이번 주에 하나 남아 있다 (문서 정합성 감사에서 발견 — story-019가 심사 계정
초대와 제출물을 수락 기준으로 걸고 있었다).

**결정: 제출용 단계를 따로 두지 않는다.** 계속 구현하다가 마감 시점의 빌드를 그대로
제출한다. 제출본을 위해 미리 다듬거나 기능을 얼리지 않는다.

### 그래서 지켜야 하는 규칙 하나

> **`main`은 항상 배포 가능한 상태여야 한다.**

제출 전용 안정화 기간이 없다는 것은, **아무 날에나 마감이 와도 내보낼 것이 있어야
한다**는 뜻이다. 이것이 이 결정이 요구하는 유일한 대가다.

실무적으로:
- 각 단계 끝에서 `npm run check` 통과 + **배포본이 처음부터 끝까지 완주 가능**
- 화면을 헐어야 하는 작업(P1의 창구 재작성)은 **한 번에 끝내고 그 안에서 커밋을
  쪼갠다.** 반쯤 헐린 창구로 며칠을 보내지 않는다
- 마감 며칠 전에 큰 리팩터링을 시작하지 않는다

### story-017 / 018 / 019는 미완이다

3일 판이 실제로는 닫히지 않았다 — `production/qa/smoke-2026-08-09.md`가 스스로
*"story-019의 최종 사인오프가 아니다"*라고 적어 두었고
`balance-notes-2026-08-10.md`는 존재하지 않는다. 이 셋은 **낡은 것이 아니라 미완**
이며, 새 계획에서는 **P8(폴리시)에 흡수된다.**

단 `production/qa/` 스모크 절차와 배포 파이프라인(story-019의 검증된 부분)은
**마감 전 언제든 다시 돌릴 수 있어야 한다.** 그것이 위 규칙의 실행 수단이다.

## P1 — 청취 + 의뢰서 작성

**왜 이 순서인가**: **Core hypothesis의 심장이다.** 이게 재미없으면 나머지를 만들
이유가 없다. 그리고 `Contract` 타입이 여기서 바뀌므로, 뒤의 모든 단계가 이것을
전제한다.

> **2026-08-09 갱신 — 이 절은 `design/gdd/intake-system.md`가 대체한다.**
> 그 문서는 정식 8섹션 GDD로 승격되어 `/design-review` full을 통과했고(2회 개정),
> 아래 항목보다 훨씬 구체적이다. **충돌하면 GDD가 이긴다.** 아래는 P1의 작업 단위
> 목록으로만 읽는다.

### 들어가는 것

1. **의뢰 내용 데이터 모델**
   - `Contract`에 슬롯 집합 추가. **슬롯 어휘 6개 확정**: `종류` · `대상` · `규모` ·
     `장소` · `기한` · `경로` (GDD 「슬롯 어휘와 의뢰 종류」)
   - 각 슬롯은 **4상태**다 — `미상 / 막힘(+사유) / 모호 / 확정`.
     ⚠ **`미상`과 `막힘`을 갈라 저장하는 것이 P2 책임 귀속의 유일한 근거다**(기둥 6)
   - `quest-templates.json` — **P1 의뢰 종류 4종**(조사·퇴치·호위·수색), 종류별 열리는
     슬롯 + F5 가중치
2. **무지(vagueness) 격차** — 기존 은폐(`concealment`)와 별개의 축. 의뢰인 직업이
   `knows`/`tells` 분포를 정한다 (GDD F4)
3. **의뢰인 직업** — 주민 / 상인 / 관리 / 영주·귀족 / 갱단 (+ 성직 / 군인은 P5 이후)
   - ⚠ **P1에서는 갱단·영주를 창구에 앉히지 않는다** (등장 확률 0). 소문 채널이 P4라
     은폐형 앞에서 갈 곳이 없다. 데이터는 지금 다 만든다
4. **질문 카탈로그** (`questions.json`) — **총 12개** = 슬롯 6 × 깊이 2등급.
   `id · slot · depth · keywords · requires`.
   ⚠ **완성 문장(`line`)을 담지 않는다** — 문안은 `(슬롯 × reach × limiter)` 키로
   `text.json`이 소유한다 (GDD R10)
5. **청취 판정** (`src/domain/intake.ts`) — 순수 함수, `Rng` 미import.
   `reach = min(knows, tells, depth)` / `limiter ∈ {지식, 공개, 질문}`
6. **응답 문안 36종** (`text.json`) — 슬롯당 6종 × 6슬롯 + 직업 레지스터 변형.
   ⚠ **무지의 침묵과 은폐의 침묵이 다르게 읽혀야 한다** — 이 저장소가 소문 시스템에서
   같은 실수를 한 번 했다 (`rumorNothingToTell`)
7. **하루 행동 칸 최소판** — **12칸 = 의뢰인 4 × 열린 슬롯 3.**
   원래 P3이었으나 **P1으로 당긴다** (아래 절 참조)
8. **입력 UI 3중 구조**
   - 클릭 앵커 — 의뢰인 대사의 단어. 비용 0. ⚠ 앵커 1개가 후보 1개와 1:1 대응되면
     드롭다운이 된다 (작성 규약)
   - 자유 타이핑 — 빈 입력창, placeholder 금지
   - 자동완성 — 부분 문자열 매칭, **후보 0개면 전송 불가 (무비용)**
   - ⚠ **포커스·캐럿·IME 조합 보존** — `<input>`과 후보 `<ul>`만 마운트 시 1회 생성하고
     나머지는 전체 재렌더. 기존 6화면과 다른 관용구다 (GDD U7)
9. **의뢰서 화면** — 받아쓰기 칸(자동) / 판단 칸(수동) 분리
   - 추정 위험도 등급, 권장 인원, 특이사항 토큰 슬롯
10. **길드마스터북** — *무엇을* 물을지만 알려주고 *답*은 알려주지 않는다.
    후보 0개 3~4초 지속 시 안내 (모달 금지)

### 완료 기준

- 마르타 시나리오가 끝까지 돈다: *"숲에 이상한 게 있어요"* → 캐묻기 → 슬롯이
  좁혀짐 → 의뢰서 작성 → 도장
- 질문을 하나도 안 해도 계약이 진행된다 (막다른 길 없음)
- 같은 시드 + **같은 질문 id 순서** = 같은 결과 (결정론)
- 후보 0개 상황에서 **행동 칸이 소모되지 않는다**
- **뭉툭 → 날카 2단 파고들기가 실제로 작동한다** (GDD AC-R4-03)
- **브라우저 실검증: 한글 조합 중 후보가 갱신돼도 조합이 끊기지 않는다**
  (GDD AC-UI-04 — happy-dom으로 검증 불가, **수동-BLOCKING**)

### ⚠ P1에서 반드시 같이 정해야 하는 것 — 지속성(세이브/로드)

**컨셉·로드맵 어디에도 저장이 없었다** (2026-08-09 감사에서 발견). 그런데
캠페인이 8~15시간이고 세션이 30~60분이면 **지속성은 선택이 아니라 필수다.**
한 탭에서 끊지 않고 8시간을 하는 사람은 없다.

그리고 단순 누락이 아니라 **기둥 5와 정면 충돌한다** — *"세이브 스캐밍 없음"*인데
저장이 존재하면 localStorage를 복사해 두는 것만으로 스캐밍이 가능하고, 정적
호스팅이라 서버 검증도 못 한다.

**왜 P1인가**: 저장 포맷은 모든 스키마 변경에 물린다. `Contract` 타입을
재설계하는 지금 같이 잡는 것이 압도적으로 싸다. P3 이후에 붙이면 그때까지의 모든
스키마를 소급 마이그레이션해야 한다.

정해야 할 것:
- 슬롯 수(단일 자동 저장 권장), 저장 시점(하루 마감만), 스키마 버전 필드
- **재현 키가 무엇인가** — 결정론 요구(*"같은 시드 + 같은 질문 순서 = 같은 결과"*)에서
  "질문 순서"가 무엇으로 기록되는가? 타이핑한 문자열인가, 매칭된 질문 id인가,
  클릭한 단어 앵커인가. 셋이 전부 다른 재현 키를 만들고, **이것이 곧 저장 포맷이다**
- 세이브 스캐밍 억제 방식 (시드 + 결정 로그를 함께 저장해 되감기를 무의미하게)

### ~~⚠ 두 자원의 역할 분담을 여기서 정의할 것~~ — **해소 (2026-08-09)**

> **인내심이라는 자원 자체를 폐기했다.** 질문의 비용은 **하루 행동 칸 하나뿐**이다.
>
> 폐기 근거는 **중복이었다** — 직업의 성격은 `knows`/`tells` 분포가 이미 전부 표현한다.
> 갱단에게 캐묻는 것이 손해인 이유는 인내심이 짧아서가 아니라 **안 나오기 때문**이다
> (슬롯당 막힘 70%). 이 절이 경고한 *"자원이 둘이면 무엇을 아끼는지 모른다"* 에 인내심이
> 정면으로 걸렸다. 근거 전문은 `intake-system.md`의 F3 폐기 기록.
>
> **딸려온 변경: 하루 행동 칸을 P3 → P1으로 당긴다.** 인내심을 지우면 P1에서 질문 비용이
> 0이 되어 *"전부 물어보기"* 가 지배 전략이 된다. **잠정값 12칸 = 의뢰인 4 × 열린 슬롯 3**
> — "모든 의뢰인의 모든 슬롯에 뭉툭한 질문 하나씩"이 정확히 예산을 다 쓰는 값이며,
> 깊이나 흥정을 원하면 반드시 어딘가의 넓이를 판다. 대기 목록·고정비는 P3에 그대로 둔다.
>
> ⚠ **이 칸은 질문 깊이 2등급(GDD R4)의 전제 조건이다.** Ace Attorney의 `Press`가
> 무비용 단일 등급이라 *"전부 눌러라"* 가 공식 공략이 됐고, 그 게임이 무너지지 않은 이유는
> `Present`에 페널티가 있어서다. **행동 칸 없이 `depth`만 구현하면 안 된다.**
> 근거: `design/research/interrogation-games-market-2026-08-09.md` §4.1

**회색지대는 이렇게 정했다**: 후보가 1개 이상인 질문은 **전부 비용을 문다.** 이미 확정된
슬롯의 재질문도 후보에서 숨기지 않고 칸을 소모한다 — 숨기면 그것이 곧 *"이미 아시잖아요"*
힌트이고, 청취 화면이 정답을 알려주지 않는다는 원칙(기둥 5)을 어긴다. 대신 재질문은
`limiter`라는 **진단**을 준다 (GDD R6).

   - **정확한 정답은 알려주지 않는다** — *"낮게 적었다"*까지만
   - 물어볼 수 있었는데 안 물은 질문을 사후에 보여준다
3. **모험가의 의뢰서 반응** — 위험도가 높게 적히면 배정을 거부하거나 수당을 요구

- 결과 화면에서 플레이어가 **자기가 적은 것**을 다시 본다
- 위험도를 낮춰 적는 것이 이득이자 위험임이 한 판 안에서 체감된다

**왜 이 순서인가**: P1~P2만 있으면 **꼼꼼히 하는 것이 항상 옳다.** 그러면 청취는

### 들어가는 것

1. ~~**하루 행동 횟수**~~ → **최소판은 P1으로 당겨졌다** (인내심 폐기의 결과 —

2. **대기 목록** — 오늘 못 부른 의뢰인은 사라진다. 무슨 의뢰였는지 영원히 모른다

3. **고정비** — 임대료 / 길드원 급여 / 치료비 / 장비 유지비. 주기적 정산

5. **근거 기반 협상** — 알아낸 사실을 근거로 들면 요구 배율 상한이 오른다

## P4 — 사람: 가치관 · 관계 · 상실

**왜 이 순서인가**: 게이트를 통과하면 이제 **누구를 보낼지**가 무거워져야 한다.
그리고 P5(세력 평판)가 모험가의 반응을 입력으로 쓰므로 그 전에 온다.

### 들어가는 것

1. **모험가 가치관** — 거절 조건, 공포 대상, 선호 의뢰, 과거 악연
   (에린 예시: 어린이 의뢰는 거절 안 함 / 언데드 공포 / 귀족 혐오)
2. **배정 거부와 그 결과** — 강제 배정 시 충성도 하락, 임무 중 이탈, 길드 탈퇴
3. **정보 채널 재배치** — 소문의 출처를 길드원 → 외부인·정보상으로 이동
   (`rumor.ts` 개정). 길드원은 의견·관계·자원만 말한다
4. **길드원 조언** — 사실이 아닌 의견. 배정 전에 거부·자원 여부를 미리 알 수 있다
5. **대화가 신뢰를 올린다** — 길드 홀 순회가 관계 관리가 된다
6. **상실 반응** — 함께 나갔던 동료에게 `lostComrade` 기억. 며칠간 조언·자원 안 함
   (자료 구조와 대사 4종이 이미 있다: `types.ts`, `text.json`)
7. **영입 하이브리드** — 돈 주고 데려오기(고를 수 있음) + 명성으로 지원자 찾아오기
   (무작위, 무료). 가입비는 받지 않는다

### 완료 기준

- 특정 모험가를 배정하려다 거부당하는 경험이 발생한다
- 동료가 죽은 뒤 남은 사람의 태도가 달라진 것이 눈에 보인다
- 명성이 오르면 지원자가 실제로 찾아온다

### 먼저 쓸 문서

- `design/quick-specs/adventurer-values-*.md`
- `design/quick-specs/rumor-network-*.md` 개정 — 출처 이동

3. **평판의 결과** — 세력별 의뢰 유입량, 가격, 특수 사건(세무 조사, 감찰관 방문)

**문서가 사실과 달랐다.** VERSION.md·CLAUDE.md·technical-preferences.md가 전부

| 근거 | 상태 |
