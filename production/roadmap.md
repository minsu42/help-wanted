# Roadmap — 제출판

**결정일:** 2026-08-10

**원칙:** 현재 완주 루프는 보존하고, 창구 청취·판정 화면만 핵심 신규 구현으로 완성한다.

## 출시 범위

`창구 → 파견 → 결과 → 길드 홀 → 하루 종료 → 엔딩 → 재시작`

창구에는 의뢰인 기색, 의뢰서 질문, 수첩, 길드마스터북, 응대 기록, 위험도 도장이
포함된다. 이 흐름에 직접 필요하지 않은 확장은 제출 후로 미룬다. 상세 범위는
`design/gdd/game-concept.md`가 소유한다.

## 작업 순서

### 0. 비주얼 타깃 잠금

- [x] 1280×720 창구 비주얼 타깃 승인 (`counter-visual-target-v2`)
- [x] 대표 의뢰인 1명의 64×64 초상과 표정 4종 제작
- [x] 수첩·의뢰서·길드마스터북·응대 기록의 픽셀 오브젝트 샘플 제작
- [ ] 실제 게임 크기에서 한 화면으로 합성해 승인
- [x] 파견·결과·홀·엔딩은 화면별 한 장 와이어프레임과 재사용 자산만 지정

합성 후보 `counter-object-composite-v1`은 1280×720 기술 검증을 통과했으며 사용자 승인
대기 중이다. 화면별 구조와 재사용 자산은 `submission-screen-wireframes-v1.md`가 잠근다.

완료 조건: 창구 한 화면이 최종 게임의 색, 비율, 픽셀 밀도, 상호작용 피드백 기준이 된다.

### 1. 기능 잠금

- [x] 의뢰서 7칸 질문과 자동 기록 상태 연결
- [x] 수첩·길드마스터북의 지식 사용과 의뢰인 기색 연결
- [x] 인내/응대 기록과 위험도 등급 도장 연결
- [x] 완성된 의뢰서를 기존 파견 루프로 전달
- [x] 브라우저에서 핵심 루프 한 회차 완주 (2026-08-10)
- [x] 화면 전환, 하루 진행, 결과 큐, 엔딩·재시작 확인
- [ ] 마우스와 키보드로 진행 가능 확인
- [ ] 막힘·데이터 유실·치명 오류만 수정
- [x] `npm run check` 통과 — 테스트 470개

완료 조건: 처음부터 끝까지 개발자 도구 조작 없이 완주한다.

### 2. 아트 잠금

- [x] 전체 화면을 승인된 2D 픽셀 형태 언어로 통일
- [ ] 창구 초상과 홀 전신이 같은 인물로 읽히게 연결
- [x] 종이·책·도장·인물 반응을 픽셀 애니메이션으로 표시
- [x] 버튼 기본·hover·disabled 상태 구분
- [x] 390×844에서 가로 넘침 없이 핵심 화면 표시
- [x] 라이선스가 확인된 기존 자산만 사용

완료 조건: 임시 UI처럼 보이는 화면이 없고 새 아트 요청 없이 제출 가능하다.

### 3. 콘텐츠·문구 잠금

- [ ] 튜토리얼 없이 첫 행동을 이해할 수 있는 짧은 안내
- [ ] 결과의 성공·부상·죽음과 원인이 읽힘
- [ ] 플레이스홀더·개발용 문구·빈 상태 점검

완료 조건: 처음 보는 사람이 핵심 루프를 설명할 수 있다.

### 4. 최종 밸런스

- [ ] 완주 불가, 즉시 파산, 항상 같은 선택 같은 블로커만 조정
- [ ] 수치는 `src/data/balance.json`에서만 수정
- [ ] 조정 뒤 완주 1회와 `npm run check`

완료 조건: 한 번의 정상 플레이에서 엔딩까지 갈 수 있고 선택이 최소 두 가지 이상 성립한다.

### 5. 배포·제출

- [ ] 프로덕션 빌드
- [ ] GitHub Pages 배포 URL 스모크 테스트
- [ ] 새로고침, 첫 로드, 완주, 재시작 확인
- [ ] 제출 설명과 스크린샷/영상 준비

완료 조건: 심사자가 별도 키·설정·설명 없이 플레이를 시작할 수 있다.
