# 프로토타입 3 — 흐르는 대화 + LLM 생성 선택지

> **상태**: 1회차 완료 (2026-08-10). **플레이테스트 대기**
> **선행**: `anchor-intake/` (앵커 전용 — *"취조 같다"* 판정으로 대체),
> `llm-intake-ab/` (자유 타이핑 + LLM 분류 — Portopia 위험으로 폐기)

## 왜 또 만들었나 — 진단이 두 번 바뀌었다

| 회차 | 형태 | 플레이 판정 |
| ---- | ---- | ---- |
| 1 | 자유 타이핑 + LLM 분류 | 유한 구조 뒤의 자유 입력 = Portopia형 위험 (조사) |
| 2 | 앵커(대사 속 단어 클릭) | *"정답 찾기 같다"* → *"**취조 같고 대화가 아니다**"* |
| **3** | **흐르는 대화 + 생성 선택지** | ← 지금 |

**2회차 판정의 원인은 입력 방식이 아니라 시간 구조였다.** 앵커든 자유 입력이든
**둘 다 턴제**다 — 내가 던지기 전까지 상대가 얼어붙어 있다. **그 멈춤이 취조의
정체다.** Oxenfree가 정확히 이 지점을 푼다: 상대가 계속 말하고, 선택지가 떴다
사라지고, **안 고르면 그냥 넘어간다.**

## 이 프로토가 시험하는 가설 셋

1. **상대가 멈추지 않으면 대화로 느껴지는가** — "취조" 판정이 사라지는가
2. **놓치는 것이 후회가 되는가** — 자유 타이핑을 버리며 잃었던 *"떠올리지 못한
   무능"* 이 **시간 축에서** 돌아오는가
3. **완결된 문장 선택지가 "정답 찾기"를 없애는가** — 매번 다르게 생성되므로
   외울 공략이 없다

## 구조

```
의뢰인이 말한다 (LLM 생성, 최대 2문장)
        ↓
길드마스터가 할 수 있는 말 2~3개가 뜬다 (LLM 생성, 완결된 문장)
        ↓                          ↘ 9초 동안 안 고르면
   고른다 → 무료                     사라진다 → 「놓친 것」으로
        ↓                                    ↓
   그물이 열린다                    청취록에서 되짚기 = 응대권 1
```

**응대권을 쓰는 곳은 셋뿐**: 되짚기 · 게이트 시도 · 재질문.
**흐름 안에서 잡으면 공짜다** — 티키타카가 곧 실력이 된다.

## LLM 소관 — 생성 하나뿐

**파싱을 하지 않는다.** 플레이어의 자유 텍스트를 해석하는 경로가 없으므로
Portopia형 실패(*"무엇이든 통한다"는 못 지킬 약속*)가 **구조적으로 불가능하다.**

한 턴에 한 번 호출해 `{say, options[]}`를 같이 받는다. 선택지에는 **우리가 준
후보 id**가 붙어 나오고, 그 밖의 id는 스키마 검증에서 버려진다 —
**LLM이 게임 상태에 닿지 못한다** (ADR-003 D3).

`config.js`가 없거나 호출이 실패하면 **고정 문안 폴백**으로 자동 전환한다.
헤더 우측에 연결 상태가 표시된다 (ADR-003 D5 — 폴백만으로 완주 가능).

## 1회차에서 잡은 것 — **설계 결함 하나 + 프롬프트 결함 둘**

### ⚠ ① 후보를 넘길 때 `fact`를 주면 연기자가 답을 먼저 말한다 (설계)

첫 실행에서 의뢰인이 **묻지도 않은 `발가락이 셋`을 먼저 말했다.** 선택지도
*"뼈들이 쌓여 있었다던데?"* 로 답을 흘렸다.

원인: 후보 목록에 **사실 원문**을 실었다 — **ADR-003 D6(공개가 허가된 내용만)
위반**이다. 문서는 *"미방문 노드는 연기자 자신이 모른다"* 고 적어 뒀는데,
**"그럼 후보는 무엇으로 표현하는가"** 가 정의되어 있지 않았다.

> **해결 — 노드에 `topic` 필드를 신설했다.** 물어볼 **거리의 이름**이고 내용을
> 담지 않는다. `d-toes`의 `fact`는 *"사람 발만 한데 발가락이 셋이었다"*,
> `topic`은 ***"발자국의 생김새"*** 다. 연기 프롬프트에는 `topic`만 간다.
>
> **GDD에 반영해야 한다** — 지금 스키마에 없는 필드다.

### ② 역할 혼동 — 의뢰인이 길드마스터에게 되물었다 (프롬프트)

*"발자국의 생김새가 매우 궁금합니다"* — 후보 목록을 **의뢰인 자신의 궁금증**으로
읽었다. 의뢰인은 **이미 겪은 사람**이지 궁금한 사람이 아니다.

해결: 시스템 프롬프트에 `say`/`options`의 화자를 **나쁜 예·좋은 예와 함께** 못박음.
*"암시로는 안 막힌다"* 는 GDD R11의 기록이 여기서도 그대로 맞았다.

### ③ 흐름 바가 안 돌았다 (코드)

`requestAnimationFrame(step)`을 `timer` 대입보다 먼저 호출해 첫 프레임에서
참조가 비었다. 순서를 바꿔 수정.

## 2회차 수정 (2026-08-10, 플레이 판정 이후)

플레이 판정: ***"재밌다. 다만 가능한 전부를 다 물어보게 되는 느낌."***

**뒤쪽 관찰이 실제 구멍이었다.** 놓친 화제가 다음 턴에 다시 후보로 떠서,
**기다리기만 해도 그물 전체를 응대권 0으로 팔 수 있었다.** 이 README가
*"놓치면 응대권을 쓴다"* 고 적어 놓고 **그 성질이 성립하지 않았다** —
「놓친 것」 목록이 장식이었다.

| 수정 | 내용 |
| ---- | ---- |
| **놓친 화제는 흐름에서 빠진다** | `candidates()`에 `&& !S.missed.has(n.id)`. 되짚기(응대권 1)로만 닿는다 |
| **실패 문구 제거** | `"물어볼 틈을 놓쳤다"` 삭제. GDD U2가 *"만료는 조용히. 실패 문구 금지"* 를 요구하는데 프로토가 정확히 그걸 어기고 있었다. 기계적 신호는 **「놓친 것」 패널이 는 것 하나뿐** |

> ⚠ **첫 번째 수정은 방금 확인된 재미를 바꿀 수 있다.** 별로면 `app.js`의
> `&& !S.missed.has(n.id)` 한 조각만 지우면 원래대로 돌아온다 (주석 달아 둠).
>
> **반대 방향 위험도 실측했다**: 수명을 3~4초로 줄이면 후보가 전부 놓쳐져
> **대화가 막힌다**(놓친 것 6개, 선택지 0개). 어느 쪽이 맞는지는 하루 경제와
> 만나야 안다 — GDD **Q13**.

## 아직 모르는 것 — 사람이 만져야 안다

1. **취조 느낌이 사라졌는가** — 이 프로토의 존재 이유다
2. **9초가 맞는가** — 압박이면 실패다. 읽고 고르는 데 편안해야 한다
3. **놓치는 것이 후회인가 짜증인가** — 후자면 시간 구조 자체가 틀린 것이다
4. **선택지가 매번 달라서 "정답 찾기"가 사라졌는가**
5. **LLM 응답 대기(1~3초)가 흐름을 끊는가** — 지금은 `…` 한 줄만 뜬다
6. **폴백 모드의 고정 문안으로도 대화처럼 느껴지는가** (헤더에서 확인 가능)
