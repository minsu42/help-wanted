# 프로토타입 — 앵커 전용 입력 + 정보 지렛대 게이트

> **상태**: 1회차 완료 (2026-08-10). **플레이테스트 대기** — 아직 사람이 만져보지 않았다.
> **대상 설계**: `design/gdd/intake-system.md` **4차 개정** (R4 앵커 · R8 지렛대 · R9 keyLeverage)
> **선행 프로토**: `prototypes/llm-intake-ab/` (3차 개정의 자유 타이핑 + LLM 분류. 대체됨)

## 검증하려는 가설 셋

1. **단어를 눌러 파고드는 것이 재미있는가** — 자유 타이핑을 버려도 유능감이 남는가
2. **지렛대 게이트가 *"아, 이걸 들이대면 되겠다"* 를 주는가** — 화법(공감/논리/압박)을
   대체할 만한가
3. **앵커 수 > 노드 수라서 가려내는 맛이 있는가** — 앵커가 질문 메뉴로 무너지지 않는가

## 실행

```bash
python -m http.server 8789
```

그리고 <http://localhost:8789/prototypes/anchor-intake/> 를 연다.
(`.claude/launch.json`의 `proto-anchor` 구성과 같다.)

`../../src/data/quest-templates.json`을 **실제로 읽는다** — 템플릿을 고치면 바로 반영된다.
그래서 `file://`로 열면 CORS로 실패한다. 반드시 서버로 열 것.

- **의뢰인** 드롭다운으로 직업을 바꾼다 (`keyLeverage`가 바뀐다)
- **시드**로 그물 실현을 바꾼다 (무지 종단·게이트 위치가 달라진다)
- **정답 보기**를 켜면 열쇠 범주와 단서 태그가 보인다 (디버그 전용)

| **LLM 0회** — 새 설계는 판정 경로에 LLM이 없다 | 연기 품질 (문안이 전부 고정) |

## 1회차에서 이미 잡은 것 — **설계 결함 하나**

⚠ **모든 노드는 그 부모의 대사 안에 자기 앵커를 갖고 있어야 한다.**

첫 실행에서 `d-toes`(발가락)를 **겨냥할 방법이 없었다.** 앵커는 이미 들은 대사에서만
나오는데, `a-footprint`의 대사에 `발가락`·`모양` 같은 자식 앵커가 하나도 없었기 때문이다.
**부모를 열어도 자식으로 갈 문이 안 생긴다.**

이것은 GDD **R3의 표면 훅 검증을 일반화해야 한다는 뜻**이다 — 지금 규칙은
*"인트로에 등장한 소재는 표면 노드여야 한다"* 인데, 실제로 필요한 것은:

> **모든 간선 `부모 → 자식`에 대해, 부모의 대사에 자식의 앵커가 최소 1개 등장해야 한다.**

빌드 게이트로 올릴 것. **프로토 없이는 못 찾았을 종류의 결함이다** — 문서상으로는
`anchors` 배열이 노드마다 있으니 문제없어 보인다.

### 같이 고친 버그 둘 (프로토 코드 쪽)

- 게이트 실패·무지 종단에서 `openNode()`를 부르는 바람에 **막혀야 할 슬롯이 확정으로
  기록**됐다. `better()`가 `확정`을 이기게 두면 안 된다
- 막힘 사유를 전역 하나로 들고 있어 **슬롯마다 다른 사유가 안 나왔다** → 슬롯별로 기록

## 검증한 것 (스크립트 조작, 2026-08-10)

관리 · 시드 7 · 열쇠 `절차`:

| 행동 | 기대 | 실측 |
| ---- | ---- | ---- |
| 미끼 앵커(`아이들`) 클릭 | 무비용, 자연스러운 회피 | ✅ 티켓 3 유지, *"그건 이 일과는 상관이 없습니다"* |
| `모양` 클릭 → `d-toes` | 티켓 −1, 대상 확정 | ✅ |
| `굴` 클릭 → `f-cave`(게이트) | 지렛대 모달, 가진 단서 전부 표시 | ✅ 후보 4개, 유효/무효 구별 없음 |
| 틀린 단서(`발자국`) | 거절 + 티켓 −1 + 재시도 가능 | ✅ |
| `가죽`(절차) 확보 후 재시도 | **문이 열린다** | ✅ 장소 `확실함` |
| 표면 진술 | 앵커 24개 > 미방문 노드 9개 | ✅ (R4 규약 만족) |

**핵심 루프가 문서대로 돌아간다** — *"다른 가지에서 캔 사실로 이 가지의 문을 연다."*

## 아직 모르는 것 — 사람이 만져야 안다

1. **가려내는 맛이 실제로 있는가.** 앵커 24개 중 유효 5개인데, 그게 *"고르는 재미"* 인지
   *"찍기"* 인지는 클릭해 봐야 안다. 헛클릭 비율 목표 10~25% (GDD Tuning)
2. **지렛대 모달이 *"아!"* 를 주는가.** 후보를 범주로 색칠하지 않기로 했는데(U2②)
   그것이 퍼즐인지 막막함인지
3. **티켓 3이 맞는가.** 프로토는 의뢰인 1명 기준 3칸이다. GDD의 하루 9칸 ÷ 3명
4. **기색(표정)이 보이는가.** 지금은 눈 픽셀 2개를 움직이는 수준이다
5. **주민은 게이트가 거의 안 생긴다** — Q9 실측대로다. 재미가 밋밋한지 확인할 것
