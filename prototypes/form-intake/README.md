# 프로토타입 4 — 의뢰서의 빈칸을 말로 채운다

> **상태**: 1회차 완료 (2026-08-10). **플레이테스트 대기**
> **대상 설계**: `design/gdd/intake-system.md` **재작성 v6**
> **선행**: `flow-intake/`(흐름+생성 선택지 — *"선택지 고르기 게임"* 판정),
> `anchor-intake/`(앵커 — *"취조 같다"*), `llm-intake-ab/`(자유 타이핑 — Portopia 위험)

## 왜 또 만들었나 — 이번엔 **컨셉**이 바뀌었다

앞의 셋은 입력 방식만 바꿨다. 전부 *"대화하다 보면 의뢰서가 채워진다"* 였고
의뢰서는 결과 표시판이었다. **v6은 뒤집는다 — 의뢰서가 먼저이고 대화가 수단이다.**

## 재는 것

1. **Q1 — 응대권 값이 맞는가.** 헤더에서 조절 (기본 3 = 하루 9 ÷ 의뢰인 3)
2. **Q3 — 한 칸에 몇 번까지 오갈 수 있어야 하는가.** 헤더의 「칸당 상한」 (0=무제한)
3. **티키타카로 느껴지는가** — 한 칸 안에서 여러 번 오가는 것이 대화인지 절차인지
4. **일깨우기가 *"아!"* 를 주는가** — 이번 설계의 새 기제

## 구조

```
의뢰서의 칸을 누른다  ← 이것이 곧 질문이다
      ↓
의뢰인이 답한다 — 셋 중 하나 (규칙 엔진이 판정)
  ├─ 말한다      → 칸이 채워진다
  ├─ 모른다      → [일깨운다] : 밖에서 온 이야기를 **건넨다**   (내용이 맞아야)
  └─ 얼버무린다  → [들이댄다] : 아는 이야기를 **꺼내 지목한다** (범주가 맞아야)
      ↓
언제나 [비워 두고 넘어간다] — 공짜. 막다른 길은 없다
```

**상황이 행동을 정하므로 보통 1~2개만 뜬다.** 그래서 *"셋 중 뭘 고르지"* 가 아니라
***"이 칸에 더 쓸까, 비워 두고 넘어갈까"*** 가 된다.

**행동은 고르고, 말은 생성된다.** 고르는 것이 문장이 아니라 **행동**이므로
*"선택지 고르기"* 가 아니고, 말이 실제로 나오므로 *"기능 버튼"* 도 아니다.

## 1회차에서 잡은 것

### ⚠ ① `render()`가 `busy` 중에 돌아 **모든 칸이 클릭 불가**였다 (코드)

`act()`가 `S.busy=true`로 두고 내부에서 `render()`를 불렀는데, 칸의 클릭 가능
조건에 `!S.busy`가 있었다. **행동 버튼은 멀쩡한데 의뢰서만 죽는** 형태라
버튼으로만 테스트했으면 못 잡았다.

> **규약**: `busy`를 내린 **다음에** 그린다. `finally { S.busy=false; render(); }`

### ⚠ ② 프롬프트 결함 둘 (프로토 3의 교훈이 또 필요했다)

- **건넨 이야기를 입에 안 올렸다** — 「일깨우기」인데 LLM이 다른 질문을 지어냈다.
  → *"「꺼낸 이야기」가 주어지면 `me`는 **반드시 그것을 자기 입으로 말한다**"* 를
  좋은 예와 함께 명시
- **모른다면서 새 사실을 지어냈다** — *"소리는 들었습니다"*.
  → *"「밝혀진 사실」이 없으면 **어떤 새 사실도 말하지 않는다**"* + 나쁜 예 추가

**"암시로는 안 막힌다"가 세 번째로 확인됐다.** 나쁜 예를 함께 줘야 막힌다.

## 검증한 것 (2026-08-10, 관리 · 시드 7 · `knows{대상0,규모2,장소2}` `tells{대상0,규모2,장소1}`)

| 경로 | 기대 | 실측 |
| ---- | ---- | ---- |
| 대상 묻기 (`knows=0`) | 「모른다」 → `본인도 모름` | ✅ 행동이 **[일깨운다]** 로 바뀜 |
| 일깨우기 — 틀린 재료(개울) | 응대권만 소모, 칸 불변 | ✅ |
| 일깨우기 — 맞는 재료(트롤 도감) | `knows` 상승 → **즉시 말한다** | ✅ *"제가 알기로 트롤은 발가락이 셋…"* → *"숲에서 커다란 발자국을 봤습니다."* |
| 일깨우기 목록 | **책만** (들은 것 제외) | ✅ 12개, 들은 것 0 (AC-R5-02) |
| 장소 묻기 (`tells=1`) | 어렴풋까지는 말한다 | ✅ |
| 장소 더 캐묻기 (`L=2 > tells`) | 「얼버무린다」 | ✅ *"그건... 별로 말씀드리기 어렵습니다."* |
| 들이대기 목록 | 들은 것 + 책 | ✅ 13개 |
| 들이대기 — 등기(절차) = 아픈 곳(절차) | **입이 열린다** | ✅ 장소 `확실` |

**두 기제가 정확히 반대 방향으로 작동한다** — 일깨우기는 내가 주고, 들이대기는
내가 지목한다. 그리고 **둘 다 "내가 아는 것"이 없으면 못 한다.**

## 2회차 (2026-08-10) — 플레이 판정 넷 반영

판정: ***"무슨 사람이든 똑같은 질문인데? 숲 어쩌고" · "수첩이 너무 난잡" ·
"모르겠다고 해놓고 갑자기 덩치가 크다고 대답" · "일단 자기 아는 건 털어놓고 시작해"***

### ★ 가장 큰 변경 — **아는 건 앉자마자 다 털어놓는다**

전에는 **상대가 순순히 말해 줄 것을 묻느라 응대권을 썼다.** 그건 잡일이다.
이제 착석 즉시 `min(knows, tells)`까지 스스로 말하고, **남은 빈칸은 전부 진짜
장애물**(무지 또는 은폐)이다.

```
앉자마자 아는 건 다 말한다            (무료)
      ↓
남은 빈칸 = 무지 or 은폐 — 어느 쪽인지는 아직 모른다
      ↓
칸을 짚어 묻는다 → 어느 쪽인지 드러난다   ← 판별. **무료로 바꿨다**
      ↓
무지면 일깨우고 / 은폐면 들이대고 / 비워 둔다   ← **여기만 응대권**
```

> **응대권이 전부 "뚫는 것"에 쓰인다.** 진단을 유료로 두면 3장으로 진단만 하다
> 끝난다 — 결정이 "어디를 뚫을까"에 모이도록 무료로 뒀다. **노브로 되돌릴 수 있다.**

실측 (주민·시드7, `knows{대상0,규모1,장소1}`):
- 첫 진술에서 규모·장소가 **어렴풋까지 저절로** 채워짐, 대상만 `?`
- 대상 진단 → `무지`, **응대권 3 유지** ✅
- 트롤 도감으로 일깨움 → 응대권 2, 대상 어렴풋 ✅

### ① 시나리오 3종 — 누가 와도 "숲 어쩌고"이던 것

`sc-forest`(주민·관리) · `sc-warehouse`(상인·갱단) · `sc-well`(귀족·관리·주민).
직업에 어울리는 사연을 시드로 고른다. 길드마스터북도 18항목으로 늘려 세 사연을 덮는다.

실측: 주민→숲 / 상인→창고 / 관리→우물 / 귀족→우물 / 갱단→창고

> **갱단이 특히 잘 나온다** — `knows` 전부 2인데 `tells`가 0,0,1이라 **장소 하나만
> 말하고 나머지는 전부 막힘**이고, `keyLeverage=없음`이라 뚫을 수도 없다.
> *"이 사람은 모르는 게 아니라 숨긴다"* 가 첫 진술만으로 드러난다.

### ② 누출 필터 — *"모르겠다"면서 없던 사실을 말하던 것*

프롬프트만으로는 안 막혔다. **아직 안 밝혀진 사실에만 나오는 낱말**을 뽑아 두고,
응답에 섞이면 **그 대사를 버리고 폴백으로 교체**한다.

> 이미 밝혀진 것·인트로·책에 나오는 낱말은 감시 대상에서 뺀다 (오탐 방지).
> `정답 보기`를 켜면 차단 횟수가 헤더에 뜬다.

### ③ 수첩 정리 — 「들은 것」과 길드마스터북 권별로

`들은 것 / 도감 / 지역 / 조직 / 시세` 다섯 묶음. **본격적인 길드마스터북 UI는
#26의 몫**이고 여기서는 난잡함만 걷어냈다.

## 아직 모르는 것 — 사람이 만져야 안다

1. **응대권 3이 맞는가** (Q1). 지금 조사 의뢰는 칸 3 × 2단 = **6번**이 완성인데
   3장이면 절반이다. 막힌 칸은 더 비싸므로 실제 완성률은 더 낮다
2. **칸당 상한이 필요한가** (Q3). 0(무제한)이 기본. 상한을 두면 *"이 칸은 포기"* 가
   명시적 결정이 된다
3. **한 칸 안의 오감이 대화인가 절차인가** — 이 프로토의 존재 이유
4. **일깨우기가 *"아!"* 를 주는가** — 12개 중 맞는 것을 고르는 맛
5. **비워 둔 칸이 무겁게 느껴지는가** — 도장을 찍으면 비운 칸 수가 나온다
6. **책 12항목이 적당한가** (Q2). 지금 각 칸마다 일깨울 재료가 3개씩 있다
