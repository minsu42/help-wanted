# Game Concept: Help Wanted

**Status:** Ship scope locked

**Updated:** 2026-08-10

## 한 줄 설명

몰락한 길드의 신임 길드마스터가 불완전한 정보를 바탕으로 의뢰를 협상하고 모험가를
파견한 뒤, 그 결과에 책임지는 싱글 플레이 경영 게임.

## 플레이어 경험

- 정보가 완전하지 않아도 결정을 내려야 한다.
- 의뢰 조건과 파티 구성이 실제 결과를 바꾼다.
- 성공·부상·죽음의 이유를 결과 화면에서 이해할 수 있다.
- 길드 홀에서 얻은 정보와 사람에 대한 기억이 다음 판단에 도움을 준다.

## 출시판 핵심 루프

1. **창구:** 의뢰인의 표정과 말을 읽고, 의뢰서의 칸을 짚어 질문하며 위험도를 판정한다.
2. **파견:** 의뢰에 보낼 모험가를 고른다.
3. **결과:** 성공·부상·죽음과 그 원인을 확인한다.
4. **길드 홀:** 소문을 듣고 필요하면 모험가를 영입한다.
5. **하루 종료:** 계약과 인물 상태가 갱신된다.
6. 마지막 날 뒤 결산을 보고 같은 빌드를 다시 시작할 수 있다.

## 반드시 구현되어야 하는 것

- 시드 기반 월드·의뢰·결과 생성
- 의뢰인 픽셀 초상과 기색 4종
- 의뢰서 7칸 질문, 수첩, 길드마스터북, 인내/응대 기록
- 위험도 등급 도장과 창구 협상
- 파티 편성, 파견 판정, 부상·사망 처리
- 결과 대조 화면
- 길드 홀 대화·소문·영입
- 자금·명성·길드 확장
- 일차 진행, 엔딩, 재시작
- 키보드와 마우스로 완주 가능한 반응형 UI

현재 `src/`의 완주 가능한 루프를 보존하되, 창구는 위 청취·판정 화면으로 교체한다.
위 목록에 없는 새 시스템은 제출판의 필수 조건이 아니다.

## 아트 확정

- 방향: **전체 2D 픽셀 창구 디오라마 + 책상 위 양피지 의뢰서**.
- 팔레트와 붉은색 사용 규칙은 `design/art/art-bible.md`의 기존 규칙을 따른다.
- 의뢰인은 64×64 네이티브 픽셀 초상과 표정 4종을 사용한다.
- 수첩·책·도장·잉크·창틀·책상은 모두 클릭 반응을 가진 픽셀 오브젝트다.
- 의뢰서는 픽셀 양피지 오브젝트로 그리되 한글은 선명한 DOM 텍스트를 사용한다.
- 기존 길드 홀과 전신 스프라이트는 유지하며 새 초상과 인물 정체성을 맞춘다.
- 장식보다 정보 계층과 클릭 가능 여부가 먼저 읽혀야 한다.

## 제출 후로 미루는 것

- LLM 연기와 프록시
- 세이브/로드
- 세력 평판, 가치관·관계 확장, 세계 변화, 3막 서사
- 핵심 캐스트 밖의 추가 캐릭터와 추가 에셋 팩
- BGM·SFX
- 수치 전면 재설계

관련 상세 GDD·ADR·P1 스토리는 아이디어와 연구 기록으로 보존하지만 제출판 요구사항으로
취급하지 않는다.

## 밸런스 원칙

밸런스는 기능과 아트가 잠긴 뒤 마지막에 한 번만 조정한다. 진행 불가, 무조건 정답,
즉시 파산처럼 완주를 막는 값만 그 전에 수정한다. 모든 값은 `src/data/balance.json`에서
조정하며 새 공식을 만들지 않는다.

## 출시 완료 기준

- `npm run check` 통과
- 새 게임부터 엔딩·재시작까지 브라우저에서 한 회차 완주
- 주요 화면에 막힌 버튼, 잘린 핵심 문구, 진행 불가능 상태가 없음
- 배포 URL에서 새로고침 후 정상 시작
