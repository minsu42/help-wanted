# Game Concept: Help Wanted

*한국어 병기: **Help Wanted / 사람을 구합니다***

*Created: 2026-08-08*
*Status: Approved*

## 제목에 대하여

`Help Wanted`는 구인 게시물의 표준 문구이며, 이 게임의 무대인 **게시판에 실제로 붙어
있을 말**이다. 이중의미가 게임 구조와 정확히 맞물린다 — **의뢰인은 도움(`help`)을
구하러 오고, 길드마스터는 그 도움으로 보낼 사람(옛 표현으로 `the help` = 일꾼)을
구한다.** 두 방향의 구인이 창구에서 만나는 것이 이 게임이다.

현대 간판 문구를 중세 길드에 붙이는 아이러니는 의도적이다 — 사람 목숨을 조건과 수당으로
환산하는 직업의 도덕적 무게를 제목이 미리 말한다.

*이전 가제: 「길드 접수창구」. 이 표현은 문서 내에서 무대(창구)를 지칭할 때 계속 쓴다.*

---

## Elevator Pitch

> 당신은 다 망한 용병 길드를 물려받은 신임 길드마스터다. 접수를 볼 사람이 없어
> 직접 창구에 앉는다. 의뢰인은 늘 뭔가를 숨기고, 당신은 이 도시의 누구도 모른다.
> 길드원들에게서 주워들은 소문으로 조건을 흥정하고, 누구를 보낼지 결정하라 —
> 잘못 보내면 사람이 죽는다.

**10초 테스트**: "창구에 앉아 의뢰를 흥정하고 사람을 파견하는 게임. 정보를 많이
알수록 유리하고, 사람을 잘못 보내면 죽는다." — 통과.

## Core Fantasy

**창구 하나에 앉아 세상 전체를 상대하는 존재.**

플레이어는 검을 들지 않고, 현장에 가지 않으며, 마법을 쓰지 않는다. 그가 가진 것은
책상, 장부, 그리고 사람들에게서 들은 이야기뿐이다. 그런데도 이 도시에서 누가 부자가
되고 누가 죽는지를 결정하는 것은 그다.

이 판타지가 다른 곳에서 충족되지 않는 이유: 대부분의 게임은 플레이어를 **행위자**로
만든다. 여기서 플레이어는 **중개자**다. 힘이 아니라 **정보의 비대칭성**이 권력의
원천이며, 그 권력을 행사한 대가는 항상 남이 치른다. 그 불편함이 이 게임의 감정이다.

### 주인공 설정: 신임 길드마스터

플레이어는 전임자가 사라진 뒤 **갓 자리를 물려받은 길드마스터**다. 이 설정은 미학적
선택이 아니라 **세 개의 설계 문제를 동시에 해결하는 구조적 장치**다.

| 설계 문제 | 이 설정이 해결하는 방식 |
| ---- | ---- |
| 왜 창구를 떠나지 않는가? (기둥 2) | **길드가 너무 작아 접수를 볼 사람이 나밖에 없다.** 창구가 곧 마스터의 자리다 |
| 왜 정보 약자인가? (기둥 1) | **부임한 지 얼마 안 됐다.** 베테랑 길드원들은 도시 전체와 아는 사이인데, 나는 아무도 모른다 |
| 왜 흥정·파견·영입 권한이 있는가? | 길드마스터니까. 게임의 핵심 동사가 직업 설정과 어긋나지 않는다 |

핵심은 정보 약자인 이유가 "지위가 낮아서"(우연)가 아니라 **"이 관계망이 아직 내 것이
아니어서"**(구조적)라는 점이다. 따라서 게임의 진행은 곧 **인맥을 물려받는 것이 아니라
직접 쌓아 올리는 과정**이며, 이것이 유로파4식 성장 감각을 텍스트 매체로 옮기는 가장
정확한 번역이다.

**검토했으나 기각한 대안 — 접수원(말단 직원)**: 기둥 2의 정당화는 더 자연스럽지만,
말단 직원이 계약 조건을 흥정하고 파견 인원을 결정하는 것은 권한상 어색하며(핵심 동사
두 개가 설정과 충돌), "내 길드가 커진다"는 성장 뽕이 "회사가 커진다"로 희석되어
타깃 플레이어의 최애 감각(유로파4)을 잃는다.

## Unique Hook

**「Papers, Please」의 창구 심문과 「Yes, Your Grace」의 청원 처리인데, AND ALSO
창구 반대편의 사람들이 자기 목표를 가진 자율 에이전트라서 매번 다른 거짓을 말하고,
내가 파견한 모험가가 살아 돌아와 다음 소문의 출처가 된다.**

무대가 사람이 아니라 **장소**(창구와 게시판)라는 점은 의도적이다. "길드마스터인데
접수창구에 앉아 있다"는 아이러니가 컨셉 전체를 한 줄로 설명한다.

### 왜 이것이 기믹이 아닌가

핵심 원리 하나로 훅과 메카닉이 연결된다: **정보 = 흥정력.**

| 알아낸 정보 | 창구에서 쓸 수 있는 흥정 카드 |
| ---- | ---- |
| "이 의뢰, 다른 길드 두 곳에서 거절당했다" | 보상 2배 요구 가능 |
| "그 숲에 실제로는 트롤이 있다" | 위험 수당 요구 — 또는 숨기고 싼 인력 투입 |
| "의뢰인이 사실 파산 직전이다" | 선불 요구 (안 하면 못 받는다) |
| "이 의뢰인은 라이벌 길드와 원수다" | 독점 계약으로 장기 고객 확보 |

정보 없이 흥정하는 것은 **눈 가리고 도박**이다. 따라서 플레이어는 강제되지 않고도
자발적으로 사람들과 대화하게 된다 — 네트워킹이 장식이 아니라 **경제적 필요**다.

### 「Yes, Your Grace」와의 결정적 차이

그 게임의 청원자들은 **대본**이었다. 두 번째 플레이에서 같은 사람이 같은 말을 한다.
이 게임의 인물들은 시뮬레이션이며, 그래서 두 번째 플레이에는 존재하지도 않는다.

## Player Experience Analysis (MDA Framework)

### Target Aesthetics (What the player FEELS)

| Aesthetic | Priority | How We Deliver It |
| ---- | ---- | ---- |
| **Discovery** (탐색, 비밀) | **1** | 매 의뢰의 숨은 진실, 소문 네트워크, 인물 관계의 발굴 |
| **Narrative** (드라마, 서사) | **2** | 창발 서사 — 내가 3번 살려 보낸 모험가가 이번엔 안 돌아온다 |
| **Challenge** (숙달) | **3** | 정보 불충분 상태에서의 흥정 판단. 스탯이 아니라 플레이어의 안목이 성장 |
| **Fantasy** (역할 몰입) | 4 | 창구에 직접 앉아야 하는 신임 길드마스터라는 구체적이고 낯선 위치 |
| **Sensation** (감각적 즐거움) | 5 | 양피지·봉랍의 촉각적 UI, 도장 찍는 순간의 확정감 |
| **Expression** (자기표현) | 6 | 정직한 중개인이 될지 착취자가 될지는 플레이어의 선택 |
| **Fellowship** (사회적 연결) | N/A | 싱글플레이. 안티 기둥 4로 명시적 배제 |
| **Submission** (휴식) | N/A | 이 게임은 압박이 핵심이다. 편안함을 목표로 하지 않는다 |

### Key Dynamics (우리가 창발시키고 싶은 행동)

1. **플레이어가 의뢰를 받기 전에 길드 홀을 한 바퀴 돈다** — 강제하지 않아도, 정보가
   돈이기 때문에 자연히 그렇게 된다.
2. **플레이어가 특정 모험가를 아끼기 시작한다** — 그가 정보원이자 전력이기 때문에.
   그리고 아끼는 순간, 위험한 의뢰 앞에서 진짜 딜레마가 생긴다.
3. **플레이어가 의뢰인에게 위험을 고지하지 않는 선택을 저지른다** — 그리고 그것이
   기억에 남는다. 게임이 비난하지 않기 때문에 더 오래 남는다.
4. **플레이어가 자기만의 판단 규칙을 만든다** — "안색이 나쁜 의뢰인은 선불 받자" 같은
   개인적 격언. 이것이 이 게임의 진짜 진행 시스템이다.

### Core Mechanics (실제로 구현하는 시스템)

1. **흥정 시스템** — 3개 축(보상 / 선불 / 위험 고지)을 조정해 계약을 타결.
   각 축은 의뢰인의 숨은 상태(자금력, 급박함, 대안 유무)에 따라 수용 범위가 다름.
   소요 일수는 협상 대상이 아니라 의뢰의 고정 속성이다 (2026-08-08 개정 — 아래
   Open Questions 1번 참조).
2. **숨은 진실 시스템** — 모든 의뢰가 `공개 정보`와 `실제 정보`를 별도로 가짐.
   실제 위험도, 실제 보상 여력, 실제 동기가 숨겨져 있다.
3. **소문 네트워크** — 길드원 에이전트가 각자 인맥을 가지며, 대화하면 자기 인맥
   범위 안의 숨은 정보를 (자기 성격 필터를 거쳐) 흘린다.
4. **파견 판정** — 실제 위험도 vs 파티 역량 → 성공 / 부상 / 사망. 결과가 명성·자금·
   관계망에 반영된다.
5. **에이전트 시뮬레이션** — 모험가와 의뢰인이 목표·성격·인맥·기억을 가지며, 플레이어의
   과거 결정을 기억한다.

## Player Motivation Profile

### Primary Psychological Needs Served

| Need | How This Game Satisfies It | Strength |
| ---- | ---- | ---- |
| **Autonomy** (자유, 의미 있는 선택) | 정직할지 속일지, 누구를 위험에 보낼지 전부 플레이어 선택. **정답이 없고 게임이 도덕적 판정을 내리지 않는다** | **Core** |
| **Competence** (숙달, 실력 성장) | 성장하는 것이 캐릭터 스탯이 아니라 **플레이어 자신의 안목**. 초반엔 흥정에서 지고, 후반엔 상대의 패를 읽는다. 정보망의 확장이 실력의 시각화 | **Core** |
| **Relatedness** (연결, 소속) | 길드원이 이름·사연·인맥을 가지며 내 결정으로 살거나 죽는다. 직접 볼 수 없기에 오히려 상상이 개입한다 | **Core** |

세 욕구 모두 Core인 것은 의도적이다. 이 장르(Papers Please 계열)의 강점이 정확히
이 삼중 충족이며, 그것이 그래픽 예산 없이도 강한 감정을 만드는 이유다.

### Player Type Appeal (Bartle Taxonomy)

- [x] **Explorers** (발견, 시스템 이해, 비밀 찾기) — **주요 대상.** 숨은 진실을
      파헤치고, 소문 네트워크의 구조를 이해하고, 에이전트 시뮬레이션의 규칙을
      역설계하는 것이 게임의 본체.
- [x] **Achievers** (목표 달성, 진행) — **부차적.** 명성 점수, 길드 등급, 생존
      기록이 성취 축을 제공. 단 체크리스트형 성취자는 배제 대상(아래 참조).
- [ ] **Socializers** — 대상 아님. 싱글플레이이며, 게임 내 인물과의 관계는 도구적이다.
- [ ] **Killers/Competitors** — 대상 아님. 라이벌 길드(Tier 2)가 도입되면 부분적으로
      충족되나, MVP에는 없다.

**명시적으로 이 게임이 맞지 않는 사람**:
- 직접 싸우고 싶은 플레이어 (안티 기둥 1이 배제)
- 반응속도·액션을 원하는 층
- **체크리스트형 성취자** — "다음에 뭘 해야 하는지" 명확히 알려주는 게임을 원하는 사람.
  이 게임은 애매함이 재미다.
- 실패를 되돌리고 싶은 플레이어 (기둥 5가 배제)

### Flow State Design

- **온보딩 커브**: 첫 3일(게임 내)은 **저위험 의뢰만** 등장하며, 숨은 진실의 격차도
  작다. 흥정 UI가 순차적으로 열린다 — Day 1엔 보상만, Day 2엔 선불, Day 3엔
  위험 고지. 첫 의뢰는 길드원이 먼저 소문을 물어다 준다(정보=흥정력을 강제 학습).
- **난이도 스케일링**: 플레이어 실력이 아니라 **명성**으로 스케일링한다. 명성이
  오르면 더 큰 의뢰가 오고, 큰 의뢰는 숨은 진실의 격차가 크다. 즉 성공이 곧 위험 상승.
- **피드백 명료성**: 매 파견 결과 화면에 **"당신이 알았던 것 vs 실제였던 것"** 대조를
  보여준다. 플레이어는 자기 판단이 왜 틀렸는지 정확히 알게 된다. 이것이 실력 성장의
  유일한 피드백 채널이며, 반드시 명료해야 한다.
- **실패로부터의 회복**: 리트라이 없음(기둥 5). 단 실패가 **영구적 정보**가 된다 —
  "그 의뢰인은 다시는 믿지 않는다"가 장부에 남는다. 실패는 처벌이 아니라 학습 자원.

## Core Loop

### Moment-to-Moment (30초) — 창구

```
의뢰인 착석 → 조건 제시 → [내가 아는 것]으로 흥정 → 타결 / 결렬 → 모험가 배정
```

플레이어가 물리적으로 하는 일: **읽고, 대조하고, 조건 축을 조정하고, 도장을 찍는다.**

**만족감의 출처**: "내가 아는 것을 상대는 내가 안다는 걸 모른다"는 정보 우위감.
하스스톤에서 상대 패를 읽었을 때와 같은 종류의 쾌감이며, 전투 없이 성립한다.

### Short-Term (5~15분) — 길드 홀 순회

```
창구 마감 → 길드원들과 잡담 → 소문 획득 → 소문이 다음 의뢰의 흥정 카드가 됨
```

**"한 번 더" 심리**: 방금 들은 소문을 써먹고 싶어서 다음 의뢰인을 부른다. 정보에는
유통기한이 있어서(해당 의뢰가 다른 길드로 넘어가면 소멸) 즉시 쓰고 싶어진다.

### Session-Level (20~40분) — 15일 근무

```
의뢰 수주 → 파견 → 귀환(또는 사망) → 명성·자금·관계망 갱신 → 다음 날
```

**핵심 긴장**: 모험가가 죽으면 **사람만 잃는 게 아니라 정보원을 잃는다.** 5년 근속
베테랑은 도시 전체와 아는 사이라 소문의 절반이 그를 통해 온다. 그를 위험한 의뢰에
보내는 것은 정보망 자체를 도박에 거는 행위다.

→ **이 게임에서 죽음은 감정적으로도, 기계적으로도 아프다.** 이 이중 손실이 설계의
핵심 성과이며, 절대 완화하지 않는다.

**세션 종료**: 15일차에 최종 명성 점수 + 길드의 운명 텍스트. 자연스러운 정지점.

### Long-Term Progression

성장하는 것은 캐릭터가 아니라 **관계망**이다.

```
소문 → 정보망 확장 → 더 좋은 조건 → 더 강한 모험가 영입 → 더 큰 의뢰 → 명성
```

유로파4의 성장 뽕이 여기 들어온다. 단 커지는 것은 지도가 아니라 인맥이다. 게임
후반에는 왕궁·교회·상단 대표가 직접 창구에 앉는다 — 이것이 "국경이 넓어지는" 감각의
텍스트 버전이다.

**위상 변화의 표현 방식**: 초반에는 플레이어가 길드 홀을 돌며 소문을 캐야 한다.
후반에는 **사람들이 플레이어에게 정보를 가져온다.** 같은 책상, 달라진 위상 —
기둥 2를 깨지 않고 성장을 보여주는 유일한 방법이며, 신임 길드마스터 설정이 이것을
가능하게 한다.

**게임이 "끝나는" 지점**: MVP는 15일 고정. 풀 비전은 길드 등급 최상위 도달 또는
파산/명성 붕괴.

### Retention Hooks

- **Curiosity**: 이번 회차에는 어떤 인물들이 생성될까. 저 의뢰인이 숨긴 것은 무엇이었나
  (결렬하면 영원히 모른다).
- **Investment**: 아끼는 모험가를 계속 살려두고 싶다. 쌓아온 인맥을 잃고 싶지 않다.
- **Social**: 해당 없음 (싱글플레이).
- **Mastery**: 다음엔 저 함정을 알아채겠다. 흥정에서 더 뜯어내겠다.

## Game Pillars

### Pillar 1: 아는 자가 이긴다

플레이어의 실력은 전투력이나 자금이 아니라 **정보량과 안목**이다.

*Design test*: 어떤 기능이 "더 센 것"을 주는가 "더 아는 것"을 주는가로 고민되면
→ **아는 것**을 택한다.

### Pillar 2: 창구를 떠나지 않는다

플레이어는 결코 현장에 가지 않는다. 세상은 오직 **사람의 입과 종이**를 통해서만
도착한다.

*Design test*: 어떤 사건을 직접 보여줄까 전해 들려줄까 고민되면 → **전해 듣는다.**

### Pillar 3: 모든 이름에는 사람이 있다

길드원과 의뢰인은 스탯 덩어리가 아니라 목표·관계·기억을 가진 자율 에이전트다.

*Design test*: 익명 다수를 늘릴까 기억되는 소수를 깊게 할까 고민되면
→ **소수를 깊게.**

### Pillar 4: 작가는 세계를 쓰고, 시뮬레이션은 사람을 쓴다

큰 사건은 대본으로 쓴다. 그 속에서 누가 죽고 누가 출세하는지는 쓰지 않는다.

*Design test*: 감동적인 장면이 떠오르면 → **특정 인물이 살아있어야 성립하는 장면은
쓰지 않는다.**

### Pillar 5: 결정은 되돌아오지 않는다

리트라이도 세이브 스캐밍도 없다. 실패는 안고 가고, 대신 **다음 판단의 정보**가 된다.

*Design test*: 실패에 재시도를 줄까 고민되면 → **주지 않는다.** 실패가 정보가 되게
만든다.

### 기둥 간 긴장 (기둥이 일을 하고 있다는 증거)

- **1 ↔ 5**: 정보를 얻으려면 실험해야 하는데, 실험의 대가는 영구적이다.
  → *"알아보려면 사람을 걸어야 한다"*
- **2 ↔ 3**: 인물에게 애착을 갖게 만들어야 하는데, 플레이어는 그들을 **직접 볼 수
  없다**. → 대화와 보고서의 텍스트 품질이 게임의 생사를 결정한다.
- **3 ↔ 4**: 작가는 통제를 원하고, 창발은 통제를 거부한다. → 척추/살 경계선을 계속
  지켜야 한다.

### Anti-Pillars (What This Game Is NOT)

- **NOT 조작 가능한 전투**: 기둥 2를 정면으로 훼손하고 규모를 몇 배로 늘린다. 전투는
  **결과와 보고**로만 존재한다.
- **NOT 필드 탐험 / 맵 이동**: 기둥 2 훼손 + 3일 규모 즉시 파괴.
- **NOT 정답이 있는 적발 퍼즐**: 기둥 1 훼손. Papers Please식 "규칙 위반 찾기"는
  결국 **반복**이 되며, 그것은 타깃 플레이어가 RPG를 피하는 바로 그 이유다.
  이 게임은 정답이 아니라 **판단**을 요구한다.
- **NOT 멀티플레이어**: 첫 게임 + 3일 규모에서 거의 확실한 실패 요인. 경쟁 욕구는
  **AI 라이벌 길드**(Tier 2)로 번역한다.
- **NOT 무한 충원 가능한 소모품 모험가**: 기둥 3 훼손. 사람이 싸면 죽음이 아프지
  않고, 죽음이 아프지 않으면 이 게임에는 남는 것이 없다.

## Visual Identity Anchor

*(AD-CONCEPT-VISUAL 게이트는 lean 리뷰 모드로 스킵됨 — 이 섹션은 브레인스토밍 중
합의된 방향이며, 아트 바이블의 씨앗이다.)*

### 선택된 방향: **「양피지와 봉랍」**

**한 줄 규칙**: **모든 정보는 종이 위에 있다.**

### 지지 원칙

1. **책상이 화면이다** — 배경은 나무 책상결, 모든 정보는 그 위에 놓인 양피지 카드로
   제시된다. UI 패널이 아니라 물건이다.
   *설계 테스트*: 새 UI 요소가 "종이에 쓸 수 있는 것"인가? 아니면 넣지 않는다.

2. **강조색은 하나뿐이다** — 세피아 단색조 + **붉은 봉랍색** 하나. 붉은색은 위험,
   사망, 결렬에만 쓴다.
   *설계 테스트*: 이 요소가 붉어야 할 만큼 치명적인가? 아니면 세피아다.

3. **얼굴을 그리지 않는다** — 캐릭터 일러스트 없음. 인물은 **이름, 필체, 그가 남긴
   기록**으로만 존재한다.
   *설계 테스트*: 이 인물을 보여줄까 서술할까 → 서술한다.

### 색 철학

바래진 양피지의 크림색·갈색·검은 잉크로 이루어진 좁은 팔레트. 채도는 전체적으로
낮다. 그 위에서 봉랍의 붉은색만이 유일하게 채도를 가지며, 따라서 화면에 붉은 것이
나타나는 순간 플레이어의 심장이 뛴다.

### 왜 이 방향인가

**3일이라는 제약을 미학으로 전환한다.** 캐릭터 아트를 만들 시간이 없다는 결핍이,
"플레이어는 창구를 떠나지 않으므로 얼굴을 볼 수 없다"는 컨셉적 강점이 된다.
기둥 2와 완전히 일치하며, CSS와 웹폰트만으로 구현 가능하다.

## Risks and Open Questions

### Design Risks

- **창발이 무작위처럼 느껴질 위험** — 가장 치명적인 설계 리스크. 플레이어가 "내 판단이
  결과를 바꿨다"고 느끼지 못하면 게임 전체가 무너진다.
  → 완화: 매 결과 화면에 **"알았던 것 vs 실제였던 것"** 대조를 반드시 표시. 인과를
  명시적으로 보여준다.
- **정보=흥정력 루프가 학습되지 않을 위험** — 플레이어가 네트워킹을 건너뛰고 도박하듯
  흥정하면 게임의 절반이 사장된다.
  → 완화: Day 1 첫 의뢰에서 길드원이 먼저 소문을 물어다 주어 우위감을 강제 체험시킨다.
- **텍스트가 지루할 위험** — 기둥 2 때문에 모든 것이 텍스트다. 텍스트가 지루하면 게임이
  지루하다. 대체 채널이 없다.
- **20~40분을 버틸 만큼의 다양성이 없을 위험** — 의뢰 템플릿이 12종이면 15일차에는
  반복이 보인다. → 완화: 반복되는 것이 **의뢰**가 아니라 **사람 조합**이 되도록 설계.

### Technical Risks

- **에이전트 시뮬레이션 튜닝에 3일이 부족함** — 창발 시스템은 원래 튜닝 집약적이다.
  → 완화: 에이전트를 최소 스펙으로. 목표 1개 + 성격 태그 2개 + 인맥 1~2개. 그 이상은
  Tier 2.
- **소문 전파 그래프의 복잡도 폭발** — 3자 전파, 시간 감쇠, 왜곡 누적을 다 넣으면
  디버깅 불가능해진다. → 완화: MVP는 **1홉 전파만** (내 길드원 → 나). 3자 전파는 Tier 2.
- **웹 개발 경험 부족** — 첫 게임이며 프레임워크 학습 곡선이 3일 중 하루를 먹을 수 있다.
  → 완화: **프레임워크를 쓰지 않는다.** Vite + TypeScript + 직접 DOM 조작.

### Market Risks

*(예선 제출작이므로 상업적 리스크는 해당사항 적음. 심사 관점으로 대체 기술.)*

- **심사위원이 로딩을 기다리지 않는다** → 웹 네이티브 선택으로 이미 완화됨.
- **심사위원이 5분 안에 재미를 못 느낀다** — 예선에서 가장 현실적인 실패 경로.
  → 완화: **첫 3분 안에 흥정 1회 + 파견 1회 + 결과 1회**가 완결되도록 온보딩을 압축.
- **텍스트 게임이 시각적 임팩트로 승부하는 경쟁작에 밀린다** → 「양피지와 봉랍」의
  강한 시각 통일성이 부분 완화. 스크린샷 한 장이 컨셉을 설명하도록.

### Scope Risks

- **대화 콘텐츠 작성량 폭발 — 3일 프로젝트 1순위 킬러.**
  → 완화: **산문 대화를 쓰지 않는다.** 흥정은 슬라이더/버튼 UI로, 텍스트는
  `{이름}은 {감정}하며 {행동}했다` 식 템플릿 조립으로. 창발이 문장을 쓴다.
- **밸런싱 시간 부재** → `balance.json` 단일 파일 격리 (위 참조).
- **Day 3에 첫 배포를 시도하는 재앙** → **Day 3 오전에 반드시 선행 배포**하여 GitHub
  Pages 경로·에셋 상대경로 문제를 미리 터뜨린다.
- **재미 검증 없이 3일이 흐를 위험** → **Day 1 종료 시점에 반드시 플레이 가능한 빌드**.
  재미없다면 그 시점에 알아야 한다.

## MVP Definition

**Core hypothesis**: *"플레이어는 소문으로 얻은 정보를 흥정에 써먹는 것을 즐기며,
모험가의 죽음을 자기 판단의 결과로 받아들인다."*

이 하나만 검증되면 게임은 성립한다. 나머지는 전부 확장이다.

### Required for MVP (3일, Tier 0)

| 시스템 | 3일 버전 |
| ---- | ---- |
| **창구 흥정** | 3개 축(보상 / 선불 / 위험 고지) 조정 + 수락·결렬 |
| **숨은 진실** | 의뢰마다 `공개 위험도`와 `실제 위험도`가 다름 |
| **소문 네트워킹** | 길드원과 대화 → 다음 의뢰의 실제 정보 일부 공개 (1홉 전파만) |
| **모험가** | 8~12명, 능력치 + 성격 태그 + 인맥 1~2개 |
| **파견 판정** | 실제 위험도 vs 파티 역량 → 성공 / 부상 / 사망 |
| **결과 대조 화면** | "당신이 알았던 것 vs 실제였던 것" — 학습 피드백의 유일 채널 |
| **진행** | 15일 근무 → 최종 명성 점수 + 엔딩 텍스트 |
| **배포** | GitHub Pages 정적 배포 동작 확인 |

**살아남아야 하는 감정**: *"이 숲이 위험하다는 걸 알고도 보상이 좋아서 신입을 보냈다.
안 돌아왔다."* — 이 한 문장이 플레이어 입에서 나오면 MVP는 성공이다.

### Explicitly NOT in MVP

- 자유 대화 / 분기 대화 트리 (템플릿 조립으로 대체)
- 관계망 시각화 그래프
- 소문 3자 전파, 시간 감쇠, 왜곡 누적
- 모험가 성장 / 스킬트리 / 장비
- 전투 시뮬레이션 로그
- 작가가 쓴 챕터 스토리라인
- 라이벌 AI 길드
- 오디오 (Tier 1로 이월)
- 길드 장부 / 과거 기록 조회 (정보 수단 확장)

### Scope Tiers

| Tier | Content | Features | Timeline |
| ---- | ---- | ---- | ---- |
| **Tier 0 — MVP (제출본)** | 의뢰 템플릿 12~15종, 모험가 8~12명, 15일 1회차 | 위 MVP 표 전부 | **3일** |
| **Tier 1 — 여유분** | 엔딩 3종 | 관계망 시각화, 사운드, 소문 3자 전파 | +3~5일 |
| **Tier 2 — 예선 통과 후** | 챕터 배경 사건, 라이벌 길드 3곳 | 작가 스토리라인 척추, AI 라이벌 길드, 길드 장부/과거 기록 조회 | +3~6주 |
| **Full Vision** | 다중 도시, 길드 등급 시스템 | 위 전부 + 장기 캠페인 | 2~4개월 (솔로) |

### 3일 실행 계획

- **Day 1** — 데이터 구조 + 창구 화면 + 흥정 + 파견 판정.
  **하루 끝에 "의뢰 받고 사람 보내서 결과 보기"가 반드시 돌아가야 한다.**
- **Day 2** — 소문 네트워킹 (차별점이므로 하루를 온전히 투입) + 사망 처리 +
  명성/자금 순환 + 결과 대조 화면.
- **Day 3** — 오전: `balance.json` 밸런싱 + **선행 배포**. 오후: 시각 정리
  (「양피지와 봉랍」) + 엔딩 + 최종 배포.
