## Overview

**의뢰서는 플레이어의 판단이 문서가 되어 남의 손에 들어가는 곳이다.**

청취(#21)가 알아낸 것을 좁혀 주면, 의뢰서는 그것을 **자동으로 정리해 보여 준다.**
플레이어가 손으로 하는 일은 하나뿐이다 — **이 일이 얼마나 위험한지 등급을 매기는 것.**

| | **자동 기록** | **판단** |
| ---- | ---- | ---- |
| 무엇 | 종류 · 대상 · 규모 · 장소 · 기한 · 경로 · 특징 및 약점 (**7항목**) | **위험도 등급 D/C/B/A/S 하나** |
| 누가 | **청취가 실시간으로** | **플레이어가 직접** |
| 고칠 수 있나 | **아니오** | 예 (도장 전까지 언제든) |

그리고 **모험가는 의뢰서를 읽고 스스로 준비하고 출발한다.** 길드마스터는 전술을
지정하지 않는다 — **적힌 사실이 준비를 만들고, 적힌 등급이 누가 오는지를 만든다.**
이 두 줄이 기둥 6의 전부이며, 이 시스템이 존재하는 유일한 이유다.

### 이 시스템이 없으면

청취가 알아낸 것이 **자동으로** 파견 판정에 반영된다. 그러면 결과가 나빠도 시스템 탓이고,
*"내가 C급이라고 적었다"* 가 나오지 않는다 — Core hypothesis가 검증할 문장이 사라진다.

### 세 개의 등급이 서로 다른 시점에 존재한다

**이것이 이 시스템의 골격이다.**

| | 등급 | 언제 보이나 | 틀릴 수 있나 |
| ---- | ---- | ---- | ---- |
| ① **의뢰인의 주장** | 의뢰인이 말한 위험도 | **처음부터 항상 표시** | **예** — 무지 또는 은폐 |
| ② **플레이어의 판정** | 의뢰서에 내가 적은 등급 | 내가 적는 즉시 | **예. 그것이 핵심이다** |
| ③ **실제 위험** | 진실 측 위협도 `T` | **파견 후에만** | — (정의상 참) |

> 예: 주장 **C** / 판정 **A** / 실제 **A** — 플레이어가 의뢰인의 축소를 뚫어낸 판이다.
> 반대로 주장 C / 판정 C / 실제 A면 정예가 필요한 자리에 신입 둘이 간다.

### 경계 — 무엇이 이 문서의 것이 아닌가

| | 소유 |
| ---- | ---- |
| 칸 상태 전이·`completeness` 계산 | **청취 (#21)** — 의뢰서는 **읽기만** 한다 |
| **게시 보수** | **`assignment-dispatch.md` R3** — 게시 보수는 의뢰서의 칸이 아니라 **게시 단계에서 정한다** |
| 적힌 등급이 누가 지원하는지를 어떻게 바꾸는가 | **`assignment-dispatch.md` F4** (지원 판정) |
| `P + C − T`의 구간과 결과 서술 | **`assignment-dispatch.md` F3** |
| 3단 대조 화면(알았던 것/적은 것/실제) | **결과 대조 (#11, P2)** |
| 흥정에서 근거로 쓰이는 방식 | **계약 협상 (#9, P3)** |
| 자유 메모(개인 수첩)의 표현 | **UI (#14)** — **판정에 닿지 않으므로 이 문서의 규칙이 아니다** |

**이 문서가 소유하는 것은 「칸의 정의」와 「등급 기준」과 「대비 C의 산정」 셋이다.**

## Player Fantasy

**목표 감정은 「서명의 무게」다.** 청취가 *"내가 물어서 알아냈다"*(유능감)라면,
의뢰서는 ***"내가 이렇게 판단한다"***(책임)이다. 둘은 같은 창구 화면에서 연속으로
일어나고, 도장 하나로 끊긴다.

정점은 **등급을 고르는 3초**다. 화면에는 내가 알아낸 것 전부와 알아내지 못한 빈칸이
같이 놓여 있고, 의뢰인은 C라고 주장했고, 나는 A라고 적으려 한다. 그 순간 플레이어는
**자기가 모르는 것의 양을 세고 있다** — 이 게임에서 가장 어른스러운 계산이다.

### 안티 감정: 서식 노동 — 그리고 이번 설계가 그것을 막는 방식

`systems-index.md`의 **1순위 리스크가 정확히 이것이다.** 방어는 수사가 아니라 구조다.

| 서식 노동이 생기는 조건 | 이 설계의 방어 |
| ---- | ---- |
| 이미 아는 것을 다시 옮겨 적게 한다 | **받아쓰기가 100% 자동.** 옮겨 적는 동작이 존재하지 않는다 |
| 결정이 아닌 항목을 여러 개 고르게 한다 | **입력이 등급 하나뿐.** 화면의 텍스트 입력 요소는 **0개** |
| 최적해가 있는 칸을 만든다 | 등급은 **추천되지 않는다.** 맞히는 것이 아니라 **판단하는 것** |
| 매 의뢰마다 같은 손동작을 반복시킨다 | 손동작이 **클릭 두 번**(등급 → 도장)이라 반복이 마모를 만들 분량이 없다 |

> **받아쓰기가 자동이고 입력이 등급 하나뿐인 것이 정확히 그 방어다.** 의뢰서를 짧게
> 만든 것은 절약이 아니라 **감정 설계**다 — 화면에 결정이 하나뿐이어야 그 하나가
> 무겁다.

### 그 대가: 무능의 자각

빈칸은 의뢰서에 **계속 보인다.** `미확인`이라고 적힌 채로 도장을 찍는 것을 막지
않는다 (기둥 5). 회수는 여기가 아니라 **결과 대조(P2)** 다 — 청취 GDD가 못박은
회수 지점 분리를 그대로 승계한다.

### 이 판타지가 깨졌다는 신호

**플레이어가 등급을 고민 없이 고르게 되면** 실패다. 원인은 둘 중 하나다 — ①
알아낸 것과 등급 사이의 거리가 너무 뻔하거나(길드마스터북이 정답을 복제하고 있다),
② 등급이 결과를 안 바꾸거나(대비 가중 또는 지원 판정이 죽어 있다).

## Detailed Rules

### R1. 칸은 두 종류다. 섞이지 않는다

| | **자동 기록 칸** | **판단 칸** |
| ---- | ---- | ---- |
| 무엇 | 종류 · 대상 · 규모 · 장소 · 기한 · 경로 · **특징 및 약점** (7) | **위험도 등급** (1) |
| 누가 채우나 | **청취가 자동으로** | **플레이어가 직접** |
| 고칠 수 있나 | **아니오** | 예 (도장 전까지) |
| 틀릴 수 있나 | 아니오 — 알아낸 것을 그대로 옮긴다 | **예. 그것이 핵심이다** |

> **왜 자동 기록 칸을 못 고치게 하는가**: 고칠 수 있으면 *"트롤 3마리"* 를 *"고블린
> 1마리"* 로 바꿔 적을 수 있고, 그 순간 이 게임은 **잘못된 정보를 임의로 만들어 쓰는
> 게임**이 된다. 거짓말은 **판단 칸에서만** 가능해야 한다 — 위험도를 낮춰 적는 것은
> 거짓이 아니라 **판단**이며, 그 구별이 기둥 6이 억울함이 되지 않게 막는다.

~~*"판단 칸은 위험도 등급 · 권장 인원 · 특이사항 셋이다"*~~
→ **폐기 (2026-08-10).** 권장 인원은 무리 단위 지원이 흡수했고, 특이사항 자유 서술은
잘못된 정보 생성과 클릭 노동을 동시에 불렀다. **판단 칸은 하나다.**

### R2. 7항목은 고정이다 — 열린 슬롯만 보이지 않는다

의뢰서 서식은 **의뢰 종류와 무관하게 7항목이 모두 인쇄되어 있다.** 그 의뢰에서
청취가 다루지 않는 항목도 `미확인`으로 남는다.

> **왜 고정인가**: 항목이 의뢰마다 달라지면 **빈칸이 무엇을 뜻하는지 배울 수 없다.**
> 서식이 같아야 *"이번 건은 유독 경로가 비어 있다"* 가 읽힌다. 그리고 고정 서식은
> **플레이어가 무엇을 물어볼 수 있었는지**를 말없이 가르친다 — 창구는 침묵하지만
> 종이는 서식으로 말한다.

**단, 서식이 정답을 알려주는 것은 아니다.** *"규모를 안 물으셨습니다"* 같은 지적은
어디에도 뜨지 않는다 (청취 GDD 「창구는 끝까지 침묵한다」 승계).

### R3. 항목의 상태는 셋으로 접어 보인다

청취는 5상태(`미상`/`어렴풋`/`확실`/`막힘(무지)`/`막힘(은폐)`)를 갖지만, **의뢰서에
인쇄되는 표기는 셋이다.**

| 의뢰서 표기 | 청취 상태 | 종이에 적히는 것 |
| ---- | ---- | ---- |
| **확정** | `확실` | *트롤 3마리* |
| **모호** | `어렴풋` | *대형 미상* |
| **미확인** | `미상` · `막힘(무지)` · `막힘(은폐)` | `—` |

> **`미상`과 `막힘`을 저장 계층에서 가르는 것은 불변이다** (청취 R1, P2 책임 귀속의
> 유일한 근거). **접히는 것은 의뢰서 표기뿐**이다 — 모험가가 받아 보는 종이에
> *"물었는데 안 알려줬다"* 를 인쇄하는 것은 사건의 사실이 아니라 창구의 사정이다.
> 3단 대조 화면(P2)은 저장된 5상태를 그대로 쓴다.

### R4. 자동 기록은 청취 중 실시간으로 갱신된다

칸이 열리는 즉시 의뢰서에 적힌다. **의뢰서는 청취가 끝난 뒤 여는 별도 화면이
아니다** — 같은 창구 화면의 하단이며, 청취의 조작 대상 그 자체다 (청취 V1).

- **자동 기록 칸에는 검은 잉크(사실)만 실린다.** 플레이어가 기입한 내용은 이 칸에
  존재할 수 없다 (R1 — 수정 불가)
- 상태 구별은 **확정 / 모호 / 미확인** 3표기가 전부다 (R3). **잉크 이원 표기는 없다**
- **의뢰인이 떠난 뒤에도 의뢰서는 살아 있다** (청취 R7·Edge「인내」)

> ~~*"단정(청취 R13, 붉은 잉크)은 자동 기록 칸에 그대로 실린다. 검은 잉크(사실)와
> 구별 표기가 유지된다. 이후 사실이 밝혀지면 단정에 줄이 그이고 사실이 덮는다."*~~
> → **폐기 (2026-08-10) — 청취 R13(단정) 자체가 폐기됐다.**
> 사유: **기둥 6의 입력단이 「단정」에서 「위험도 등급」으로 옮겨갔다.** 자동 기록은
> 수정 불가이며, 임의 기재 경로는 의도적으로 닫혔다 — *"잘못된 정보를 임의로 만들어
> 쓰는 게임"* 을 막는 것이 R1의 존재 이유이고, 붉은 잉크는 바로 그 경로였다.
> 청취 GDD의 R13·AC-R13-01/02/03 폐기는 그쪽 문서가 소유한다.

### R5. 위험도 등급은 도장 전까지 언제든 바꿀 수 있다

플레이어는 `D/C/B/A/S` 중 하나를 고른다. **다시 고르는 데 비용이 없고 횟수 제한이
없다.** 확정되는 순간은 **도장 하나뿐**이다.

> **왜 무제한인가**: 등급은 자원이 아니라 판단이다. 판단을 무르는 데 값을 매기면
> 플레이어는 **틀릴까 봐 안 고르게 되고**, 그러면 판단이 아니라 회피가 학습된다.
> 값은 도장 뒤에 온다 — 사람이 돌아오지 않는 형태로.

**등급을 고르지 않은 채로도 도장을 찍을 수 있다** (R7).

### R6. 세 등급의 표시 규칙

| | 표시 | 규칙 |
| ---- | ---- | ---- |
| ① 의뢰인의 주장 | **항상 보인다** | 의뢰서 상단에 *"의뢰인 진술: C"* 로 인쇄. 청취 전부터 있다 |
| ② 플레이어의 판정 | 고른 즉시 | 주장과 **다른 칸**에 적힌다. 나란히 놓여야 대조가 보인다 |
| ③ 실제 위험 `T` | **절대 안 보인다** | 파견 결과 이전에는 화면·DOM·세이브 어디에도 나오지 않는다 |

**추천 등급은 존재하지 않는다.** 시스템이 *"B를 권합니다"* 라고 말하는 지점은
설계에 없다 (F1 참조).

### R7. 미확인 항목이 있어도, 등급을 안 골라도 도장은 언제나 찍힌다

막다른 길 금지(기둥 5)는 의뢰서에도 적용된다.

- **전 항목 `미확인`이어도 유효한 의뢰서다** — 대비 `C = 0`으로 게시될 뿐이다
- **등급 미기재도 유효하다.** 다만 **빈칸은 기본값이 아니다** — 위험도 미기재는
  *"위험 없음"* 이 아니라 ***"모른다고 적었다"*** 이고, 게시판에서 그렇게 읽힌다
- 확인 대화상자를 띄우지 않는다. 도장에 손을 얹는 **한 박자 연출**이 그것을 대신한다
  (청취 V5)

> **등급 미기재 게시물의 처리 요구**: 지원 판정(`assignment-dispatch.md` F4)에서
> 무등급 게시물은 **`S`로 간주해 위험 허용치를 비교한다** — *"등급도 못 매긴 일"* 은
> 무리에게 가장 위험한 일로 읽히는 것이 맞다. **값의 소비는 그 문서가 소유하며, 이
> 문서는 요구만 건넨다.**

### R8. 세부 지시는 없다 — 모험가가 스스로 준비한다

접근 시각 · 장비 · 전술을 지정하는 칸을 두지 않는다. **길드마스터의 일은 정보를
정확히 넘기는 것이지 작전을 짜는 것이 아니다.**

> 그래서 **대비 `C`는 "얼마나 잘 지시했는가"가 아니라 "얼마나 충실히 적혔는가"** 다
> (F3). 지시 칸을 두면 준비의 책임이 모험가에서 플레이어로 넘어오고, 그 순간 이
> 게임은 파티 빌더가 된다 — 기둥 2(창구를 떠나지 않는다)의 반대편이다.

## Formulas

### F1. 공개 등급 기준 — **계산식이 아니라 기준표다**

**위험도 등급은 「필요한 파티 수준」이다.** 추상적인 위험 눈금이 아니다.
아래 표는 **게임 안에서 플레이어에게 공개된다** (길드마스터북 첫 장).

| 등급 | **공개된 의미** |
| ---- | ---- |
| **D** | 신입 1명이 처리 가능 |
| **C** | 신입 2~3명 또는 숙련자 1명이 처리 가능 |
| **B** | 정규 파티가 필요 |
| **A** | 베테랑 파티와 충분한 정보가 필요 |
| **S** | 정예 파티와 특수 대응이 필요 |

**플레이어는 숨겨진 숫자를 맞히는 것이 아니라, 알아낸 사실을 이 기준에 대입한다.**
*"트롤 3마리, 폐광 안, 다수"* → 기준표를 읽고 → *"정규 파티로는 모자라겠다"* → **A**.

> **번역기는 코드가 아니라 사람이다.** 슬롯 내용에서 등급으로 가는 다리는 시스템이
> 아니라 **길드마스터북을 든 플레이어**가 놓는다. 이것이 D1의 답이며, 이 개정에서
> 가장 중요한 한 줄이다.

**실제 위협도 `T` 매핑** — 의뢰마다 숨은 값이며, P1은 **콘텐츠별로 명시**한다
(생성식 없음):

| 등급 | D | C | B | A | S |
| ---- | ---- | ---- | ---- | ---- | ---- |
| **`T`** | **3** | **4** | **5** | **6** | **7** |

`T`는 `assignment-dispatch.md` F3(`D = P + C − T`)의 입력이고, 안전 범위는 그 문서의
Tuning Knobs(2~9)가 소유한다. **이 표는 「등급의 이름 ↔ 위협도 수치」 사전이지
플레이어에게 보이는 값이 아니다** (R6 ③).

#### ~~구 F1. 위험도 등급 매핑 `gradeOfRisk(risk: 0~200)`~~ — **폐기 (2026-08-10)**

~~`risk < 40 → D` / `40~79 → C` / `80~119 → B` / `120~169 → A` / `≥170 → S`.
`dispatch.successRatio = 1.0`과 `adventurer.gradeThresholds`(25/50/75),
`scaling.maxPartySizeCap = 3`, `scaling.riskSpread = 0.2`,
`scaling.concealmentMax = 0.45`에 근거한 밴드 산정.~~

**두 번 죽었다.**

1. **파견 모델이 폐기됐다.** `risk 0~200`·`successRatio`·`gradeThresholds`는
   `assignment-dispatch.md`가 `D = P + C − T`(전력 1~4 / 대비 0~4 / 위협 2~9)로

2. **애초에 다리가 필요 없다.** 저 계산식의 유일한 목적은 **시스템이 등급을

   번역기가 필요 없다.**

> **살아남은 것 하나**: *"밴드를 파티 구성으로 정한 것이 핵심"* — 그 통찰은 숫자가

### F2. 항목 점수 (`score`)

```
score(확정) = 1.0
score(모호) = 0.5
score(미확인) = 0.0
```

**청취 F3(`completeness`)와 같은 채점 규칙이다.** 차이는 **분모**뿐이며 F3에서
갈린다.

### F3. 대비 `C` — 의뢰서에 적힌 사실의 충실도

```
C = 4 × Σ score(항목 j) / n        (j = 그 의뢰의 진실 항목)
n = 그 의뢰가 가진 진실 항목의 개수
C ∈ 0 .. 4
```

- **분모 `n`은 「그 의뢰의 진실 항목 수」다** — 서식의 7항목이 아니다. 그 의뢰에
  실제로 존재하는 사실만 센다 (경로가 없는 의뢰에서 `경로: 미확인`은 감점이 아니다)
- **분자는 의뢰서에 인쇄된 상태**로만 센다. 플레이어가 머리로 아는 것은 계상되지
  않는다 — **적힌 것만이 간다** (기둥 6)
- **가중치를 두지 않는다** (`w[칸]` 없음). 청취 F3는 가중합이지만 `C`는 균등이다 —
  가중치표는 공략집이 되고, 대비는 *"무엇을 알아냈나"* 가 아니라 *"얼마나
  알아냈나"* 여야 한다
- **LLM이 관여하지 않는다.** 순수 규칙 계산이며 같은 의뢰서면 항상 같은 `C`다

> ~~`assignment-dispatch.md` R9·F2: *"대비 추출은 LLM(구조화 출력)"*~~
> → **폐기 (2026-08-10).** 자유 서술 칸이 사라져 **판독할 문장이 없다.** 항목 상태는
> 이미 구조화된 값이므로 추출 단계 자체가 불필요하다. **LLM의 소관에서 대비가
> 빠지고, 대사 생성만 남는다.**

#### 워크드 예제 — 트롤 / 폐광 / 햇빛

진실 항목 4개(`n = 4`)를 가진 의뢰: 대상=트롤 · 규모=다수 · 장소=폐광 ·
특징 및 약점=햇빛에 약함.

| # | 의뢰서 상태 | Σ score | **`C`** | 서술 |
| ---- | ---- | ---- | ---- | ---- |
| ① | 대상 확정, 나머지 미확인 | 1.0 | **1.0** | 트롤인 줄만 알고 간다 — 낮은 대비 |
| ② | 대상·규모·장소 확정, 약점 미확인 | 3.0 | **3.0** | 어디서 몇을 만나는지 안다 — 중간 대비 |
| ③ | 4항목 전부 확정 | 4.0 | **4.0** | 햇빛까지 안다 — 높은 대비 |
| ④ | 대상 확정, 규모 모호, 장소 확정, 약점 미확인 | 2.5 | **2.5** | 규모가 흐리다 |
| ⑤ | 전 항목 미확인 | 0 | **0** | 빈 의뢰서 (R7 — 유효하다) |

**이 차이가 목숨이다.** `T = 6`(A급) 의뢰에 전력 `P = 4`인 무리가 갈 때
(`assignment-dispatch.md` F3, `D = P + C − T`):

| 예제 | `D` | 결과 구간 |
| ---- | ---- | ---- |
| ③ `C=4` | **2** | 진통 끝 완수 |
| ② `C=3` | **1** | 부상 철수 |
| ① `C=1` | **−1** | **사망자 발생** |
| ⑤ `C=0` | **−2** | **사망자 발생** (경계) |

**같은 무리, 같은 괴물, 다른 종이.** 세 항목을 더 알아낸 것이 장례를 막았다.

## Edge Cases

### 전 항목 미확인인 채로 도장

**유효하다.** 오류도 경고도 아니다 (R7, 기둥 5). `C = 0`으로 게시되며, 게시물의
정보 충실도가 바닥이므로 지원이 줄어든다(`assignment-dispatch.md` F4의 `minInfo`).
**막다른 길이 아닌 이유**: 유찰의 출구 3개(보수 인상 · 재작성 · 초빙)가 그대로 열려
있다(그 문서 R8). 재청취가 아니라 **재작성**이 출구라는 점이 중요하다 — 이미 아는
것을 다시 못 적어서 유찰된 상황은 발생하지 않는다.

### 의뢰인의 주장이 실제와 정반대일 때

**설계상 정상이며 흔하다** (은폐형 의뢰인). 주장 `D` / 실제 `S`도 유효한 실현이다.

- 시스템은 **경고하지 않는다.** *"진술과 기록이 어긋납니다"* 류의 표시는 없다 —
  그것은 창구가 정답을 알려주는 것이다
- 플레이어가 가진 유일한 단서는 **자동 기록된 사실 그 자체**와 청취 중의 기색이다
- **회수는 결과 대조(P2)** 에서 3단(주장/판정/실제)으로 나란히 보여 준다. 여기서
  *"저 사람이 나를 속였다"* 와 *"내가 안 물었다"* 가 갈린다

### 플레이어가 `S`를 남발할 때 — **대가는 있고, 절반은 아직 미확정이다**

등급은 결과가 아니라 **누가 오는지**를 바꾸므로 과대 기재에 대가가 있다.

| 대가 | 성립 여부 |
| ---- | ---- |
| **지원 감소** | ✅ **성립.** `assignment-dispatch.md` F4의 `위험허용_g ≥ 표기위험도_q`가 이미 이것이다. 위험 허용치가 낮은 무리는 `무시`로 떨어지고, 남는 것은 소수의 베테랑뿐이다 |
| **보수 부담** | ⚠ **아직 성립하지 않는다.** 시세(F4의 분모)가 **표기 등급에 연동될 때만** 성립한다. 그 연동은 어디에도 정해져 있지 않다 — 길드마스터북 시세표(#26)와 `assignment-dispatch.md` F4가 함께 결정해야 한다 |

**정직하게 적는다: 현재 문서 상태로는 대가가 하나뿐이다.** 지원 감소만으로도
과대 기재가 무료는 아니지만, *"S로 도배하고 베테랑만 쓴다"* 를 막는 힘은 약하다.
시세 연동이 정해지기 전까지 이 구멍은 열려 있다.

> **반대 방향(`D` 남발)은 이미 완결되어 있다.** 낮게 적으면 신입이 몰려오고, 대비
> `C`는 등급과 무관하므로 보정되지 않는다 → `P`가 낮은 채로 `T`를 만난다 → 사람이
> 죽는다. **기둥 6의 정본 경로이며 여기에는 구멍이 없다.**

### 등급을 안 고르고 도장을 찍으려 할 때

**막지 않는다.** 확인 대화상자도 띄우지 않는다 (R7). 게시물에는 등급 칸이 비어
있는 것으로 인쇄되고, 지원 판정은 `S`로 간주한다 — **가장 위험한 것으로 읽히므로
"안 고르는 것"이 회피 전략이 되지 않는다.**

### 도장 이후

**의뢰서는 불변이 된다.** 등급도 자동 기록도 고칠 수 없다. 다만 유찰된 게시물의
**재작성**(`assignment-dispatch.md` R8 ②)은 새 청취 없이도 등급을 다시 매길 수
있어야 한다 — 그 경로의 소유는 그 문서다.

### 진실 항목이 1개뿐인 의뢰

`n = 1`이면 `C`는 0 또는 2 또는 4만 나온다 (계단이 거칠다). **유효하지만 밸런스
경고 대상이다** — `n ≥ 3`을 콘텐츠 작성 기준으로 삼는다 (Tuning Knobs).

### 청취를 한 번도 하지 않고 도장

가능하다. 선제 진술(청취 R3)만으로 채워진 상태가 그대로 기록된다. **의뢰인이
순순히 말한 것만으로도 `C > 0`이 나올 수 있다** — 그것이 무료로 얻는 바닥이며,
플레이어의 기여는 그 위의 증분이다.

**게이트웨이를 완전히 차단해도 의뢰서 작성 → 도장 → 게시가 바이트 단위로 동일하게
동작한다.**

## Acceptance Criteria

> GDD 본문을 읽지 않은 QA 담당자도 판정할 수 있게 작성했다.

### A. 칸의 정의

- **AC-CF-01** *(정적 + 실브라우저)* 자동 기록 7항목이 **모두 편집 불가**다. DOM에
  해당 영역의 `input`·`textarea`·`contenteditable`이 **0개**이고, 실브라우저에서
  클릭·더블클릭·키 입력으로 값이 바뀌지 않는다.
- **AC-CF-02** *(정적 + 실브라우저)* **의뢰서 화면 전체의 텍스트 입력 요소가 0개**다.
  등급 선택은 버튼/라디오이며 자유 서술 칸은 존재하지 않는다.
- **AC-CF-03** 서식은 의뢰 종류와 무관하게 **항상 7항목**을 표시한다. 다루지 않는
  항목은 `미확인`으로 인쇄된다 (항목이 사라지지 않는다).
- **AC-CF-04** 청취에서 칸이 열리는 즉시 의뢰서 표기가 갱신된다 (별도 확정 조작 없음).
- **AC-CF-05** `막힘(무지)`·`막힘(은폐)`·`미상`은 의뢰서에서 **모두 `미확인`으로
  동일하게 인쇄**되지만, 세이브에서는 **구별 보존**된다 (직렬화 왕복 검사).

### B. 등급

- **AC-CF-06** *(정적 + 실브라우저)* **추천 등급이 어디에도 표시되지 않는다.**
  화면·DOM·툴팁·`aria` 속성 어디에도 시스템이 제안한 등급 값이 없고, 코드에
  추천 계산 함수가 존재하지 않는다.
- **AC-CF-07** 의뢰인의 주장 등급은 **청취 시작 전부터 항상 표시**되며, 플레이어의
  판정 등급과 **다른 칸에 나란히** 보인다.
- **AC-CF-08** *(BLOCKING)* **실제 위험 `T`가 파견 전에 노출되지 않는다** — 화면,
  DOM(속성·데이터셋·주석 포함), 세이브 파일, 네트워크 페이로드 어디에도 없다.
- **AC-CF-09** 도장 전까지 등급을 **횟수 제한 없이** 다시 고를 수 있고 비용이 없다.
- **AC-CF-10** 도장 이후 등급과 자동 기록이 **불변**이 된다.

### C. 도장과 막다른 길

- **AC-CF-11** **전 항목 `미확인`이어도 도장이 찍힌다.** 경고·차단·확인 대화상자가
  없다.
- **AC-CF-12** **등급을 고르지 않아도 도장이 찍힌다.** 게시물의 등급 칸은 비어 있고,
  지원 판정에서 `S`로 간주된다.
- **AC-CF-13** 의뢰인이 인내 소진으로 퇴장한 뒤에도 의뢰서 작성과 도장이 가능하다
  (청취 AC-EDGE-02와 짝).

### D. 대비 `C` — 수식

- **AC-CF-14** 워크드 예제 재현: `n=4` 의뢰에서
  ① 1항목 확정 → `C = 1.0` / ② 3항목 확정 → `C = 3.0` / ③ 4항목 확정 → `C = 4.0` /
  ④ 확정2+모호1 → `C = 2.5` / ⑤ 전 미확인 → `C = 0`.
- **AC-CF-15** **결정론**: 같은 의뢰서 상태면 `C`가 **항상 같다.** LLM 게이트웨이를
  두 개의 서로 다른 목으로 갈아끼워도, 또는 완전히 차단해도 `C`가 바이트 단위로
  동일하다.
- **AC-CF-16** *(정적)* `C` 계산 경로에 `fetch`·LLM 게이트웨이 import가 없다
  (`src/domain/commission.ts`는 순수 함수다).
- **AC-CF-17** 그 의뢰에 존재하지 않는 항목은 분모 `n`에서 제외된다 — 경로가 없는
  의뢰에서 `경로: 미확인`이 `C`를 떨어뜨리지 않는다.
- **AC-CF-18** `C ∈ [0, 4]`가 모든 입력에서 보장된다 (경계값 + 임의 조합 검사).

### E. 화면 배선 (**수동-BLOCKING** — 이 저장소의 2회 사고 재발 방지)

- **AC-CF-19** 실브라우저: 청취 → 자동 기록 갱신 → 등급 선택 → 도장 → 게시가
  실제 클릭으로 완주된다.
- **AC-CF-20** 실브라우저: LLM 게이트웨이 차단 상태에서 위 동선이 **동일하게**
  완주된다 (대사 문자열만 폴백으로 바뀐다).
- **AC-CF-21** *(정적 + 실브라우저)* **자동 기록 칸에 플레이어가 기입한 내용이
  존재할 수 없다.** 어떤 조작 시퀀스로도 7항목의 값이 청취 산출 이외의 것으로
  바뀌지 않으며, 코드에 자동 기록 칸을 쓰는 플레이어 입력 경로가 없다.

> ~~**AC-CF-21** 실브라우저: 붉은 잉크(단정)와 검은 잉크(사실)가 의뢰서에서
> **색 + 표기 이중**으로 구별된다 (청취 AC-R13-02와 짝).~~
> → **폐기 (2026-08-10) — 청취 R13(단정) 폐기.** 기둥 6의 입력단이 단정 → 위험도
> 등급으로 옮겨갔고, 자동 기록은 수정 불가이므로 임의 기재 경로가 닫혔다.
> **잉크 이원 표기 자체가 사라졌으므로 검증할 대상이 없다.** 그 자리를 위 「수정
> 불가」 검증이 대신한다 — 원래 요구에 더 정확하다.
