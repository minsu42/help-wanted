## Overview

**길드마스터북은 플레이어가 읽어 두는 네 권의 참고서다. 그리고 두 가지 일을 한다.**

| | 무엇을 공급하나 | 어디서 쓰이나 |
| ---- | ---- | ---- |
| ① **일깨우기의 재료** | 밖에서 온 사실 — `hintTags`/`leverageTag`가 붙은 항목 | **청취 (#21)** — R5 일깨우기 · R6 들이대기 |
| ② **등급 판단의 기준** | 대상별·환경별 위험 기준과 주의 문구 | **의뢰서 (#25)** — 위험도 등급 `D/C/B/A/S` 기입 |

**이 둘이 같은 책이라는 것이 설계의 전부다.** 「트롤」 항목 하나가 대화를 뚫는
열쇠이면서 동시에 *"단독이면 B, 무리면 A 이상"* 이라는 판단의 근거다. 읽은 것이
**대화도 뚫고 판단도 만든다.** 두 권으로 쪼개면 책은 도구 두 개가 되고, 한 권이면
**지식 하나**가 된다.

### 책은 계산하지 않는다 *(최상위 원칙)*

**길드마스터북은 정답 등급을 자동 계산하지 않는다. 판단에 필요한 기준과 대표 사례를
제공할 뿐이다.**

> **충분히 조사했다면 적절한 등급을 합리적으로 판단할 수 있어야 한다. 난도는 등급표를
> 추측하는 데서 나오지 않고, 필요한 사실을 알아내는 데서 나온다.**

이 한 문장이 이 문서 전체의 헌법이다. 난도의 소재지가 **책 읽기**가 아니라
**청취**에 있다는 선언이고, 그래서 추천 등급 계산기도, 자동 매칭도, 「이 의뢰에
해당하는 항목」 강조도 존재하지 않는다.

### 이 시스템이 없으면

**두 곳이 동시에 무너진다.**

1. **청취의 무지 축이 죽는다** — `막힘(무지)` 칸을 열 재료가 P1에 하나도 없다.
   `[일깨운다]`가 영영 뜨지 않고, 무지형 의뢰인은 그냥 벽이 된다
2. **등급 기입이 눈금 없는 추측이 된다** — 플레이어는 *"트롤 세 마리"* 를 알아내고도
   그것이 B인지 A인지 알 방법이 없다. 그러면 기둥 6의 *"내가 A라고 적었다"* 는
   책임이 아니라 **주사위**가 된다

**②가 더 무섭다.** 재료가 없으면 게임은 심심해지지만, 기준이 없으면 게임이 **억울해진다**
(`game-concept.md` 「책임이 억울함이 될 위험」).

## Player Fantasy

**"내가 읽어 둔 것이 지금 걸린다."**

### 목표 감정 ① — *"아!"* (재료로 쓰일 때)

정점은 **책을 펴는 순간이 아니라 책을 덮은 뒤**에 온다. 의뢰인이 *"그 비탈 말입니까,
글쎄요…"* 라고 할 때, 화면에는 아무 힌트도 뜨지 않는다. 그런데 어제 지역권에서 읽은
*"그 일대는 소유가 갈려 다툼이 잦다"* 가 머릿속에서 걸린다.

**걸리는 것은 시스템이 아니라 플레이어다.** 이 감정은 시스템이 후보를 좁혀 주는 순간
소멸한다 — 그래서 R7의 열람 금지 조항들이 감정 설계이지 UI 취향이 아니다.

### 목표 감정 ② — *"이건 A다"* (기준으로 쓰일 때)

칸이 채워진다. `대상=트롤` · `규모=무리` · `장소=폐광`. 도감은 *"트롤 무리는 A 이상"*
이라 하고 지역권은 *"폐광은 퇴로가 제한된다"* 고 한다. **책은 답을 합쳐 주지 않는다.**
합치는 것은 플레이어이고, 그 순간이 **판단**이다.

그리고 그 판단은 도장을 거쳐 남의 손에 들어간다 (기둥 6).

### 성장하는 것은 캐릭터가 아니라 플레이어의 지식이다 *(기둥 1)*

책은 레벨업하지 않는다. 항목이 늘어나는 것도 P1에서는 없다 (P4 소문이 재료를 **추가**할
뿐). **10회차에 3회차보다 잘하게 되는 이유는 순전히 플레이어가 책을 읽었기 때문**이며,
그것이 *"아는 자가 이긴다"* 의 가장 순수한 형태다.

### 안티 감정: **찾아보기 노동**

가장 큰 위험은 *"막혔다 → 책을 연다 → 색인을 훑는다 → 맞는 걸 찾는다"* 라는 **숙제**다.
이것이 되는 순간 v5가 받은 판정 — *"선택지 고르기 게임"* — 이 책의 형태로 부활한다.

**세 가지로 막는다:**

| 방어 | 내용 | 어디에 |
| ---- | ---- | ---- |
| **작다** | P1 전체 **8~12항목**. 다 읽는 데 몇 분이면 되고, **색인이 필요 없는 크기**다 | Formulas F1 |
| **미리 읽힌다** | 책은 막히기 전부터 열려 있다. 첫 계약 전 시세권 1회 노출이 「읽는 물건」이라는 것을 가르친다 | R7 · R8 |
| **찾아도 안 나온다** | 문안이 개념·통념 층위라 **검색으로는 매칭되지 않는다.** 기억으로만 걸린다 | R6 |

> **세 번째가 핵심이다.** 책이 정답 문장을 담고 있으면 *"막힌 칸의 단어로 책을 훑는다"*
> 가 최적 전략이 되고, 그 순간 이 게임은 Ctrl+F 게임이 된다.

### 이 판타지가 깨졌다는 신호

- 플레이어가 **막힌 뒤에만** 책을 연다 → 준비 자산이 아니라 정답 메뉴가 됐다
- 플레이어가 책의 문장을 **읽지 않고 제목만 훑는다** → 항목이 너무 많거나 문안이 정답의
  복제라 본문이 쓸모없다
- *"어떤 등급을 적어야 하지"* 가 **책을 뒤지는 문제**가 됐다 → 기준의 구간이 너무 잘게
  쪼개졌다 (Tuning Knobs 「기준의 세밀도」)

## Detailed Rules

### R1. 네 권이고, 권마다 소관이 다르다

| 권 | 담는 것 | 주로 어느 칸에 | 재료로서 | P1 항목 수 |
| ---- | ---- | ---- | ---- | ---- |
| **도감** | 마물·짐승·인적 위협의 통념과 습성 | `대상` · `규모` · `특징 및 약점` | **일깨우기**의 주력 | **4~5** |
| **지역** | 지형·길·계절이 일에 미치는 영향 | `장소` · `경로` · `기한` | 일깨우기 | **2~3** |
| **조직** | 세력·직업·관습·이해관계 | `특징 및 약점` · 사람에 관한 것 | **들이대기**의 주력 (`leverageTag` 보유) | **1~2** |
| **시세** | 의뢰 종류별 통상 보수 | (칸에 안 들어간다) | **재료 아님** | **1** (표 하나) |

**시세권은 성격이 다르다** — 칸을 채우지도, 재료가 되지도 않는다. 하는 일은
**보수 제안액을 읽는 눈금**을 주는 것 하나다 (청취 R12 *"시세의 네 배"* · 배정 F4의
`보수비 = 게시 보수 / 시세`). 그래서 항목 수 예산에서 표 하나로 셈한다.

> **왜 나누는가**: 네 권은 **분류 편의가 아니라 읽는 순서의 힌트**다. 조사 의뢰를
> 받으면 도감과 지역을 보게 되고, 사람이 걸린 의뢰면 조직을 보게 된다.
> 권 경계가 겹치는 문제는 **Q1**이 소유한다.

### R2. 한 항목이 두 역할을 겸한다 *(설계 결정)*

**등급 기준 항목과 일깨우기 재료 항목은 같은 항목이다.** 「트롤」 하나가 기준도 주고
재료도 된다.

```
「트롤」
  본문   — 개념·통념 층위의 산문 (읽을 것)
  기준   — 단독 B / 무리 A 이상 / 주의 문구        → 의뢰서가 쓴다
  hintTags — 대화를 뚫는 열쇠                       → 청취가 쓴다
  leverageTag — (있으면) 사람을 압박하는 범주        → 청취가 쓴다
```

> **왜 쪼개지 않는가**: 쪼개면 플레이어가 **두 번 읽는다.** 「일깨우기용 트롤」과
> 「기준용 트롤」이 따로 있으면 책은 도구함이 되고, *"읽어 둔 것이 걸린다"* 는
> 대신 *"필요할 때 꺼낸다"* 가 된다. 하나로 두면 **한 번 읽은 것이 두 곳에서 값한다** —
> 그것이 Overview가 말한 설계의 전부다.
>
> **부작용도 하나 있고, 그것은 의도된 것이다**: 재료로 쓰려고 읽다가 기준을 알게 되고,
> 기준을 보려고 폈다가 재료를 알게 된다. **책이 한 번에 두 가지를 가르친다.**

### R3. 항목의 구조

| 필드 | 필수 | 무엇 | 소비자 |
| ---- | ---- | ---- | ---- |
| `id` | ✅ | 안정 식별자 (세이브·검증용) | 전부 |
| `book` | ✅ | `bestiary` / `region` / `order` / `rates` | UI |
| `title` | ✅ | 표제 (「트롤」·「폐광」) | UI |
| `body` | ✅ | **개념·통념·소문 층위의 산문 2~4줄** | UI (읽히는 본체) |
| `criteria` | ▲ | 조건 → 등급 대응 목록 | UI **표시만** |
| `caution` | ▲ | 주의 문구 (*"과소평가하지 말 것"*) | UI **표시만** |
| `hintTags` | ▲ | 일깨우기 매칭 키 (1~3개) | 청취 R5 |
| `leverageTag` | ▲ | 들이대기 범주 (`절차`/`손익`/`체면`) 또는 없음 | 청취 R6 |

▲ = 권/항목 성격에 따라 없을 수 있다. **`criteria`가 없는 항목도 유효하다** (조직권의
관습 항목 등) — 그런 항목은 순수한 재료다. 반대로 `hintTags`가 없는 항목도 유효하다
(시세표) — 그런 항목은 순수한 기준이다. **다만 도감 항목은 둘을 다 가져야 한다**
(빌드 검증 — AC-DATA-03).

### R4. 기준은 「조건 → 등급」의 짧은 목록이다

```
고블린
  소수            D
  무리            C
  대규모 집단     B 이상

트롤
  단독            B
  무리            A 이상
  ⚠ 규모와 지형이 불명확하면 과소평가하지 말 것

드래곤
  존재가 확인되면  S
```

- **구간은 항목당 1~3개다** (Tuning Knobs 「기준의 세밀도」). 드래곤처럼 하나여도 된다
- **`B 이상`·`A 이상` 같은 열린 표기를 허용한다.** 이것은 데이터 결함이 아니라
  **설계다** — 책이 답을 확정해 주지 않는 자리를 만든다. 상한을 정하는 것은 플레이어다
- **등급의 뜻은 「필요한 파티 수준」이다** (R5). 추상적 위험 눈금이 아니다

### R5. 등급의 뜻은 「필요한 파티 수준」이다 *(확정)*

| 등급 | 뜻 |
| ---- | ---- |
| **D** | 신입 1명이면 된다 |
| **C** | 신입 2~3명, 또는 숙련 1명 |
| **B** | 정규 파티가 필요하다 |
| **A** | 베테랑 파티 + 충분한 정보 |
| **S** | 정예 + 특수 대응 |

**플레이어가 직접 고르며 시스템은 추천하지 않는다.** 등급을 사람 수로 말하는 이유는
그것이 **모험가가 의뢰서를 읽는 방식**이기 때문이다 — 등급은 게이지가 아니라
**동원 지시**다 (`commission-form.md` F1의 같은 결정).

> **A만 유일하게 사람 수 밖의 조건을 단다** — *"충분한 정보"*. 이것은 우연이 아니라
> **기둥 6이 등급표 안으로 들어온 자리**다. A급 일에서 정보가 모자라면 사람이 죽는다는
> 것을 등급의 정의 자체가 말한다.

### R6. 문안은 개념·통념 층위로 쓴다 — **정답 복제 금지** *(불변)*

**책의 어떤 문장도 의뢰 템플릿의 진실 문자열과 같아서는 안 된다.**

| | 금지 | 허용 |
| ---- | ---- | ---- |
| 예 | *"사람 발만 한데 발가락이 셋이었다"* (템플릿의 `확실` 사실 그대로) | *"발가락이 셋인 자국은 이 지방에서 하나뿐이다"* |
| 왜 | 책을 훑으면 답이 나온다 → Ctrl+F 게임 | 읽은 사람만 연결한다 → *"아!"* |

**책과 정답 사이의 추론 거리가 "아!"의 크기다** (`intake-system.md` U3 실측 기록).
거리는 노브이며 기본값은 **2단계**다 (Tuning Knobs 「추론 거리」).

**정적 검사로 강제한다** — `quest-templates.json`의 진실 문자열과 `handbook.json`의
`body`/`criteria` 문자열이 **일치하는 쌍이 0개**여야 한다 (AC-DATA-01).

### R7. 열람 규칙 — **항상 열람 가능한 준비 자산** *(불변, `intake-system.md` U3 승계)*

**금지 목록. 이것을 어기면 v5의 「선택지 고르기 게임」 판정으로 퇴행한다.**

| ❌ 금지 | 왜 |
| ---- | ---- |
| **막혀야만 열리는 규칙** | 책이 막힘의 보상이 되면 「읽는 물건」이 아니라 「받는 물건」이다 |
| **막힌 순간의 자동 펼침** | 시스템이 *"지금이 책 볼 때다"* 를 알려주는 것 = 정답 신호 |
| **관련 탭·항목 강조** | 후보를 좁혀 주는 것 = 정답 후보 메뉴 |
| **`hintTags`/`leverageTag`에 의한 정렬·색칠** | 무엇이 통할지 아는 것이 곧 퍼즐이다 |
| **「이 의뢰에 해당하는 기준」 추출 표시** | 판단을 대신해 주는 것 = 추천 시스템 |

**허용되는 것**: 평소 접혀 있는 것(표현), 권 탭으로 넘기는 것, 항목을 스크롤하는 것,
플레이어가 **직접** 연 상태를 유지하는 것.

> **경계선은 "누가 시작했는가"다.** 플레이어가 펴면 무엇이든 허용, 시스템이 펴거나
> 좁히면 무엇이든 금지. 유일한 예외가 R8이며, 그것이 예외인 이유도 명확하다.

### R8. 시세권은 첫 계약 전에 **1회** 노출된다 *(필수)*

첫 계약(첫 도장) 이전에 시세권이 **펼쳐진 상태로 한 번** 화면에 있어야 한다.

**R7과 충돌하지 않는 이유**: 이것은 **상황 반응이 아니라 초기 상태**다. 막힘에도,
칸에도, 의뢰 내용에도 반응하지 않는다 — **게임이 시작됐다는 사실 하나에만** 반응하고
그 후로는 두 번 다시 자동으로 열리지 않는다.

**없으면 무너지는 것**: 청취 R12의 *"시세의 네 배 = 경보"* 가 무의미해진다. 시세를
모르는 플레이어에게 모든 제안액은 그냥 숫자다. 배정 F4의 `보수비` 감각도 같이 죽는다.

> 구체 연출(튜토리얼 대사 / 책상 위 펼쳐진 초기 상태 / 첫날 편지)은 **Q3**이 소유한다.
> 이 문서가 못박는 것은 **「첫 계약 전 1회」라는 시점 하나**다.

### R9. 책은 게임 상태에 닿지 않는다 *(계층 규칙)*

- `src/domain/**`는 `handbook.json`을 **import하지 않는다.** 도메인이 아는 것은
  청취가 넘겨준 재료의 `hintTags`/`leverageTag`뿐이다
- 책은 **읽기 전용 정적 데이터**다. 런타임에 변하지 않고, 세이브에 들어가지 않는다
  (세이브에 들어가는 것은 «어느 항목을 재료로 썼는가»의 `id`뿐)
- **LLM은 책에 관여하지 않는다.** 문안은 사람이 쓴다. LLM의 소관은 **대사 생성**뿐이며
  (ADR-003), 재료를 건넬 때 나오는 *내 대사*의 생성이 접점의 전부다

### R10. 책은 P1에서 자라지 않는다

항목은 캠페인 중 추가되지 않는다. **재료를 늘리는 채널은 소문(#8, P4)**이며 그것은
수첩의 다른 묶음이다 (`intake-system.md` U3). P1의 책은 **처음부터 전부 열려 있는
고정 자산**이다.

> **왜 잠그지 않는가**: 해금은 *"읽는 물건"* 을 *"모으는 물건"* 으로 바꾼다. 그리고
> 해금 조건이 곧 진행 게이트가 되어 기둥 5(막다른 길 없음)와 부딪힌다.

## Formulas

### **이 시스템에는 판정 수식이 없다 — 그것이 설계다**

**`recommendGrade(slots, handbook) → Grade` 같은 함수는 존재하지 않으며, 존재해서는
안 된다.**

수식을 하나라도 두는 순간 다음이 순서대로 일어난다:

1. 수식이 있으면 **추천값이 생긴다**
2. 추천값이 있으면 **화면에 띄우고 싶어진다** (안 띄우면 왜 계산했나)
3. 띄우면 플레이어는 **그것을 그대로 적는다** — 뭉툭한 판단보다 시스템의 숫자가 늘 더
   믿음직해 보인다
4. 그 순간 기둥 6이 죽는다 — *"내가 A라고 적었다"* 가 *"시스템이 A라기에 A라고 적었다"*
   가 된다

**등급 기준은 수식이 아니라 표다.** 표는 사람이 읽고, 수식은 기계가 돌린다.
이 시스템의 산출물은 **읽히는 것**이지 계산되는 것이 아니다.

> `commission-form.md`의 열린 결정 **D1**(슬롯 내용 → 위험도 추정의 다리)은 이 문서의
> 관점에서 **(가) `completeness`만 쓴다**로 기울어 있다 — 슬롯 내용에서 등급을 뽑는
> 다리를 놓는 것 자체가 위 4단계의 1번이기 때문이다. 최종 결정권은
> `commission-form.md`에 있다.

### F1. 항목 수 예산 *(유일한 수량 제약)*

```
P1 총 항목 수 = 8 ~ 12
  도감 4~5 · 지역 2~3 · 조직 1~2 · 시세 1(표)
```

근거는 `intake-system.md` Tuning Knobs 「책의 항목 수 (P1)」 기본 **8~12** (안전 범위
6~20)이며 미해결 Q2가 소유한다. 상한의 근거는 **색인 없이 다 읽히는 크기**이고,
하한의 근거는 **막힌 칸에 줄 것이 있어야 한다**는 것이다.

**의뢰당 열린 칸 3개 · 그중 막힘 기대 1~2개**를 기준으로 하면, 8~12항목은
막힌 칸 하나에 **후보가 될 만한 항목 2~3개**를 주는 크기다 — 고를 것이 있으되
아무거나 통하지는 않는다.

### F2. `hintTags` 매칭 — 청취 R5와 **같은 규칙, 다른 소유자**

```
일깨우기 성공 ⇔ (재료.hintTags ∩ 칸.hintTags) ≠ ∅
```

**판정의 소유자는 청취(#21)다.** 이 문서는 **재료 쪽 `hintTags`를 어떻게 붙이는가**만
소유한다:

| 규칙 | 값 |
| ---- | ---- |
| 항목당 태그 수 | **1~3** (기본 2) |
| 태그의 층위 | **주제**이지 정답이 아니다 — `트롤의습성`, `토지분쟁`, `폐광구조` |
| 금지 | 칸 id·진실 문자열을 그대로 태그로 쓰는 것 (`대상_트롤3마리` ❌) |

### F3. `leverageTag` 매칭 — 청취 R6과 같은 규칙

```
들이대기 성공 ⇔ 재료.leverageTag == 의뢰인.keyLeverage
```

값 어휘는 `절차`·`손익`·`체면` 셋이며 `intake-system.md` R6 표가 소유한다.
**주로 조직권 항목이 갖는다** — 사람의 이해관계를 다루는 권이기 때문이다.
도감 항목은 보통 `null`이다.

### F4. 등급 기준의 표현 — **계산이 아니라 대응표**

```
criteria: [ { when: <조건 라벨>, grade: <'D'|'C'|'B'|'A'|'S'>, open: <bool> } ]
```

`open: true`면 화면에 *"A 이상"* 으로 표기된다. **이 구조를 소비하는 런타임 코드는
「표시」 하나뿐이다.** `when`/`grade`를 읽어 값을 만들어 내는 코드는 존재하지 않는다
(AC-DATA-04 정적 검사).

**유일한 기계 소비자는 빌드 시 검증기다** (아래 Edge Cases 「책과 진실의 어긋남」).
검증기는 `tools/build/` 소관이며 게임 번들에 들어가지 않는다.

## Edge Cases

### 책에 없는 대상이 나왔을 때

**유효한 상황이다. 오류가 아니다.** 플레이어는 기준 없이 판단한다 — 그리고 그것이
*"모르는 것에 등급을 매기는 기분"* 이라는 이 게임의 핵심 감정이다.

**다만 P1에서는 빈도를 통제한다:**

- **빌드 게이트**: `quest-templates.json`이 실현할 수 있는 모든 `대상` 값에 대해
  **관련 항목이 최소 1개** 존재해야 한다 (AC-DATA-02). P1에서 「책에 없는 대상」은
  **의도적으로 배치될 때만** 나온다
- **일반 원칙 항목**: 도감에 「처음 보는 것」 성격의 항목을 **최소 1개** 둔다
  (*"이름을 모르는 것에 이름을 지어 부르지 말 것. 규모를 모르면 큰 쪽으로 적는다"*).
  이것은 답이 아니라 **태도**를 준다
- **P4 이후**는 다르다 — 소문이 재료를 공급하므로 「책에 없는 것」이 정상 상태가 된다.
  그때 이 조항은 완화된다 (**Q4**)

### 기준이 서로 겹칠 때 — *"트롤 무리 + 폐광 = A? S?"*

**책은 해소하지 않는다. 합성 규칙을 두지 않는다.**

- 도감은 *"무리 → A 이상"* 이라 하고, 지역은 *"퇴로가 제한된다"* 고 한다.
  **둘을 더해 주는 코드도, 표도 없다**
- 대신 **각 권의 `intro`가 읽는 법을 한 번만 말한다** — *"땅이 일을 바꾼다"*.
  이것은 규칙이 아니라 **문장**이고, 적용은 플레이어가 한다
- `open: true`(「A 이상」)가 존재하는 이유가 정확히 이것이다 — **위로 열려 있는 자리**를
  책이 미리 만들어 둔다

> **이것이 안티 기둥 「정답이 있는 적발 퍼즐」의 시험대다**
> (`game-concept.md`). 합성표를 만드는 순간 정답이 하나로 확정되고, 이 게임은
> **표를 외우는 게임**이 된다.

### 규모가 `미확인`일 때 — *"과소평가하지 말 것"* 의 처리

- **`caution`은 지시문이지 계산이 아니다.** UI는 그것을 **표시할 뿐 아무 일도 하지
  않는다** — 등급 선택지를 좁히지도, 경고를 띄우지도, 기본값을 바꾸지도 않는다
- 칸이 `미확인`/`모호`라는 사실은 의뢰서 화면이 이미 보여 주고 있다
  (`미확인`/`모호`/`확정` 세 표시 — `commission-form.md` 소관). **책은 그 위에
  한 겹을 더 얹지 않는다**
- **낮게 적는 것은 언제나 가능하다** (기둥 5 — 막다른 길 없음). 그리고 그것이
  나중에 사람이 죽는 이유다 (기둥 6)

### 책의 기준과 실제 진실이 어긋나는 콘텐츠 → **데이터 검증 실패**

의뢰 템플릿의 진실이 *"트롤 3마리, 실제 위협도 A급"* 인데 도감이 *"무리는 C"* 라고
적혀 있으면 **그것은 콘텐츠 버그다.**

- **빌드 시 검증기**가 `criteria`의 `when`/`grade`를 템플릿의 진실 등급과 대조하고,
  어긋나면 **빌드를 실패시킨다** (AC-DATA-06)
- `open: true`인 기준은 **하한만 검사**한다 — *"A 이상"* 은 실제가 A거나 S면 통과
- **이 검사가 없으면 이 시스템 전체가 거짓말이 된다** — *"충분히 조사했다면 적절한
  등급을 판단할 수 있어야 한다"* 는 확정 문장이 데이터로 지켜지는 유일한 방법이다

> **주의: 이것은 "책이 정답을 준다"와 다르다.** 검증기는 *책이 거짓말을 하지 않는지*만
> 본다. 플레이어가 그 등급에 **도달하려면 여전히 사실을 알아내야 한다** —
> 조사가 모자라면 어느 `when`에 해당하는지 자체를 모른다.

### 항목이 하나도 로드되지 않을 때 (데이터 누락·파싱 실패)

- **게임은 완주된다.** `[일깨운다]`가 뜨지 않고 (청취 Edge Cases 「막힘」과 같은 처리),
  등급은 기준 없이 고른다
- **조용히 실패하지 않는다** — 개발 빌드에서는 콘솔 경고, 프로덕션 빌드에서는
  빌드 게이트가 이미 막았어야 한다 (AC-DATA-02)

### 같은 `hintTag`를 여러 항목이 가질 때

**허용한다.** 어느 것을 건네도 성공하며 결정론이 깨지지 않는다 (판정은 재료의 `id`가
아니라 태그 교집합으로 한다). 오히려 *"둘 다 통하네"* 는 **책이 서로 연결돼 있다는
감각**을 준다.

**단, 한 태그를 4개 이상의 항목이 공유하면 경고**한다 — 그 태그는 너무 넓어서
「아무거나 통한다」로 가고 있다 (Tuning Knobs 「태그 밀도」).

### 시세권과 첫 계약의 경합

첫 의뢰인이 **앉기 전에** 노출이 끝나야 한다. 대화 중간에 끼워 넣으면 R7의
「자동 펼침 금지」와 구별이 안 된다 — 플레이어에게는 *"지금 시세를 보라는 신호"* 로
읽힌다.

## Tuning Knobs

전부 `balance.json`의 `handbook` 절과 `handbook.json`이 소유한다.
**코드에 숫자를 박지 않는다.**

| 노브 | 위치 | 기본값 | 안전 범위 | 너무 높으면 | 너무 낮으면 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| **항목 수 (P1)** | handbook | **8~12** | 6~20 | **찾아보기 노동** — 색인이 필요해지고 아무거나 통해 일깨움이 싱겁다 | 뚫을 방법이 없다 — 무지 칸이 통째로 벽 |
| **기준의 세밀도** (항목당 `criteria` 수) | handbook | **2~3** | 1~4 | 등급 고르기가 **표 조회**가 된다 — 판단이 검색으로 바뀐다 | 기준이 뭉툭해 판단의 근거가 안 된다 (드래곤은 1개로 충분) |
| **추론 거리** (책 문안 ↔ 정답) | handbook | **2** | 1~3 | 아무도 연결하지 못한다 — 책이 장식 | **0은 금지** (정답 복제). 1은 Ctrl+F 게임에 가깝다 |
| **태그 밀도** (항목당 `hintTags`) | handbook | **2** | 1~3 | 아무 재료나 통한다 — 일깨우기 성공률이 90%를 넘는다 | 정확히 하나만 통해 무차별 대입이 유일한 전략 |
| **태그 공유 상한** (한 태그를 가진 항목 수) | balance | **3** | 2~4 | 태그가 넓어져 「아무거나 통한다」 | 재료 간 연결감이 사라진다 |
| **노출 시점** (시세권) | balance | **첫 계약 전 1회** | (범주형) | — | **없으면 R12의 「시세의 네 배」가 무의미** (필수, R8) |
| **권 수** | handbook | **4** | 3~4 | 탭이 많아 훑기가 부담 | 도감/지역이 한 권이면 읽는 순서의 힌트가 사라진다 |

### 추론 거리의 눈금 *(문안 작성자용)*

| 거리 | 책이 적는 것 | 정답 | 판정 |
| ---- | ---- | ---- | ---- |
| **0** | *"발가락이 셋이었다"* | 〃 | ❌ **금지** — 정답 복제 |
| **1** | *"발가락 셋인 자국은 트롤이다"* | *"발가락이 셋이었다"* | ⚠ 너무 가깝다 |
| **2** | *"발자국이 크고 발가락 수가 적어 다른 짐승과 갈린다"* | 〃 | ✅ **기본** |
| **3** | *"자국만 보고도 아는 사냥꾼이 있다더라"* | 〃 | ⚠ 어렵다 — 실험군 |

### 간섭

- **항목 수 ↔ 태그 밀도 ↔ 인내**: 셋이 청취 완성률(목표 45~55%)을 정한다
  (`intake-system.md` 「완성 한계의 산정」). **책만 따로 튜닝하면 안 된다**
- **기준의 세밀도 ↔ 추론 거리**: 기준을 잘게 쪼개면서 문안을 멀리 두면
  *"기준은 자세한데 어디 해당하는지 모른다"* 가 된다 — 억울함의 전형
- **`tellsDist` ↔ 조직권 항목 수**: 은폐를 늘리면 `leverageTag`를 가진 항목도 늘어야
  한다. 아니면 벽

### 추적할 지표

| 지표 | 목표 | 왜 |
| ---- | ---- | ---- |
| 책을 **막히기 전에** 연 세션 비율 | **> 60%** | 준비 자산인가 정답 메뉴인가의 유일한 정량 지표 |
| 일깨우기 성공률 | 50~70% | `intake-system.md`와 같은 목표. 책이 그 분모다 |
| 항목당 사용 횟수의 편차 | 최대:최소 **4:1 이하** | 한 항목만 계속 쓰이면 나머지는 장식 |
| 「충분히 조사한 의뢰」의 등급 정답률 | **> 80%** | 확정 문장(*"판단할 수 있어야 한다"*)의 직접 측정 |

## Acceptance Criteria

> **QA 담당자가 본문을 읽지 않고 판정할 수 있게 작성했다.**
> 유형: **(정적)** = 코드·데이터 검사 / **(실브라우저)** = 수동, BLOCKING /
> **(설계)** = 콘텐츠별 수동 검증

### A. 열람 규칙 — 「정답 메뉴 금지」 *(R7)*

- **AC-BOOK-01 (정적)** **책을 여는 코드 경로에 게임 상태를 읽는 분기가 0개다.**
  `막힘`·칸 상태·의뢰 내용·인내를 조건으로 책의 열림/탭/스크롤을 바꾸는 코드가
  존재하지 않는다.
- **AC-BOOK-02 (실브라우저)** **어떤 상황에서도 책이 자동으로 펼쳐지지 않는다.**
  다음을 모두 시도하고 책이 스스로 열리지 않음을 확인: 칸이 `막힘(무지)`가 될 때 ·
  `막힘(은폐)`가 될 때 · `[일깨운다]`가 뜰 때 · 인내가 0이 될 때 · 등급 칸에 처음
  진입할 때. **유일한 예외는 R8의 첫 계약 전 1회 노출뿐이다.**
- **AC-BOOK-03 (실브라우저 + 정적)** **탭 강조·정렬·색칠이 없다.**
  ① 어느 상황에서도 특정 권 탭이 다른 탭과 다르게 표시되지 않는다
  ② 항목 순서가 **모든 상황에서 데이터 파일 순서와 동일**하다 (정적: 정렬 함수 부재)
  ③ 항목의 색·굵기·배지가 `hintTags`/`leverageTag`/칸 상태에 따라 달라지지 않는다.
- **AC-BOOK-04 (실브라우저)** 「이 의뢰에 해당하는 기준」류의 추출·요약 표시가
  화면 어디에도 없다.
- **AC-BOOK-05 (실브라우저)** 책은 **막히지 않은 상태에서도** 언제나 열린다 —
  의뢰인 착석 전, 대화 중, 의뢰인 퇴장 후 모두.

### B. 데이터 무결성

- **AC-DATA-01 (정적)** **정답 복제 금지.** `quest-templates.json`의 모든 진실
  문자열(`어렴풋`·`확실` 사실)과 `handbook.json`의 모든 `body`·`criteria.when`·
  `caution` 문자열을 대조해 **완전 일치 쌍이 0개**다. (공백·문장부호 정규화 후 비교.)
- **AC-DATA-02 (정적, 빌드 게이트)** 템플릿이 실현할 수 있는 모든 `대상` 값에 대해
  관련 항목이 **최소 1개** 존재한다. 없으면 **빌드 실패.**
- **AC-DATA-03 (정적)** 모든 `bestiary` 항목이 `criteria` **1개 이상**과 `hintTags`
  **1개 이상**을 갖는다 (두 역할 겸임의 강제 — R2).
- **AC-DATA-04 (정적)** **`criteria`를 소비하는 코드는 표시 경로 하나뿐이다.**
  `criteria`/`grade` 필드를 읽어 값을 반환하는 함수가 `src/` 안에 존재하지 않는다
  (`tools/build/`의 빌드 검증기는 제외).
- **AC-DATA-05 (정적)** 시세 값의 소스가 **한 곳**이다 — `handbook.json`의 `rates`와
  배정 F4가 쓰는 시세가 같은 파일에서 온다.
- **AC-DATA-06 (정적, 빌드 게이트)** **책의 기준과 진실이 정합한다.** 각 템플릿의
  진실 조합에 대해 해당 항목의 `criteria`가 지정하는 등급이 실제 등급과 일치한다
  (`open: true`는 하한만 검사). 어긋나면 **빌드 실패.**
- **AC-DATA-07 (정적)** 항목 수가 예산 안이다 (P1: 8~12). 한 `hintTag`를 가진 항목이
  **4개 이상이면 경고**.
- **AC-DATA-08 (정적)** `src/domain/**`가 `handbook.json`을 import하지 않는다 (R9).

### C. 계층·결정론

- **AC-BOOK-06 (정적)** 세이브(`SaveFileV1`)에 책의 **본문·기준 문자열이 없다.**
  들어가는 것은 재료 `id`뿐이다.
- **AC-BOOK-07** 책 데이터를 통째로 비워도 **게임이 완주된다** — `[일깨운다]`가 뜨지
  않고 등급은 기준 없이 고를 수 있다 (막다른 길 없음).
- **AC-BOOK-08** 같은 재료 `id`를 건네면 **책의 표시 상태와 무관하게** 같은 판정이
  나온다 (판정은 청취 소유, 책은 표시만).

### D. 노출 시점

- **AC-BOOK-09 (실브라우저)** **첫 계약(첫 도장) 이전에 시세권이 펼쳐진 상태로
  정확히 1회 노출된다.** 첫 의뢰인 착석 **이전**이며, 그 후로는 어떤 상황에서도
  자동으로 열리지 않는다 (AC-BOOK-02와 함께 검사).
- **AC-BOOK-10 (실브라우저)** 시세권을 본 뒤, 갱단/귀족의 「시세의 네 배」 제안이
  화면상 눈에 띄게 이상한 값으로 읽힌다 (청취 R12 정합 — 수동 확인).

### E. 설계 검증 *(콘텐츠별 수동 — 자동화 불가)*

- **AC-BOOK-11 (설계)** **충분히 조사한 의뢰는 책의 기준만으로 정확한 등급에 도달
  가능하다.** P1의 모든 의뢰 템플릿에 대해, **열린 칸을 전부 `확실`로 채운 상태**에서
  책만 읽고 판단했을 때 실제 등급이 나오는지 사람이 확인한다.
  **하나라도 도달 불가능하면 그 템플릿 또는 그 항목이 결함이다.**
- **AC-BOOK-12 (설계)** 반대로, **조사가 모자란 상태에서는 등급이 확정되지 않는다.**
  같은 템플릿을 `규모=미확인`으로 두면 `criteria`의 어느 행에 해당하는지 알 수 없어야
  한다. **알 수 있으면 기준이 조사를 우회하고 있는 것이다.**

### 이 기준으로 안 잡히는 것 — GATE로 넘긴다

1. ***"아!"* 가 오는가** — 추론 거리가 맞았는지는 사람만 안다
2. **찾아보기 노동으로 느껴지는가** — AC-BOOK-01~05는 *구조*를 막을 뿐 *감각*은 못 잰다
3. **책을 실제로 읽는가** — 지표(「막히기 전 열람 60%」)는 대리 지표이지 증명이 아니다
4. **등급을 적는 것이 판단으로 느껴지는가** — 기둥 6의 정서적 토대

| # | 질문 | 왜 지금 못 정하나 | 언제 · 누가 |
| ---- | ---- | ---- | ---- |
| **Q1** | **4권의 경계 — 도감과 지역이 겹칠 때 어디에 쓰나?** *"폐광에 사는 고블린"* 은 도감인가 지역인가. 지금은 *"주어가 무엇인가"*(대상=도감 / 땅=지역)로 나눠 뒀지만, 항목이 늘면 반드시 애매한 것이 나온다. 대안: ① 주어 기준(현행) ② 중복 게재 허용 ③ 권을 3권으로 줄이고 태그로 가름 | 실제 항목 8~12개를 써 봐야 어디가 걸리는지 안다 | **P1 데이터 작성 시** · narrative-director |
| **Q2** | **항목 8~12개가 충분한가?** (`intake-system.md` **Q2**와 같은 질문 — 소유는 그쪽) 적으면 무지 칸이 통째로 안 뚫리고, 많으면 아무거나 통하면서 찾아보기 노동이 된다 | 책의 실물과 프로토 4회차가 있어야 잰다 | **P1 데이터 작성 시** · systems-designer |
| **Q3** | **노출 시점의 구체 형태** (`systems-index.md` #26 **Q5**) — R8이 *"첫 계약 전 1회"* 라는 **시점**만 못박았다. 무엇으로 노출하나: ① 첫날 책상에 펼쳐진 초기 상태 ② 전임자의 편지 ③ 첫 의뢰인 착석 전 짧은 안내. **①이 R7 위반과 가장 멀다** (아무것에도 반응하지 않으므로) | 튜토리얼 전체 설계와 묶여 있다 | **P1 UI 착수 시** · ux-designer |
| **Q4** | **책에 없는 대상을 만났을 때 — P1에서 의도적으로 배치할 것인가?** 지금은 빌드 게이트로 사실상 금지했다(AC-DATA-02). 배치하면 *"모르는 것에 등급을 매기는"* 가장 무거운 감정이 나오지만, **P1에서 그것을 주면 억울함으로 읽힐 위험**이 있다 (재료가 책뿐이라 만회 수단이 없다) | 소문(P4) 도입 여부(`intake-system.md` **Q4**)와 묶여 있다 | **P1 후반** · game-designer |
| **Q5** | **`leverageTag`를 도감 항목에도 붙일 것인가?** 지금은 조직권 전용에 가깝다. 붙이면 재료 풀이 넓어지지만 *"트롤 지식으로 관리를 압박한다"* 가 어색해질 수 있다 | 들이대기 성공률(50~75%)을 프로토로 재야 안다 | **프로토 4회차** · game-designer |
| **Q6** | **소문(P4)이 들어오면 책의 항목 수를 줄일 것인가?** 재료 공급원이 둘이 되면 8~12는 과잉일 수 있다. 그러나 책은 **기준표 역할**도 지므로 재료 관점만으로 줄이면 등급 판단이 망가진다 — **두 역할이 같은 항목이기 때문에 생기는 첫 번째 충돌**이다 | P4 스코프가 미정 | **P4 착수 전** · producer |

> **가장 무거운 것은 Q1과 Q4다.** Q1은 데이터 작성을 시작하는 순간 매 항목마다 부딪히고,
> Q4는 *"이 게임이 얼마나 가혹한가"* 를 정한다. **Q2·Q5는 프로토 4회차 한 번으로
