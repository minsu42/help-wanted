## Overview

**청취는 의뢰서의 빈칸을 대화로 채우는 시스템이다.**

창구에 앉은 의뢰인 앞에 빈 의뢰서가 있다. 칸은 **종류 · 대상 · 규모 · 장소**처럼
의뢰 종류가 정하며, 각 칸은 `미상 → 어렴풋 → 확실` 세 단계를 갖는다. 플레이어는
**칸을 짚어 묻고**, 의뢰인의 대답에 따라 그 칸이 채워지거나, 막히거나, 비워진 채
남는다.

의뢰인이 막는 방식은 둘뿐이고 **뚫는 법이 정반대다**:

| | **모른다** | **얼버무린다** |
| ---- | ---- | ---- |
| 정체 | 진짜 모른다 (무지) | 알면서 안 한다 (은폐) |
| 뚫는 법 | **일깨우기** — 내가 아는 걸 **준다** | **들이대기** — 내가 아는 걸 **무기로 쓴다** |
| 방향 | 내 정보 → 상대에게 | 상대의 사실 → 내가 지목 |
| 맞아야 하는 것 | **내용** (이 칸에 관한 것인가) | **범주** (이 사람에게 통하는가) |

**같은 자원(내가 아는 것)을 정반대 방향으로 쓴다.** 그리고 아는 게 없으면 둘 다 못
뚫는다 — 이것이 기둥 1(*아는 자가 이긴다*)의 가장 직접적인 형태다.

**막힌 칸을 비워 두고 넘어가는 것은 언제나 가능하다.** 그것이 압력 밸브이자,
나중에 사람이 죽는 이유다 (기둥 6).

### 이 시스템이 없으면

의뢰서가 처음부터 다 채워져 있거나 영원히 비어 있다. 전자면 판단할 것이 없고,
후자면 판단의 근거가 없다. 둘 다 *"내가 C급이라고 적었다"* 가 나오지 않는다.

## Player Fantasy

**플레이어는 서류를 채우는 사람이다. 그리고 그 서류가 사람을 죽인다.**

### 목표 감정 ① 유능감 — *"내가 알고 있었기 때문에 뚫었다"*

정점은 **막힌 칸이 열리는 순간**이고, 여는 열쇠는 **내가 이미 알던 것**이다.

> 관리: *"그 비탈 말입니까. …글쎄요, 조사만 해 주시면 됩니다."* (얼버무림)
> → 플레이어가 수첩에서 **「그 땅 소유를 두고 다툼이 있었다」**(책에서 읽은 것)를 꺼낸다
> → 나: *"소유 문제가 걸려 있다고 들었습니다. 보고서에 어떻게 적을까요?"*
> → 관리: *"…예. 사실은 작년부터 방앗간 쪽과…"*

**확률도 대기도 없다.** 맞는 것을 꺼냈으면 열리고, 아니면 안 열린다. 여기서 성장하는
것은 캐릭터가 아니라 **플레이어가 가진 것과 아는 것**이다.

### 목표 감정 ② 판별 — *"이 사람은 모르는 게 아니라 숨기고 있다"*

*"글쎄요…"* 와 *"그건 상관없습니다"* 는 다른 말이다. 구별할 수 있어야 **어느 열쇠를
꺼낼지** 정할 수 있고, 구별하지 못하면 자원을 헛되이 쓴다.

> **이 저장소는 이미 같은 실수를 한 번 했다** — 소문 네트워크에서 *"입을 다물었다"* 와
> *"아는 게 없다"* 를 한 문안으로 뭉갰고 버그가 됐다(`rumorNothingToTell`).
> **청취는 그 규칙을 처음부터 지고 출발한다.**

### 그 대가: 무능의 자각 — *"비워 둔 칸이 사람을 죽였다"*

빈칸은 화면에 **계속 보인다.** 숨기지 않는다. 플레이어는 *"저 칸을 비운 채 도장을
찍는다"* 는 것을 **알면서** 찍는다.

> **v1~v5는 무능을 "몰라서 못 물은 것"으로 만들려 했다** (목록을 숨기거나, 시간에
> 흘려보내거나). 재작성은 반대로 간다 — **보이는데도 못 채운다.**
> 그것이 더 무겁고, 조건도 없다.

### ⚠ 두 감정의 회수 지점은 다르다 *(불변)*

| 감정 | 언제 | 어디서 |
| ---- | ---- | ---- |
| 유능감·판별 | 칸이 열리는 즉시 | **창구 (이 시스템)** |
| 무능의 자각 | 사람이 돌아오지 않은 뒤 | **결과 대조 화면 (P2)** |

**창구는 끝까지 침묵한다.** *"당신은 규모를 묻지 않았습니다"* 를 띄우지 않는다 —
그것은 정답을 알려주는 것이고, 고칠 수 있으면 기둥 5가 무너진다.

### 이 판타지가 깨졌다는 신호

**모든 칸을 매번 다 채우게 되면** 실패다. 방어는 **하루 응대권** 하나이며,
그것이 없으면 이 시스템은 체크리스트가 된다.

## Detailed Rules

### R1. 의뢰서의 칸이 곧 슬롯이다 *(ADR-001)*

`종류`는 모든 의뢰에 있고 나머지는 종류가 정한다. **P1 조사 의뢰: 대상 · 규모 · 장소.**

| 상태 | 뜻 | 칸에 적히는 것 |
| ---- | ---- | ---- |
| `미상` | 아직 묻지 않았다 | `?` (점선 칸) |
| `어렴풋` | 대강 안다 | *대형 미상* |
| `확실` | 정확히 안다 | *트롤 3마리* |
| `막힘(무지)` | 물었으나 본인이 모른다 | *본인도 모름* |
| `막힘(은폐)` | 물었으나 말하지 않는다 | *말하지 않음* |

**`미상`과 `막힘`은 반드시 갈라 저장한다** — P2 책임 귀속의 유일한 근거다 (불변).

### R2. 칸마다 짧은 사슬이 있다

각 칸은 **2단**이다: `어렴풋` 사실 하나, `확실` 사실 하나.

```
대상:  [어렴풋] 숲에서 커다란 발자국을 봤다
       [확실 ] 사람 발만 한데 발가락이 셋이었다
```

> **v3~v5의 12노드 DAG를 버렸다.** 그물의 가치(가지 간 의존)는 **일깨우기·들이대기의
> 재료 관계**가 대신 진다 — 저작량이 1/3로 줄고 플레이어에게 구조가 보인다.

### R3. 표면 진술은 무료다

의뢰인은 앉자마자 **자기가 하고 싶은 말**을 한다. 보통 `종류`와 한두 칸의 `어렴풋`이
여기서 채워진다. **응대권을 쓰지 않는다.**

### R4. 묻는다 — 칸을 짚는 것이 곧 질문이다

빈칸(또는 `어렴풋` 칸)을 누르면 그 칸을 묻는다. **응대권 1.**
대답은 셋 중 하나이며, 칸의 다음 단계 `L`에 대해 판정한다:

```
① knows[칸] < L                  →  모른다      (일깨우기 가능)
② tells[칸] < L                  →  얼버무린다  (들이대기 가능)
③ 그 외                          →  말한다      (칸이 L로 채워진다)
```

**①이 ②보다 위다 — 모르는 것은 숨길 수도 없다.** (v4의 결정 승계)

### R5. 일깨운다 — 내가 아는 것을 **준다**

`막힘(무지)` 칸에만 뜬다. 수첩에서 **밖에서 온 사실** 하나를 골라 건넨다. **응대권 1.**

- **맞는 조건: 내용이다.** 재료의 `hintTags`와 칸의 `hintTags`가 겹쳐야 한다
- 성공: `knows[칸]`이 그 단계로 올라가고 **즉시 말한다**
- 실패: 아무것도 안 열린다. *"…그게 이 일과 무슨 상관인지…"*

> **재료는 밖에서 온 것뿐이다** — 길드마스터북(P1) · 소문(P4). **이 대화에서 얻은
> 사실은 일깨움에 쓸 수 없다.** 그래야 *"캐물으면 다 나온다"* 가 되지 않고,
> **무지 축이 살아 있다.**

### R6. 들이댄다 — 내가 아는 것을 **무기로 쓴다**

`막힘(은폐)` 칸에만 뜬다. 수첩에서 사실 하나를 꺼내 지목한다. **응대권 1.**

- **맞는 조건: 범주다.** 재료의 `leverageTag`가 의뢰인의 `keyLeverage`와 같아야 한다
- 성공: `tells[칸]`이 올라가고 **즉시 말한다**
- 실패: 문이 닫히지만 **재시도할 수 있다**
- **재료는 어디서 온 것이든 된다** — 이 대화에서 얻은 사실도 무기가 된다

| 직업 | `keyLeverage` | 무엇이 아픈가 |
| ---- | ---- | ---- |
| 관리 | **절차** | 기록·고지 의무·관할 |
| 상인 | **손익** | 거래·값·손실 |
| 영주·귀족 | **체면** | 평판·가문·소문 |
| 주민 | (은폐가 거의 없다) | — |
| 갱단 | **없음** | 어떤 것으로도 안 열린다 |

> **왜 조건이 다른가**: 일깨우기는 *"무엇에 대한 것인가"*, 들이대기는 *"누구에게
> 통하는가"* 다. **전자는 칸을 읽는 일이고 후자는 사람을 읽는 일이다.**

### R7. 넘어간다 — 언제나 가능하고 공짜다

칸을 비운 채 다음으로 간다. **막다른 길은 없다** (기둥 5). 응대권이 0이어도
보수 합의·도장은 계속 가능하다.

### R8. 기색 — 얼버무림에는 신호가 있다

`막힘(은폐)`이 발생할 때 의뢰인이 티를 낸다 (말끝 흐림·시선 회피). **창의 표정**과
대사로 전달된다. **무지와 은폐가 다르게 들리고 다르게 보여야 한다** —
`rumorNothingToTell` 사고의 재발 방지선.

### R9. 티키타카 — 한 칸 안에서 여러 번 오간다

한 번 묻고 끝이 아니다. 대답 뒤에 **상황이 주는 행동**이 뜬다:

| 칸의 상태 | 뜨는 것 |
| ---- | ---- |
| 미상 | **[묻는다]** |
| 어렴풋 | **[더 캐묻는다]** |
| 막힘(무지) | **[일깨운다]** — 줄 게 있을 때만 |
| 막힘(은폐) | **[들이댄다]** — 꺼낼 게 있을 때만 |
| 언제나 | **[넘어간다]** |

**보통 1~2개만 뜬다.** 그래서 *"셋 중 뭘 고르지"* 가 아니라 ***"이 칸에 더 쓸까,
비워 두고 넘어갈까"*** 가 된다 — **그것이 이 게임의 진짜 결정이다.**

그리고 의뢰인은 대답에 **곁가지 말**을 붙인다 (불안·사정·부탁). 정보가 아니라
**사람이 드러나는 자리**이며, 대화의 살이 여기 있다.

### R10. 판정은 순수 함수다

상태 전이의 입력은 **플레이어가 누른 것**이다 — `(칸, 행동, 재료?)`. 같은 입력이면
같은 전이다. 무작위성은 **의뢰 생성 시점**(F1)에만 있다. `src/domain/intake.ts`는
`Rng`도 `fetch`도 import하지 않는다.

### R11. LLM은 **생성만** 한다

| 소관 | |
| ---- | ---- |
| 의뢰인의 대사 | ✅ |
| **플레이어의 대사** — 행동을 문장으로 | ✅ |
| 이해·분류 | ❌ **없다** |

**플레이어의 자유 텍스트를 해석하는 경로가 없으므로 Portopia형 실패가 구조적으로
불가능하다.** 프롬프트에는 **공개가 허가된 내용만** 싣는다 (ADR-003 D6) — 미공개
칸은 `topic`(물어볼 거리의 이름)으로만 표현하고 `fact`를 주지 않는다.

> **`topic`이 없으면 무슨 일이 일어나는가**: 프로토 3회차에서 의뢰인이 **묻지도 않은
> 사실을 먼저 말했다.** 후보에 `fact`를 실었기 때문이다.
>
> **역할을 섞지 않는 것도 필수 요구다** — 같은 프로토에서 의뢰인이 후보 목록을 자기
> 궁금증으로 읽어 길드마스터에게 되물었다. **나쁜 예·좋은 예를 함께 줘야 막힌다**
> (*"암시로는 안 막힌다"*).

**폴백**: LLM 장애 시 고정 문안으로 대사를 댄다. **판정은 영향을 받지 않으므로
폴백만으로 완주 가능하다** (ADR-003 D5).

### R12. 보수는 의뢰인이 먼저 부른다 *(v4에서 승계, 불변)*

청취를 마치면 의뢰인이 **선제 보수를 제안**한다. 제안액 자체가 정보다.
판정은 숨은 지갑 `{cap, easy, counter}`가 소유한다 (F4). **제시액 수락이 기본
동선이고 역제시는 선택이다.**

## Formulas

### F1. 의뢰 실현 — **여기서만 RNG를 쓴다**

```
knows[칸] = weightedPick(rng, occupation.knowsDist)
tells[칸] = weightedPick(rng, occupation.tellsDist)
```

| 직업 | `knowsDist` `[none,vague,certain]` | `tellsDist` | 성격 |
| ---- | ---- | ---- | ---- |
| 주민 | `[15,55,30]` | `[0,5,95]` | 정밀도 낮음 · 은폐 없음 |
| 상인 | `[10,35,55]` | `[5,20,75]` | 균형 |
| 관리 | `[5,25,70]` | `[10,35,55]` | 안다. 절차상 일부만 말한다 |
| 갱단 | `[0,5,95]` | `[70,25,5]` | 무지 0 · 은폐 최대 |
| 영주·귀족 | `[5,20,75]` | `[45,35,20]` | 안다. 곤란한 것만 감춘다 |

**`종류` 클램프**: `knows[종류]`·`tells[종류]`를 최소 `vague`로 올린다 — 갱단도 자기
의뢰가 무슨 종류인지는 말한다.

**RNG 소비 순서 고정**: 칸은 스키마 순서(`종류 → 대상 → 규모 → 장소 → 기한 → 경로`).
데이터 배열 순서에 의존하면 밸런스 수정이 회귀 테스트를 깨뜨린다.

### F2. 응답 판정 *(R4)*

```
respond(칸 s, 다음 단계 L) =
  knows[s] < L  →  '모른다'
  tells[s] < L  →  '얼버무린다'
  그 외          →  '말한다'
```
**경계**: `L = vague`(1) 또는 `certain`(2). `none = 0`.

### F3. 정보 충실도 (completeness)

```
completeness = Σ(w[칸] × score(state[칸])) / Σ(w[칸])
score: 확실 1.0 / 어렴풋 0.5 / 막힘 0.0 / 미상 0.0
```

`w[칸]`은 종류별로 정한다 (조사: 대상 3 / 규모 2 / 장소 1). 분모 0이면 1.0 고정,
`종류`는 가중합에서 제외. **`막힘`과 `미상`이 둘 다 0점인 것은 의도**다 — 정보량은
같고, 차이는 **책임 귀속**에만 쓴다 (P2).

소비처 둘: **파견 판정**(위험도 추정 오차) · **지원 판정**(`assignment-dispatch.md` F4).

### F4. 지갑 판정 *(v4에서 승계)*

```
a ≤ easy        → 수락 (무난)
easy < a ≤ cap  → 수락 (부담 — 연기에 부담이 실린다)
a > cap         → 거절 + counter 역제안
```
**불변식 (빌드 게이트)**: `0 < easy < counter ≤ cap`. `a`는 정수.
`cap = round(시세 × walletMult[직업])`.

| 직업 | `walletMult` | |
| ---- | ---- | ---- |
| 주민 | 0.5 ~ 0.9 | 시세를 못 채운다 |
| 상인 | 0.9 ~ 1.4 | 시세를 안다 |
| 관리 | 1.0 ~ 1.5 | 공금이라 시세대로 |
| 갱단 | **1.5 ~ 4.0** | 후하게 부르는 것 자체가 수상하다 |
| 영주·귀족 | **2.0 ~ 5.0** | 돈이 문제가 아니다 |

**배수 3 이상은 갱단·귀족뿐**이므로 *"시세의 네 배"* 가 직업을 말해 준다.
**역제시는 첫 회만 무료**, 2회차부터 응대권 1.

## Edge Cases

### 응대권
- **0이 되면**: 묻기·일깨우기·들이대기가 잠긴다. **보수 합의·의뢰서·도장은 계속
  가능하다** (기둥 5).
- **1 남았을 때 묻으면**: 정상 처리 후 잠근다. 소비 전에 미리 막지 않는다.
- **LLM 장애**: **판정은 이미 끝나 있다.** 대사만 폴백으로 나온다. 응대권 복원 같은
  보정이 필요 없다.

### 막힘
- **모른다고 한 칸에 줄 재료가 하나도 없으면**: `[일깨운다]`가 **뜨지 않는다.**
  넘어가는 것만 남는다. **막다른 길이 아니다** — 다른 칸과 계약은 그대로 진행된다.
- **틀린 재료를 줬을 때**: 응대권을 쓰고 아무것도 안 열린다. **재시도 가능.**
- **갱단(`keyLeverage=없음`)**: 어떤 무기로도 안 열린다. **그것이 정보다** —
  불완전한 정보로 수임 여부를 정하는 것이 그 의뢰의 진짜 결정이 된다.

### 축퇴 의뢰
- **전 칸이 `none`으로 실현되면**: 표면 진술만 나오고 모든 칸이 `막힘(무지)`가 된다.
  **유효한 상태이며 오류가 아니다.** 다만 깨진 데이터와 화면상 구별되어야 하므로
  ① 표면 진술은 반드시 나오고 ② 첫 물음이 *"글쎄요…"* 로 응답한다.
- 주민 기준 확률 `0.15³ ≈ 0.3%` — 300판에 한 번이면 반드시 나온다.

### 채널 중복
- 소문이 이미 채운 칸을 다시 물으면: 상태 불변, 응대권 −1. **의도된 함정** —
  아는 것을 기억할 책임은 플레이어에게 있다.

### 같은 의뢰인의 재방문
- 인물 신상은 알려진 것으로 취급하되, **이번 계약의 `knows`/`tells`는 새로 실현된다.**
  *"예전에 다 물어봤으니 자동 채움"* 은 오구현이다.
- 연기 프롬프트의 대화 이력은 **계약 단위로 초기화**한다.

### 결정론
- **재현 키는 `(칸, 행동, 재료?)` 시퀀스다.** LLM이 판정 경로에 없으므로 그대로
  결정론이다.
- **저장은 최종 상태 직접 저장**이다 (ADR-002 D2). 대화 이력·연기 대사는 저장하지
  않는다 (ADR-002 **D9** — 휘발 상태).
- **세이브에 LLM이 만든 값이 하나도 없다.** 모델을 바꿔도 과거 세이브가 안 흔들린다.

## Tuning Knobs

전부 `balance.json`의 `intake` 절과 `quest-templates.json`이 소유한다.
**코드에 숫자를 박지 않는다.**

| 노브 | 위치 | 기본값 | 안전 범위 | 너무 높으면 | 너무 낮으면 |
| ---- | ---- | ---- | ---- | ---- | ---- |
| `knowsDist[직업]` | balance | F1 표 | `none` 0~70 | 무지투성이 — 청취가 헛수고 | 모두 백과사전 |
| `tellsDist[직업]` | balance | F1 표 | `none` 0~80 | 은폐투성이 — 재료 없으면 벽 | 은폐 축이 논다 |
| `keyLeverage[직업]` | balance | R6 표 | (범주형) | **직업마다 달라야 한다** | 한 무기가 지배 |
| **하루 응대권** | balance | **9** = 의뢰인 3 × 3 | 의뢰인×3의 0.8~1.2배 | 전부 채워져 세금이 된다 | 표면만 듣고 끝난다 |
| 의뢰당 칸 수 | templates | **3** (종류 외) | 2~5 | 한 건이 길어 처리량 압박 과다 | 판단할 것이 없다 |
| 책의 항목 수 (P1) | handbook | **8~12** | 6~20 | 아무거나 통해 일깨움이 싱겁다 | 뚫을 방법이 없다 |
| `w[칸]` | templates | 대상3/규모2/장소1 | 최대:최소 **3:1 이하** | 가중치표가 공략집 | 선택이 무의미 |
| 지갑 계수 | balance | 0.7 / 0.85 | **불변식만** (F4) | 부담 구간 소멸 | 수락이 기본 동선이 아니게 됨 |

#### 하루 응대권의 산정

```
필요 = 의뢰인 3 × (칸 3 × 2단) = 18       ← 전부 채우려면
예산 = 9                                  ← 절반
```

**전 의뢰 완전 완성은 불가능하다.** 그것이 *"누구의 무엇을 채우고 무엇을 비울까"* 라는
이 게임의 결정이다. 일깨우기·들이대기가 각 1칸이므로 **막힌 칸은 더 비싸다** —
막힌 칸을 뚫을지 다른 칸을 채울지가 곧 판단이다.

#### 간섭

- **응대권 ↔ 칸 수**: 둘이 완성률을 정한다. 목표 **완성률 45~55%**
- **`tellsDist` ↔ 책의 항목 수**: 은폐를 늘리면 재료도 늘려야 한다. 아니면 벽
- **`keyLeverage` 다양성 ↔ 은폐 빈도**: 은폐가 잦을수록 무기 범주가 갈려야 한다

#### 추적할 지표

| 지표 | 목표 | 왜 |
| ---- | ---- | ---- |
| 완성률 (채워진 칸 ÷ 전체) | **45~55%** | 100%면 판단이 없고, 20%면 노력이 무의미 |
| 일깨우기 성공률 | **50~70%** | 100%면 고를 것이 없고, 낮으면 무차별 대입 |
| 들이대기 성공률 | **50~75%** | 〃 |
| 막힘 비율 (주민) | 15% 내외 | 넘으면 헛수고로 느껴진다 |
| `막힘` 중 뚫은 비율 | **30~50%** | 0%면 재료가 없고, 100%면 막힘이 장식 |

## Visual/Audio Requirements

> **레지스터**: 창구는 **창**(상단, 픽셀 인물 — 아트 바이블 §5.9)과 **종이**(하단,
> 의뢰서 — §5.1~§5.8) 둘을 갖는다. **`--seal`(붉은 봉랍)은 한 번도 등장하지 않는다.**

### V1. 의뢰서가 화면의 중심이자 조작 대상이다

**칸을 누르는 것이 곧 행동**이므로 의뢰서는 결과 표시판이 아니라 **인터페이스**다.

- 누를 수 있는 칸은 정적 산문과 **구별되어야 한다** (방법은 art-director 위임)
- **체크박스·진행률 바 금지** (불변) — 서류이지 과제 목록이 아니다

### V2. 칸의 다섯 상태를 색 없이 가른다 *(v1~v5 승계)*

| 상태 | 시각 |
| ---- | ---- |
| `미상` | **점선 칸, 잉크 없음** |
| `막힘(무지)` | 실선 칸 + **둥근 얼룩** (스며들다 만 흔적) |
| `막힘(은폐)` | 실선 칸 + **짧고 곧은 사선** (눌러 찍은 자국) |
| `어렴풋` | 자간 넓게, 기본 굵기 |
| `확실` | 자간 기본, 한 단계 굵게 |

**가장 중요한 구별은 `미상` vs `막힘`** — 빈칸이냐 잉크가 묻었냐. 문장을 안 읽고
훑어도 갈린다. **색에 의존하지 않으므로 색맹 모드에서도 유지된다.**

### V3. 창의 표정 — 기색이 여기 산다

| 표정 | 언제 | 무엇이 |
| ---- | ---- | ---- |
| 평상 | 기본 | — |
| **기색** | 얼버무리기 **직전** | 눈 — 시선이 비껴간다 |
| 무지 | 모른다고 할 때 | 눈썹 — 미안한 듯 처짐 |
| 은폐 | 얼버무릴 때 | 입 — 다물린 직선 |

**기색만이 대사보다 앞선다.** 그리고 *"뭔가 있다"* 까지만 말하고 **사유는 말하지
않는다.** 38px 얼굴에서 눈은 2×2픽셀이므로 **고개 각도를 함께 쓴다** (§5.9).

### V4. 소리

`모호`/`확실`에 다른 소리를 주지 않는다 — **"얻었다 vs 못 얻었다"만** 가르고 세부는
시각에 맡긴다. 무지·은폐에 다른 스팅어를 주지 않는다 (문장보다 먼저 도착해 텔레그래핑).

| 파일 | 발생 | 상한 |
| ---- | ---- | ---- |
| `sfx_pen-scratch_fill.ogg` | 칸이 채워질 때 | ~15–25KB |
| `sfx_ink-blot_block.ogg` | 칸이 막힐 때 | ~10–15KB |
| `sfx_page-turn_notebook.ogg` | 수첩을 열 때 | ~10–15KB |

초기 로드에서 제외 (지연 로드). **BGM 없음** — P8 재검토.

> **v5가 받은 판정에 대한 처방이 이 한 줄이다.**

**시간 압박 없음** — 선택지가 사라지지 않는다. 압박은 하루 응대권 하나다.

| **길드마스터북** | 도감·시세·지역·조직 | 일깨우기 · 들이대기 |
| **소문** (P4) | 밖에서 사 온 사실 | 일깨우기 · 들이대기 |

- **유효/무효를 미리 구별하지 않는다.** `hintTags`·`leverageTag`로 정렬·색칠 금지 —
  **무엇이 통할지 아는 것이 곧 퍼즐이다**
- 물러나기는 **비용 0**

### U4. 실패를 실패처럼 그리지 않는다

붉은 테두리·흔들림·오류 문구·실패음 금지. **의뢰인의 자연스러운 대사**로 응답한다.
기계적 신호는 **응대권(티켓)이 줄어드는 것** 하나뿐이다.

### U5. 접근성

키보드 단독 경로 · 색 비의존 · 점멸 금지 · 1280×720 실측.
`aria-live="polite"`로 **의뢰인 응답 도착**과 **응대권 변화**를 알린다.
**텍스트 입력이 없으므로 IME·포커스·캐럿 문제가 존재하지 않는다.**

## Acceptance Criteria

> GDD 본문을 읽지 않은 QA 담당자도 판정할 수 있게 작성했다.
> LLM이 낀 경로는 **게이트웨이를 목으로 갈아끼워** 결정론적으로 검증한다.

### A. 핵심 규칙

- **AC-R3-01** 착석 직후: 표면 진술이 나오고 응대권은 초기값 그대로다.
- **AC-R4-01** 판정 3분기: `knows<L`이면 「모른다」, `tells<L`이면 「얼버무린다」,
  둘 다 아니면 「말한다」. **`knows`가 우선**함을 둘 다 낮은 케이스로 확인한다.
- **AC-R4-02** 묻기 1회 = 응대권 −1.
- **AC-R5-01** `hintTags`가 겹치는 재료로 일깨우면 칸이 채워진다. 겹치지 않으면
  아무것도 안 열리고 응대권만 준다.
- **AC-R5-02** **이 대화에서 얻은 사실은 일깨우기 목록에 나타나지 않는다** (정적 검사).
- **AC-R6-01** `leverageTag == keyLeverage`인 재료로 들이대면 칸이 채워진다.
  틀리면 `막힘(은폐)` 유지 + **재시도 가능**.
- **AC-R6-02** `keyLeverage=없음`(갱단)은 **가질 수 있는 모든 재료**로 시도해도
  열리지 않는다.
- **AC-R7-01** 넘어가기는 언제나 가능하고 응대권을 쓰지 않는다.
- **AC-R9-01** 상황별로 뜨는 행동이 R9 표와 일치한다. **줄 재료가 없으면
  `[일깨운다]`가 뜨지 않는다.**
- **AC-R10-01** 같은 `(칸, 행동, 재료)` 시퀀스는 **LLM 유무와 무관하게** 같은 칸
  상태를 만든다.
- **AC-R11-01** 연기·대사 생성 요청 페이로드에 **미공개 칸의 `fact`가 없다**
  (`topic`만 있다).
- **AC-R11-02** 게이트웨이를 완전히 차단해도 **판정·응대권 회계가 바이트 단위로
  동일**하고, 달라지는 것은 대사 문자열뿐이다.
- **AC-R12-01** 의뢰인의 선제 제안액을 그대로 수락하면 항상 성공한다.

### B. 수식

- **AC-F1-01** 직업별 `knows`/`tells` 실현이 F1 표와 **버킷별 ±3×SE** 이내 (몬테카를로).
- **AC-F1-02** 갱단의 `종류`가 `none`으로 실현돼도 클램프가 `vague`로 올린다.
- **AC-F1-03** 템플릿의 칸 배열 순서를 바꿔도 같은 시드면 같은 실현 (RNG 순서 고정).
- **AC-F3-01** 워크드 예제: 대상3 확실 / 규모2 어렴풋 / 장소1 미상 → **0.667**.
- **AC-F3-02** 종류 외 칸 0개 → `completeness = 1.0`.
- **AC-F4-01** 지갑 경계: `easy` 무난 / `easy+1` 부담 / `cap` 부담 / `cap+1` 거절+역제안.
- **AC-F4-02** *(빌드 게이트)* `0 < easy < counter ≤ cap`을 깨는 계수 조합은 빌드 실패.
- **AC-F4-03** 배수 3 이상은 **갱단·귀족에서만** 나온다 (몬테카를로).

### C. Edge Cases

- **AC-EDGE-01** 응대권 1에서 묻기 → 정상 처리 후 잠금. 마지막 물음이 씹히지 않는다.
- **AC-EDGE-02** 응대권 0에서도 **보수 합의·의뢰서·도장이 가능**하다.
- **AC-EDGE-03** 게이트웨이 타임아웃 → 판정은 이미 확정, 폴백 문안으로 대사. **복원
  로직이 존재하지 않는다.**
- **AC-EDGE-04** 전 칸 `none` 실현(축퇴) → 표면 진술 정상, 첫 물음이 「모른다」로
  응답, 계약 진행 가능.
- **AC-EDGE-05** 소문이 이미 채운 칸을 다시 물으면 상태 불변 + 응대권 −1 (함정 유지).

### D. 결정론·지속성

- **AC-DET-01** 같은 시드 + 같은 템플릿 → 같은 `knows`/`tells` 실현.
- **AC-DET-02** `SaveFileV1`에 **대화 이력·연기 대사 필드가 없다** (정적 검사,
  ADR-002 D9).
- **AC-DET-03** 게이트웨이 목을 **서로 다른 두 응답 집합**으로 바꿔도 같은 입력
  시퀀스면 **세이브 바이트가 동일**하다.
- **AC-DET-04** `미상`과 `막힘(+사유)`이 직렬화 왕복에서 구별 보존된다.

### E. 화면 배선 (**수동-BLOCKING** — 이 저장소의 2회 사고 재발 방지)

- **AC-UI-01** 실브라우저: 칸 클릭 → 응답 → 칸 반영 → 다음 행동 표시가 완주된다.
- **AC-UI-02** 실브라우저: 일깨우기·들이대기가 수첩을 열고 재료 선택 후 **내 대사가
  화면에 나온다.**
- **AC-UI-03** 실브라우저: 게이트웨이 차단 상태로 **청취 → 보수 → 도장이 완주된다.**
- **AC-UI-04** *(정적)* 칸 표시 DOM에 `<input type=checkbox>`·`<progress>`가 없다.
- **AC-UI-05** *(정적)* 수첩이 `hintTags`·`leverageTag`로 정렬·색칠하지 않는다.
- **AC-UI-06** 실브라우저: **텍스트 입력 요소가 화면에 0개**다.
- **AC-UI-07** 실브라우저: 기색 표정이 **얼버무림 대사보다 먼저** 나타난다.

### 이 기준으로 안 잡히는 것 — GATE로 넘긴다

1. **유능감** — *"내가 알고 있었기 때문에 뚫었다"* 는 계산으로 검증 불가
2. **티키타카로 느껴지는가** — 한 칸 안에서 여러 번 오가는 것이 대화인지 절차인지
3. **판별** — 무지와 은폐를 실제로 구별해 내는가 (목표: 3회차 안에 학습)
4. **비워 둔 칸이 무겁게 느껴지는가** — 기둥 6의 감정적 토대
5. **일깨우기가 *"아!"* 를 주는가** — 재료가 맞았을 때의 쾌감
