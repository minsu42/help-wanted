## Overview

게시판에 붙은 의뢰서가 모험가와 만나 파견 결과가 되기까지를 다룬다.
흐름: **게시 (게시 보수 명기) → 아침 지원 (무리 단위) → 배정 (선택·끼워넣기·초빙) →
파견 판정 (전력 + 대비 − 위험) → 결산.** 의뢰서에 **자동 기록된 사실**이 요구 태그와
대비를 만들고, 게시 보수와 **내가 매긴 등급**이 지원의 질을 정하며, **판정은 전부
규칙이 정한다** — LLM은 판정 경로에 없다 (R9).

**두 갈래를 혼동하지 않는다** *(2026-08-10 확정)*: **내가 적은 등급은 「누가 가는가」를
바꾸고**(F4), **「누가 돌아오는가」는 `P + C − T`가 정한다**(F3).

## Player Fantasy

**"내가 쓴 종이가 사람을 움직인다."** 잘 쓴 의뢰서에 좋은 무리가 붙는 만족, 짜게 매긴
보수에 신출내기만 기웃거리는 불안, 지원자 명단을 놓고 "지금 줄까, 내일을 기다릴까"
망설이는 긴장(보류의 긴장), 끼워넣기를 거절당하는 머쓱함, 그리고 유찰된 의뢰서 앞에서
보수를 올릴지 다시 쓸지 고민하는 접수원의 아침. 실패의 감정은 결산이 아니라 **여기서
이미 시작된다** — 요른만 지원한 명단을 보는 순간, 플레이어는 자기가 쓴 의뢰서를 다시 읽는다.

## Detailed Rules

**R1. 로스터는 개인 10±2명이다.** 각자 이름·초상·전투력·특기 태그 1~2개·무리 소속을
갖는다. 얼굴이 기억되는 규모(시장조사: 8~16이 한계)를 넘기지 않는다.

**R2. 지원은 무리 단위다.** 무리(2~4인, 리더 중심)가 게시물마다 `지원 | 조건부 | 무시`를
정한다. **판정은 규칙이다**: 무리의 성향 파라미터(최소 기대 보수 배율, 정보 요구치,
위험 허용치) × 게시물(게시 보수/시세, 정보 충실도, 표기 위험도)로 결정된다(F4).
LLM은 결정된 판정에 **코멘트만 연기**한다 — 셀린의 비웃음은 대사지 판정이 아니다.

**R3. 게시 보수는 의뢰비와 분리된다.** 마진 = 의뢰비 − 게시 보수. 게시 보수가 지원
판정(F4)의 주 입력이다. **역마진(게시 보수 > 의뢰비)을 금지하지 않는다** — 가난한
의뢰인의 위험한 의뢰에 길드가 돈을 얹는 것은 유효한 선택이다(자선 또는 평판 투자).

> **경계 명시 — 게시 보수는 의뢰서의 칸이 아니다** *(2026-08-10)*.
> `commission-form.md`는 게시 보수를 **의뢰서 칸에서 뺐다** — 그 문서에서 플레이어가
> 적는 것은 **위험도 등급 하나**다. 게시 보수는 **의뢰서를 쓴 다음, 게시 단계에서
> 정하는 값**이며 **이 문서 R3이 소유한다.** 재게시할 때 보수만 올리는 것(R8 출구
> ①)이 성립하는 이유가 이것이다 — **의뢰서를 건드리지 않고 값만 바꾼다.**

**R4. 요구 태그는 의뢰서에 자동 기록된 사실에서만 파생된다** *(2026-08-10 재작성)*.
~~"야행성"이라 적으면 게시물에 `밤눈` 요구가 뜬다.~~ → **플레이어가 적는 자유 서술은
없다.** 칸(`종류·대상·규모·장소·기한·경로·특징 및 약점`)이 청취로 `확정`되면 그 사실에
매인 요구 태그가 뜨고, `모호`·`미확인`이면 뜨지 않는다.

**적히지 않은 진실은 요구를 만들지 않으며, 위기는 그대로 온다.** 청취의 품질이
매칭의 품질이다 — **기둥 6의 매칭 버전**이다.

> **자유 서술이 빠지면서 이 규칙은 오히려 깨끗해졌다** *(2026-08-10)*.
> 예전 판에서는 *"내가 「야행성」이라고 타이핑했는가"* 가 관문이었고, 진실을 알면서도
> 안 적는 것과 몰라서 못 적는 것이 같은 결과로 뭉갰다. 지금 인과는 한 줄이다:
>
> **안 물어본 것이 안 적히고, 안 적힌 것이 준비를 못 만든다.**
>
> 플레이어가 요구 태그를 조작할 방법은 **없다** — 유일한 조작 경로는 **청취를 더
> 잘하는 것**이다. `특징 및 약점` 칸(*"햇빛을 꺼린다"*)이 요구 태그의 가장 큰
> 공급원이며, 그 칸을 뚫었는가가 파견의 대비 `C`와 요구 태그를 **동시에** 가른다.

**R5. 특기 태그는 확률 보정이 아니라 사건 분기다.** 파견 이벤트 테이블에서 태그
보유 여부가 위기의 형태를 바꾼다 — `밤눈` 보유: "울음소리로 위치를 특정했다" /
미보유: "어둠 속에서 조우했다". 시장조사 체크리스트 1번: +10% 보정은 만들지 않는다.

**R6. 끼워넣기 제안은 거부될 수 있다.** 개인 지원자를 무리에 추가 제안할 수 있으나
무리·개인의 관계 값이 거부를 낳는다 ("그놈과는 안 갑니다"). 거부 사유는 표시된다 —
막다른 길이 아니라 관계 정보의 공개다.

**R7. 초빙은 웃돈 + 지명이다.** 지원하지 않은 무리를 시세 ×1.5~2.0의 게시 보수로
지명해 부를 수 있다. 관계(기용 이력)가 좋으면 배율이 내려간다 — 웃돈과 관계 레버리지
둘을 갖춰 "상점 구매"로 전락하지 않게 한다 (시장조사 체크리스트 7).

**R8. 유찰은 상태이지 실패가 아니다.** 지원 0 또는 미배정 게시물의 출구는 셋:
① 게시 보수 인상 재게시 ② **의뢰서 재작성 재게시** (정보 보강 → 요구 태그 노출 →
지원 유인) ③ 초빙. 기한(의뢰별 2~4일) 만료 시 의뢰인 실망 — 평판 하락과 의뢰 철회.

**R9. 파견 판정은 순수 함수이며 LLM은 판정 경로에 없다** (F3) *(2026-08-10 재작성)*.

~~LLM이 판정에 관여하는 유일한 지점은 **대비 추출**(의뢰서 vs 진실 항목별
`덮음|부분|비어있음`, 구조화 출력)이며, 추출 결과는 저장되어 재현 가능하다
(ADR-003 D4의 분류와 같은 지위).~~ → **전부 폐기.** 근거로 삼았던 **ADR-003 D4는
폐기됐고**, 확정 설계가 **자유 서술과 LLM 대비 추출을 함께 삭제**했다. 읽을 자유
서술이 없으므로 추출할 것도 없다.

- **대비 `C`는 규칙이 직접 계산한다** — 자동 기록된 칸의 상태(`확정`/`모호`/`미확인`)를
  세는 일이고, 문장 이해가 필요 없다 (F2)
- **판정 경로 전체가 순수 함수다**: `P`(F1) · `C`(F2) · `T`(템플릿 고정값) · `D = P + C − T`(F3) ·
  지원 판정(F4). 어디에도 `fetch`가 없다
- **LLM의 소관은 결과 서술과 코멘트뿐이며, 결과를 바꿀 수 없다.** 순서가 강제된다 —
  **판정이 먼저 확정되고, 그 확정값을 입력으로 서술이 생성된다**
- **게이트웨이를 완전히 차단해도 결과·인명·로그가 바이트 단위로 동일**하다.
  달라지는 것은 문장뿐이다 (AC-AD-05)

> **이 문서에서 LLM 의존이 사라진 것은 축소가 아니라 정합**이다. 청취
> (`intake-system.md` R11)는 처음부터 *"LLM은 생성만"* 이었는데, 이 문서만 판정
> 경로에 LLM을 두고 있었다. **두 문서가 이제 같은 규약 위에 선다.**

**R10. 부상·피로가 순환을 강제한다.** 파견에서 다친 모험가는 휴식일 동안 지원하지
않는다. 순환 장치 없이는 상위 무리만 쓰게 된다는 것이 시장의 정설이다 (XCOM 2).

**R11. 정보는 부분 공개다.** 모험가 특기는 기용 이력·홀(P4+)에서 아는 만큼만 보인다
(신입은 `?`). 판정 수식·위협도는 비공개이며, 무리의 지원 코멘트가 반쯤의 힌트다
(Dispatch 원칙: 전부 보이면 계산기, 전부 숨기면 도박).
**실제 위험도 `T`도 비공개이며 파견 후에 공개된다** *(2026-08-10)* — F3의 세 등급 표.

**R12. 의뢰 템플릿은 `T`·진실·알아낼 수 있는 사실·책의 기준 넷을 함께 갖는다.**
데이터 무결성 규칙이며 **빌드 게이트다.** 전문은 F3 아래에 있다 (`T` 값과 한 몸이라
그쪽에 둔다).

## Formulas

모든 수치는 `balance.json`으로 격리한다 (「넘을 수 없는 제약」 3번).

**F1. 무리 전력** `P = Σ(개인 전투력 s_i) × 호흡 h`
- `s_i ∈ 1..4` (신출내기 1, 베테랑 3, 정예 4), `h ∈ 0.9..1.1` (함께한 파견 수로 성장 — P6에서 확장)
- 예: 요른의 떠돌이들 = (1+1) × 1.0 = 2 → 스케일 조정 후 프로토 값과 정합시킨다

**F2. 대비** `C = 4 × Σ(cov_j) / n` *(2026-08-10 재작성 — 규칙 계산)*

**모험가가 의뢰서를 읽고 스스로 준비한다.** 길드마스터는 전술을 지정하지 않는다 —
적힌 사실이 충실할수록 그들이 알아서 잘 준비한다. 따라서 **`C`는 의뢰서에 자동
기록된 사실의 충실도**이며, **규칙 계산이고 LLM이 없다.**

```
C = 4 × Σ(cov_j) / n          C ∈ 0..4

cov_j — 그 의뢰의 진실 항목 j를 덮는 칸의 상태 점수
        확정   1.0
        모호   0.5
        미확인 0        (막힘·미상 모두 0 — 정보량이 같다)

n — 그 의뢰의 진실 항목 수 (템플릿이 정한다)
```

- ~~추출은 LLM(구조화), 합산은 규칙.~~ → **전부 규칙.** 세는 대상은 **칸의 상태**이지
  문장이 아니다 (R9)
- **채점 대상은 그 의뢰의 진실 항목**이다. 진실에 없는 칸이 `확정`이어도 `C`를
  올리지 않는다 — **관계없는 것을 많이 아는 것은 준비가 아니다**
- `n = 0`이면 `C = 4`로 고정 (준비할 것이 없는 의뢰)

**워크드 예제** — 폐광의 트롤 무리 (진실 항목 3개: 대상 / 규모 / 특징 및 약점):

| 의뢰서에 적힌 것 | `cov` | `Σ` | `C` | 뜻 |
| ---- | ---- | ---- | ---- | ---- |
| *트롤* 만 (`대상` 확정, 나머지 미확인) | 1, 0, 0 | 1.0 | **1.3** | **낮음** — 몇 마리인지도 모르고 간다 |
| *트롤* + *다수* + *폐광* (`대상`·`규모` 확정) | 1, 1, 0 | 2.0 | **2.7** | **중간** — 머릿수는 맞췄으나 약점을 모른다 |
| + *햇빛을 꺼림* (`특징 및 약점` 확정) | 1, 1, 1 | 3.0 | **4.0** | **높음** — 낮에 몰아붙일 준비를 하고 간다 |

**한 칸이 `C`를 1.3 움직인다** — `F3`의 구간 폭이 2이므로 **두 칸이면 결과 등급이
통째로 바뀐다.** 이것이 청취가 목숨값인 이유다.

> ⚠ **이 수식은 `commission-form.md`와 공동 소유이며, 소유권은 `commission-form.md`의
> F2에 있다.** 이 문서는 **동일한 정의를 쓰고 있으며 독자적으로 바꾸지 않는다.**
> 채점표(`확정 1.0 / 모호 0.5 / 미확인 0`)나 `n`의 정의를 고쳐야 하면
> **`commission-form.md` F2를 먼저 고치고 이 절을 따라 맞춘다.** 두 곳에서 따로
> 진화하면 같은 의뢰서가 두 개의 `C`를 갖는다.

**F3. 파견 판정** `D = P + C − T` (T = 의뢰의 **실제 위험도**, 진실 측 숨은 값)
- 구간: `D ≥ 4` 완수 / `≥ 2` 진통 끝 완수 / `≥ 0` 부상 철수 / `≥ −2` 사망자 발생 / `< −2` 전멸
- 검증된 예 (프로토 실측): 전력 4 + 대비 4 − 위협 6 = 2 → 진통 끝 완수.
  빈 의뢰서(C=0)면 같은 무리가 −2 → 사망자 발생 — **적은 만큼의 차이가 목숨이다**
- 난수 항은 P2에서 ±1 시드 롤 검토 (없어도 성립 — 결정론 우선)

**`T`의 P1 값 — 등급별 고정** *(2026-08-10 확정)*:

| 실제 등급 | D | C | B | A | S |
| ---- | ---- | ---- | ---- | ---- | ---- |
| **`T`** | **3** | **4** | **5** | **6** | **7** |

**`T`는 숨은 값이다.** 플레이어에게 보이지 않으며 파견 후에 공개된다.
**세 개의 등급이 다른 시점에 존재한다** — 혼동하면 이 시스템 전체가 무너진다:

| | 무엇 | 보이는가 |
| ---- | ---- | ---- |
| **의뢰인의 주장** | 의뢰인이 말한 위험도 | 보인다 — **틀릴 수 있다** |
| **플레이어의 판정** | 내가 의뢰서에 적은 `D/C/B/A/S` | 보인다 — **F4에만 쓰인다** |
| **실제 위험** | 진실 측 등급 → `T` | **숨김.** 파견 후 공개 — **F3을 정한다** |

**등급의 뜻은 「필요한 파티 수준」이다** — 숫자의 크기가 아니라 **누구를 보내야
하는가**다:

| 등급 | 필요한 파티 |
| ---- | ---- |
| **D** | 신입 1 |
| **C** | 신입 2~3 또는 숙련 1 |
| **B** | 정규 파티 |
| **A** | 베테랑 파티 + **충분한 정보** |
| **S** | 정예 + 특수 대응 |

> **A 이상부터 정보가 요구 사항에 들어온다** — 전력만으로는 `T=6`을 넘길 수 없고
> `C`가 붙어야 한다. **기둥 6이 난이도 곡선에 새겨지는 지점이다.**

**R12 (신설). 의뢰 템플릿은 네 가지를 함께 가져야 한다** *(2026-08-10 — 데이터 규칙)*:

1. **실제 위험도 `T`** — 위 표의 등급별 고정값
2. **그 `T`를 설명하는 진실** — 왜 이만큼 위험한가 (`T=6`인데 *"고블린 한 마리"* 면 거짓)
3. **플레이어가 알아낼 수 있는 사실** — 청취 칸으로 도달 가능한 항목. **F2의 `n`이
   여기서 나온다**
4. **길드마스터북에서 참조할 기준** — 그 진실을 판단하게 해 주는 책의 항목.
   책에 없으면 플레이어는 **추측밖에 할 수 없다**

> **`T`와 진실이 맞지 않는 콘텐츠는 데이터 검증에서 실패시킨다 (빌드 게이트).**
> 이것을 런타임에 눈감아 주면 **플레이어가 배우는 인과가 망가진다** — 잘 물어보고
> 잘 판단했는데 죽는 일이 생기고, 그 순간 이 게임은 학습 불가능해진다.
> 밸런스 실수는 튜닝으로 고칠 수 있지만 **인과의 붕괴는 못 고친다.** AC-AD-10 참조.

**F4. 지원 판정** — 무리 g, 게시물 q에 대해:
```
지원   ⇔ 보수비 ≥ minPay_g  AND  정보충실도 ≥ minInfo_g  AND  위험허용_g ≥ 표기위험도_q
조건부 ⇔ 위 중 하나만 미달 (미달 항목이 코멘트의 소재가 된다)
무시   ⇔ 둘 이상 미달
```
- `보수비 = 게시 보수 / 시세(q)` (시세는 길드마스터북 표와 동일 소스),
  `정보충실도 = 채워진 슬롯 가중합 / 열린 슬롯 가중합`
  (`intake-system.md` F3의 `completeness`)
- 예: 셀린(minPay 1.2, minInfo 0.7) — 오우거 의뢰(시세 40) 게시 보수 30, 충실도 0.9
  → 보수비 0.75 미달 하나 → **조건부** ("보수가 시세 이하군요")
- 성향 파라미터는 무리마다 다르고 비공개 — 학습하는 것이 플레이의 일부다

**`표기위험도_q`는 플레이어가 의뢰서에 적은 `D/C/B/A/S` 등급이다**
*(2026-08-10 확정)*. `statedRisk`(의뢰인의 주장)가 **아니다.** `T`(실제)도 아니다.
**의뢰서에 있는 유일한 플레이어 입력**이며, 그것이 닿는 곳이 여기다.
비교를 위해 등급을 `D=1 … S=5`로 순서화한다.

> ### 확정 설계의 핵심 분리 — 등급과 결과는 다른 것을 정한다
>
> | | 무엇을 정하는가 | 입력 |
> | ---- | ---- | ---- |
> | **내가 적은 등급** | **누가 지원하고 배정되는가** | F4 |
> | **파견 결과** | **누가 돌아오는가** | **`P + C − T`** (F3) |
>
> **등급을 높게 적는다고 의뢰가 쉬워지지 않는다.** `T`는 진실이 정하고 내 글씨는
> 거기 닿지 않는다. 등급이 바꾸는 것은 **명단**뿐이다.
>
> **과대 기재(S 남발)의 대가는 이 경로로 돌아온다**: 높게 적으면 위험 허용치가
> 높은 **좋은 무리가 붙는다.** 그러나 같은 무리가 **게시 보수 요구도 함께 올린다**
> (`minPay`) — 시세 대비 배율이 안 맞으면 그들은 `조건부`나 `무시`로 답한다.
> **S라고 적어 놓고 D값 보수를 붙이면 아무도 안 온다.** 등급 인플레는 지갑으로
> 환수된다.
>
> **과소 기재의 대가는 더 조용하다**: 신출내기가 붙고, 그들이 `T=7`을 만난다.
> 이쪽의 회수는 F4가 아니라 **F3**이고, 청구서는 결과 대조 화면에서 온다 (기둥 6).

## Edge Cases

- **지원 0** → R8의 출구 3개가 전부 열려 있어야 한다. 어떤 조합의 게시물도 세 출구가
  모두 막히는 상태는 존재하지 않는다 (막다른 길 금지).
- **한 무리가 여러 의뢰에 지원** → 배정은 하루 1무리 1의뢰. 배정 순간 다른 의뢰의
  지원이 철회되고 해당 게시물은 유찰 규칙을 따른다.
- **모든 무리가 같은 의뢰에 몰림** → 나머지 게시물이 연쇄 유찰 — 의도된 압박.
  게시 보수 설계가 분산의 도구다.
- **끼워넣기 거부** → 거부 사유(관계·자존심·보수) 표시. 같은 판에서 재제안 불가.
- **로스터 전원 부상/파견 중** → 그날 게시물은 자동 보류 (기한만 소모). 파산 방어는
  경제 시스템(P3)이 다룬다.
- **역마진 게시** → 허용. 결산에 마진이 음수로 표기될 뿐 시스템 제재 없음.
- **요구 태그를 가진 모험가가 로스터에 없음** → 요구는 떠 있되 충족 불가.
  R5의 사건 분기에서 미보유 경로로 처리 — 태그는 자격 검사(하드 게이트)가 아니다.
- **기한 당일 게시** → 아침 지원 기회 1회뿐. 경고 표시.

## Acceptance Criteria

- **AC-AD-01** 의뢰서에 적히지 않은 진실 항목은 요구 태그를 만들지 않는다 (R4).
  같은 진실, 다른 의뢰서 → 다른 요구 태그 목록.
- **AC-AD-02** 같은 게시물 + 같은 로스터 상태 → 같은 지원 목록 (F4는 순수 함수, LLM 무관).
- **AC-AD-03** F3 경계값 테스트: D = 4.0/3.9, 2.0/1.9, 0/−0.1, −2.0/−2.1 이 각각 다른
  결과 구간에 떨어진다.
- **AC-AD-04** 지원 0 게시물에서 출구 3개(보수 인상·재작성·초빙)가 모두 조작 가능하다.
- **AC-AD-05** LLM 게이트웨이를 끈 폴백 모드에서 게시→지원→배정→판정→결산이 완주되고,
  **결과·인명·이벤트 로그가 켠 상태와 바이트 단위로 동일**하다 — 달라지는 것은 대사
  문자열뿐이다 *(2026-08-10 강화)*. ~~(대비 추출은 키워드 휴리스틱 폴백, 코멘트는
  템플릿)~~ → **대비 추출이 없다.** `C`는 규칙이 항상 계산한다 (R9·F2).
- **AC-AD-06** 게시 보수를 올리면 지원 무리 수가 단조 비감소한다 (다른 조건 고정).
- **AC-AD-07** 끼워넣기 거부가 실제로 발생 가능하고, 거부 시 사유가 표시된다.
- **AC-AD-08** 태그 보유/미보유가 파견 이벤트 로그에 서로 다른 이벤트를 남긴다 (R5 —
  확률 보정이 아니라는 증거).
- **AC-AD-09** 브라우저 실검증: 게시판 화면에서 지원 코멘트·배정·출발이 실제 클릭으로
  완주된다 (배선 통합 테스트 — 이 저장소의 2회 사고 재발 방지).
- **AC-AD-10** *(빌드 게이트, 2026-08-10)* **데이터 검증**: 모든 의뢰 템플릿이
  R12의 넷을 갖는다 — ① `T`가 등급표(D3/C4/B5/A6/S7)의 값이고 ② 그 `T`를 설명하는
  진실 항목이 있고 ③ 각 진실 항목이 **청취 칸으로 도달 가능**하고 ④ 판단 기준이
  길드마스터북에 있다. **하나라도 어기면 빌드 실패.** 특히 ③이 깨지면
  **알아낼 방법이 없는 정보가 목숨을 가르는** 상태가 된다.
- **AC-AD-11** *(2026-08-10)* **F2 워크드 예제 재현**: 폐광 트롤(진실 3항목)에서
  `대상`만 확정 → `C ≈ 1.3`, `+규모` → `C ≈ 2.7`, `+특징 및 약점` → `C = 4.0`.
  **`C` 계산 경로에 `fetch`가 없다** (정적 검사).
- **AC-AD-12** *(2026-08-10)* **등급과 결과의 분리**: 같은 의뢰·같은 무리에서
  플레이어가 적은 등급만 `D`↔`S`로 바꿔도 **`D = P + C − T`의 값과 파견 결과가
  불변**이다. 바뀌는 것은 F4의 지원 목록뿐이다.
