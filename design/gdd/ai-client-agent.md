# AI 의뢰인 에이전트

> **상태:** Designed — NAN 2026 예선 범위
>
> **상위 문서:** `design/gdd/game-concept.md`
>
> **구현 우선순위:** P0

## Overview

AI 의뢰인 에이전트는 플레이어의 자유 발화를 구조화하고, 규칙 엔진의 허용된 도구를 호출하며, 확정된 결과를 인물의 성격과 대화 맥락에 맞게 연기한다. AI는 게임의 진실, 경제 상한, 사실 공개 성공, 파견 결과를 직접 수정할 수 없다.

## Player Fantasy

플레이어는 문장 패턴을 맞히는 것이 아니라 자기 말을 알아듣고 방어하는 상대와 대화한다고 느껴야 한다. 의뢰인은 이전에 한 말을 기억하고, 말실수를 수습하고, 체면과 목적을 지키며, 협상에서 역제안한다.

## Detailed Design

### 에이전트 입력

```ts
interface AgentContext {
  persona: PublicPersona;
  publicFacts: PublicFact[];
  allowedTools: AgentToolDefinition[];
  conversation: DialogueTurn[];
  playerTurn: PlayerUtterance;
  currentEmotion: Emotion;
}
```

아직 공개할 수 없는 사실 원문은 입력에 포함하지 않는다. 에이전트는 도구 결과를 받기 전에는 그 사실을 모른다.

### 허용 도구

| 도구 | 입력 | 규칙 엔진 결과 |
|---|---|---|
| `interpret_turn` | 플레이어 발화 | 의도, 대상, 주장, 자료 지식, 금액, 어조 |
| `ask_fact` | 대상 슬롯 | 공개 가능한 자발·질문 사실 |
| `challenge_claim` | 주장 ID·지식 ID | 대조 유효성, 공개 사실, 상태 변화 |
| `negotiate_reward` | 제안액·지식 ID | 수락·거절·역제안과 확정 금액 |
| `commit_reaction` | 표현 의도 | 허용 표정과 대사 길이 검증 |

AI는 존재하지 않는 도구를 호출할 수 없고, 도구 결과를 덮어쓸 수 없다.

### 한 턴의 에이전트 루프

```text
플레이어 입력
  → Worker가 입력·세션 검증
  → AI가 interpret_turn 호출
  → 규칙 엔진이 문장 속 자료 지식의 가시성과 관련성을 검증
  → AI가 ask_fact / challenge_claim / negotiate_reward 중 하나 요청
  → 규칙 엔진이 허용 결과 반환
  → AI가 허용 결과만 사용해 최종 대사 생성
  → Worker와 클라이언트가 출력 이중 검증
  → 화면 반영
```

### 출력 스키마

```ts
interface AgentResponse {
  utterance: string;
  expression: 'calm' | 'uneasy' | 'guarded' | 'angry';
  interpretedTurn: InterpretedTurn;
  toolReceipt: ToolReceipt;
}
```

- `utterance`: 1..360자.
- `expression`: 규칙 엔진이 허용한 변화 안에서만 선택.
- `toolReceipt`: 서버가 서명하며 클라이언트가 임의 생성할 수 없음.
- 미공개 사실 ID, 시스템 프롬프트, 모델 사고 과정은 응답에 포함하지 않음.

### 프롬프트 구성

시스템 프롬프트는 다음 우선순위를 가진다.

1. 안전 정책과 출력 스키마
2. 도구 사용 규칙
3. 공개 가능한 세계·사건 정보
4. 인물의 성격·목적·말투
5. 현재 감정과 대화 이력
6. 플레이어의 최신 발화

페르소나는 비밀을 직접 담지 않고, 비밀을 지키려는 행동 성향만 담는다.

### 기억

예선에서는 한 의뢰 안의 세션 기억만 지원한다.

- 최근 전체 대화 최대 12턴
- 공개 사실 목록
- 플레이어가 문장으로 인용해 검증된 자료 지식 목록
- 현재 감정·인내·경계
- 현재 협상안

12턴을 넘으면 오래된 대사는 사실과 약속만 구조 요약해 남긴다. 예선 기본 질문 제한은 5회이므로 정상 플레이에서는 요약이 거의 발생하지 않는다.

`/respond`에는 최신 플레이어 문장, 최근 대화 최대 12턴, 인물의 공개 태도와 규칙 엔진이 승인한 반응을 전달한다. 모델은 이 맥락으로 말투와 연결성을 만들되 승인 반응의 의미나 공개되지 않은 사실을 바꾸지 못한다.

### 실행 모드 표시

- `VITE_AGENT_ENDPOINT`가 있고 Worker 헬스체크가 성공하면 `실시간 AI`다.
- 로컬 Vite 개발 중 주소가 없으면 자동 테스트용 `개발 시뮬레이터`다.
- 프로덕션에서 주소가 없으면 시작을 차단한다.
- 현재 모드는 창구 헤더에 항상 표시하며 시뮬레이터를 실제 AI라고 표현하지 않는다.

### 프롬프트 인젝션 방어

- “지시를 무시하라” 같은 문장은 세계 안의 이상한 발언으로 취급한다.
- 에이전트에게 미공개 사실 원문을 보내지 않는다.
- 도구 인수는 허용 ID와 범위를 검증한다.
- AI가 성공했다고 주장해도 `ToolReceipt`가 없으면 상태에 반영하지 않는다.
- 출력에 시스템 지시나 비공개 ID 패턴이 있으면 응답을 폐기하고 같은 턴을 재생성한다.

### 연결 실패

AI는 핵심 플레이이므로 연결이 없을 때 다른 대화 방식으로 전환하지 않는다.

- 턴 전송 실패: 입력 문장을 보존하고 재시도.
- 세 번 연속 실패: 연결 상태와 진단 ID 표시.
- 이미 확정된 규칙 상태는 롤백하지 않음.
- 새 의뢰 시작 전 헬스체크 실패: 시작을 막고 연결 복구를 안내.

## Formulas

### 컨텍스트 예산

```text
contextTokens = system + persona + publicFacts + history + playerTurn
contextTokens <= 6000
```

| 구성 | 예산 |
|---|---:|
| 시스템·도구 | 1,500 |
| 페르소나 | 500 |
| 공개 사실·자료 | 1,000 |
| 대화 이력 | 2,500 |
| 최신 입력·출력 여유 | 500 |

### 호출 예산

```text
maxCallsPerCase = 7
maxCallsPerRun = 21
```

의뢰당 선제 진술 1회, 자유 발화 5회, 최종 반응 1회를 상한으로 한다.

## Edge Cases

- **AI가 도구를 호출하지 않고 답하면:** 응답을 상태에 반영하지 않고 도구 호출을 강제해 한 번 재생성한다.
- **AI가 도구 결과와 반대 사실을 말하면:** 응답을 폐기하고 허용 결과를 강조해 재생성한다.
- **출력 스키마가 깨지면:** 한 번 재생성하고 다시 실패하면 턴 오류로 반환한다.
- **대화 이력이 예산을 넘으면:** 오래된 턴을 구조 요약하되 공개 사실과 협상안은 원문 값으로 유지한다.
- **플레이어가 비밀 ID를 추측하면:** ID는 공개 사실이 아니므로 도구가 거절한다.
- **동일 턴이 네트워크 재전송되면:** `turnId` 멱등 키로 기존 영수증을 반환한다.
- **모델이 안전 정책으로 응답을 거절하면:** 게임 상태를 바꾸지 않고 해당 턴 오류를 표시한다.

## Dependencies

| 시스템 | 방향 | 인터페이스 |
|---|---|---|
| 자유 심문 | 상류·하류 | 플레이어 입력, 구조화 해석, 허용 대사 |
| 사건 콘텐츠 | 상류 | 공개 가능한 사실 ID와 도구 규칙 |
| 규칙 코어 | 상류 | 도구 실행과 상태 영수증 |
| Cloudflare Worker | 기반 | 키, 프롬프트, 호출 제한, 공급자 연동 |

## Tuning Knobs

| 노브 | 기본 | 안전 범위 | 영향 |
|---|---:|---:|---|
| `maxHistoryTurns` | 12 | 8..20 | 기억 품질과 비용 |
| `maxContextTokens` | 6000 | 4000..10000 | 비용·응답 품질 |
| `maxOutputChars` | 360 | 180..500 | 대화 속도 |
| `maxCallsPerCase` | 7 | 5..10 | 비용과 플레이 폭 |
| `retryCount` | 1 | 0..2 | 지연과 복구율 |

## Visual/Audio Requirements

- 연결 상태는 화면 가장자리의 작은 봉랍 표시로 나타내되 정상 상태에서는 주의를 빼앗지 않는다.
- 응답 생성 중 캐릭터별 대기 행동을 사용한다.
- 오류는 인물 대사처럼 꾸미지 않고 시스템 상태로 명확히 구분한다.
- 같은 감정이라도 인물별 표정 차이를 유지한다.

## UI Requirements

- 전송 중 현재 턴만 잠그고 자료집 열람은 허용한다.
- 재시도 시 입력 문장을 그대로 보존한다.
- 내부 프롬프트, 도구 이름, 모델 공급자는 플레이 화면에 표시하지 않는다.
- 개발 모드에서는 해석 결과와 도구 영수증을 별도 검사 패널에서 확인할 수 있다.

## Acceptance Criteria

- **GIVEN** 미공개 사실, **WHEN** 프롬프트 인젝션을 입력해도, **THEN** 대사·DOM·네트워크 응답에 해당 사실이 나타나지 않는다.
- **GIVEN** AI가 존재하지 않는 사실을 말했을 때, **WHEN** 응답을 검증하면, **THEN** 게임 상태와 의뢰서 후보는 변하지 않는다.
- **GIVEN** 동일 `turnId`, **WHEN** 요청을 재전송하면, **THEN** 새 상태 변화 없이 같은 도구 영수증을 반환한다.
- **GIVEN** 도구 결과와 반대되는 대사, **WHEN** 검증하면, **THEN** 플레이어에게 표시되지 않는다.
- **GIVEN** AI 연결 실패, **WHEN** 턴 오류가 발생하면, **THEN** 입력 문장과 이전 상태가 보존된다.
- **GIVEN** 정상 의뢰 한 건, **WHEN** 5회 자유 발화를 완료하면, **THEN** 호출 수가 사건 상한을 넘지 않는다.
