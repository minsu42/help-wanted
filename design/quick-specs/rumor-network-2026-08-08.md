# Quick Design Spec: 소문 네트워크

**Type**: New Small System
**System**: 소문 네트워크 (systems-index #8, Feature 레이어, Tier 0)
**GDD Reference**: 없음 — 이 프로젝트는 `/design-system` 정식 GDD를 스킵한다.
상위 컨셉은 `design/gdd/game-concept.md`의 Core Mechanics 3번 / Short-Term 루프 절.
**Date**: 2026-08-08
**Scope**: 길드 홀에서 사람들과 대화해 의뢰의 숨은 사실을 얻는다. 그 사실을 흥정에
쓰는 것은 계약 협상(#9)의 몫이다.
**Estimated Implementation**: 6~7시간

---

## Overview

창구를 마감하면 플레이어는 길드 홀로 간다. 그날 홀에 있는 사람들과 대화하면, 그들이
**아는 의뢰인**에 대한 숨은 사실을 흘린다 — 단 **자기 성격을 거쳐서**. 이렇게 얻은
사실이 다음 날 창구에서 흥정 카드가 된다.

MVP는 **1홉 전파만** 한다: 사람 → 나. 3자 전파·시간 감쇠·왜곡 누적은 Tier 2다.

이 시스템이 이 게임의 차별점이자 밸런싱 리스크가 가장 큰 곳이다. 컨셉 문서가 기술
리스크로 명시했다 — *"정보가 너무 잘 흐르면 게임이 쉬워지고, 안 흐르면 도박이 된다."*
그래서 이 스펙의 설계 결정 대부분은 **정보 유입량을 노브 하나로 돌릴 수 있게 만드는
것**을 목표로 한다.

## Core Rules

### 1. 사실(Fact) — 정보의 단위

```
Fact = { id: `${contractId}:${kind}`, contractId, kind }
kind = 'realRisk' | 'realWealth'
```

의뢰 하나당 사실 2개를 심는다 (`factsPerContract`). `realRisk`는 흥정의 위험 고지
축을 열고, `realWealth`는 선불이냐 보상이냐를 가른다.

**`urgency`와 `hasAlternative`는 소문으로 얻지 않는다.** 흥정 중 의뢰인의 반박
("선불은 도저히 안 되겠소")이 그 정보 채널이다. 정보원이 둘로 나뉘어 있어야 대화만으로
모든 것이 풀리지 않는다.

### 2. 누가 아는가 — 인맥 그래프는 의뢰가 생성될 때 자란다

의뢰가 생성될 때, 그 의뢰인을 아는 모험가를 `knownByMin`~`knownByMax`명 뽑아
`Client.knownBy`에 기록한다. 뽑기 가중치는 `tenureYears`다 — 근속이 길수록 아는
사람이 많다. 뽑기 대상은 **월드 모험가 풀 전체**(길드원 + 외부인)다.

이 방식을 택한 이유는 **커버리지가 밸런스 노브가 되기 때문**이다. 인맥을 게임 시작
시점에 고정하면 "아무도 모르는 의뢰"가 통제 불가능하게 발생해 순수 도박이 되고,
반대로 다 알면 게임이 쉬워진다. 생성 시점에 정하면 이 값을 Day 3에 직접 돌릴 수 있다.

부수 효과가 정확히 원하던 것이다: **베테랑이 뽑힐 확률이 높으므로, 베테랑이 죽으면
정보망이 실제로 무너진다.**

### 3. 길드 홀 출석 — 희소성은 예산이 아니라 세계에서 온다

플레이어에게 "하루 N회 대화권"을 주지 않는다. 대신 **그날 홀에 누가 있는가**가
정해져 있다.

**월드 모험가 풀**: 총 `worldRosterSize`명(기본 22). 그중 8~12명이 길드원
(`inGuild: true`), 나머지는 외부.

매일 홀에 나타나는 사람:
- **길드원** 중 `status === 'available'`인 사람에서 `hallAttendanceMin`~`Max`명
- **외부 모험가** `visitorMin`~`visitorMax`명

`onMission` / `injured` / `dead`는 나타나지 않는다. → **파견은 곧 정보원 차출이다.**
베테랑을 긴 의뢰에 보내면 그동안 정보가 마른다. 계약 협상에서 기한 축을 잘라내며
잃은 일정 긴장이 여기서 더 자연스러운 형태로 되살아난다.

홀에 있는 사람과는 **각자 1회씩 자유롭게** 대화한다.

이 모델을 택한 이유: "3회 대화권"은 추상적 자원 관리지만 "오늘 홀에 있는 사람이
이들뿐"은 **세계의 사실**이다. 후자가 기둥 2("세상은 사람의 입을 통해서만 도착한다")와
맞는다 — 내가 정보를 고르는 것이 아니라 세상이 오늘 이만큼만 보내준 것이다.

### 4. 대화 1회의 결과 — 두 단계

| 단계 | 조건 |
|---|---|
| **① 인맥 공개** | **신뢰 무관.** 이 사람이 아는, 현재 열린 의뢰의 의뢰인이 `PlayerKnowledge.discoveredContacts`에 기록된다 |
| **② 사실 공개** | 성격·신뢰 판정을 통과해야 한다. 통과 시 사실 1개 (`talkative`는 2개) |

두 단계를 분리한 것이 이 시스템의 핵심 장치다. **무엇을 아는지는 못 들어도 누구를
아는지는 알 수 있다.** 길드 홀이 플레이할수록 밝아지고, 외부 모험가 정찰(§8)이
성립한다.

### 5. 성격 필터

| 태그 | 효과 |
|---|---|
| `talkative` | 한 번에 사실 2개 |
| `cautious` | 신뢰 임계값이 높다 (`trustThresholdCautious`) — 못 미치면 "잘 모르겠습니다" |
| `loyal` | 신뢰 임계값이 낮다 (`trustThresholdLoyal`) |
| `greedy` | 소액(`greedyPrice`)을 요구한다. 거절하면 침묵 |
| `bitter` | 위험도를 **실제보다 높게** 전한다 (+`traitDistortion`) |
| `boastful` | 위험도를 **실제보다 낮게** 전한다 (−`traitDistortion`) |

**성격 태그는 플레이어에게 항상 보인다.** 왜곡은 무작위가 아니라 **체계적**이며,
따라서 *"저 친구 말은 늘 과장이니 좀 깎아 듣자"* 를 배울 수 있다. 이것이 스탯이 아니라
플레이어의 안목이 성장한다는 말의 실체다.

능력치 표시 결정(`types.ts`의 `Grade`)과 같은 원리다 — **장부는 정직하고, 사람의 입이
필터다.**

왜곡은 **표시값에만** 걸린다. 흥정의 위험 고지 축이 열리는 조건은 "실제 위험도에 대한
사실을 얻었는가"이지 그 값이 정확한가가 아니다. 진짜 값은 결과 대조 화면에서만 드러난다.
`boastful`의 말을 믿고 위험을 과소평가하는 것이 곧 플레이어의 실수가 된다.

### 6. 신뢰

`trust`(0~1)가 성격별 임계값 미만이면 사실을 말하지 않는다.

| 사건 | Δtrust |
|---|---|
| 살아 돌아옴 | `+trustOnSurvive` |
| 부상 귀환 | `−trustOnWound` |
| 사망 (생존 길드원 전체에게) | `−trustOnDeath` |
| **알고도 위험을 고지하지 않은 계약에서 사망** | `−trustOnDeceit` (가장 큼) |

착취가 정보망을 스스로 조인다. 이것이 MDA의 Expression 축("정직한 중개인이 될지
착취자가 될지")을 지탱하는 유일한 기계적 장치다.

### 7. 유통기한

사실은 의뢰에 붙어 있다. 의뢰가 결렬되거나 타결되면 그 사실은 사라진다. 별도 만료
로직이 없다 — 컨셉의 *"정보에는 유통기한이 있다"* 가 자동으로 성립한다.

### 8. 외부 모험가 — 정찰과 영입

§4의 두 단계가 외부인에게 그대로 적용되는데, 결과가 갈린다:

| 단계 | 길드원 | 외부인 |
|---|---|---|
| ① 인맥 공개 | 신뢰 무관 | **신뢰 무관 — 똑같이 열린다** |
| ② 사실 공개 | 신뢰 판정 | 신뢰 0 → 사실상 불가 |

그래서 외부인과의 대화는 **정찰**이다. 무엇을 아는지는 못 듣지만 **누구를 아는지는
안다.** *"저 사람은 상단주를 안다. 영입하면 그 의뢰가 열린다."* 영입이 눈감고 하는
도박이 아니라 정보에 근거한 투자가 된다.

영입 자체의 규칙은 별도 시스템(#19)이 소유한다. 이 스펙은 대화 규칙까지만 정의한다.

### 9. 온보딩과 위상 변화 (양 끝단)

- **Day 1**: 첫 의뢰 전에 길드원 한 명이 먼저 다가와 사실 1개를 준다. "정보 = 흥정력"을
  강제로 한 번 체험시킨다. 컨셉의 Design Risk("정보=흥정력 루프가 학습되지 않을 위험")
  완화책이다.
- **명성 임계 이상**(`reputationForFreeRumor`): 매일 아침 사실 1개가 자동으로 도착한다.
  초반에는 내가 물어보러 다니고, 후반에는 사람들이 가져온다. 같은 책상, 달라진 위상 —
  기둥 2를 깨지 않고 성장을 표현하는 방법이다.

## Tuning Knobs

| Knob | Default | Range | Category | Rationale |
|---|---|---|---|---|
| `hallAttendanceMin` / `Max` | 3 / 4 | 2–6 | gate | **1순위 노브.** 이 게임 난이도의 주 조절판 |
| `visitorMin` / `Max` | 0 / 2 | 0–3 | gate | 0을 허용해 "오늘은 아무도 안 왔다"를 만든다 |
| `worldRosterSize` | 22 | 16–30 | gate | 길드원 8~12명 + 외부 |
| `factsPerContract` | 2 | 1–3 | gate | 컨셉 Open Question 2의 초기값 |
| `knownByMin` / `knownByMax` | 1 / 2 | 0–4 | gate | 0을 허용하면 "아무도 모르는 의뢰"가 생긴다 — 의도적으로 쓸 것 |
| `tenureWeightExponent` | 1.5 | 1.0–3.0 | curve | 높을수록 베테랑에 정보가 집중된다 = 죽음이 더 아프다 |
| `trustThresholdDefault` | 0.4 | 0.2–0.7 | gate | |
| `trustThresholdCautious` | 0.6 | 0.4–0.9 | gate | |
| `trustThresholdLoyal` | 0.2 | 0.0–0.4 | gate | |
| `traitDistortion` | 0.15 | 0.05–0.4 | feel | 크면 정보가 쓸모없어지고 작으면 성격이 무의미해진다 |
| `greedyPrice` | 20 | 10–50 | curve | 의뢰 1건 보상의 약 15%. 아프되 낼 만해야 한다 |
| `trustOnSurvive` | +0.05 | 0–0.2 | curve | |
| `trustOnWound` | −0.10 | 0–0.3 | curve | |
| `trustOnDeath` | −0.15 | 0–0.4 | curve | |
| `trustOnDeceit` | −0.35 | 0.2–0.6 | curve | 침묵의 대가가 가장 커야 한다 |
| `reputationForFreeRumor` | 40 | 25–70 | gate | 명성 0~100 스케일, 시작 10. 중반에 도달해 위상 변화가 체감되게 |

전부 `src/data/balance.json`의 `rumor` 섹션. 코드에 상수를 박지 않는다.

> **`hallAttendanceMax`는 이 섹션에 없다.** 길드 등급에서 온다 (`guildTiers[].hallAttendanceMax`,
> 등급 1→4 / 2→5 / 3→6). 플레이어가 돈으로 정보 유입량을 사는 구조이기 때문이다.

## Acceptance Criteria

- [ ] 같은 시드 + 같은 대화 순서면 **항상 같은 사실**이 나온다
- [ ] 같은 시드면 홀 출석자 구성이 항상 같다
- [ ] 의뢰인의 `knownBy`에 없는 사람은 그 의뢰의 사실을 절대 말하지 않는다
- [ ] `trust`가 임계값 미만이면 사실을 말하지 않는다 (성격별 임계값이 적용된다)
- [ ] `talkative`는 1회 대화에서 2개, 그 외는 1개를 말한다
- [ ] `bitter`가 전한 위험도 > 실제 > `boastful`이 전한 위험도
- [ ] 왜곡된 값을 받아도 **위험 고지 축은 열린다** (게이트는 획득 여부로 판정)
- [ ] 대화하면 그 사람이 아는 열린 의뢰의 의뢰인이 `discoveredContacts`에 기록된다
- [ ] **외부 모험가는 인맥은 공개하되 사실은 공개하지 않는다**
- [ ] `onMission` / `injured` / `dead`는 홀에 나타나지 않는다
- [ ] 홀 출석 인원이 `hallAttendanceMin`~`Max` 범위 안이다
- [ ] 홀에 있는 사람과 하루 1회씩만 대화할 수 있다
- [ ] Day 1 무료 소문은 홀 출석과 무관하게 도착한다
- [ ] 의뢰가 종료되면 그 의뢰의 사실은 더 이상 조회되지 않는다
- [ ] 모든 노브가 `balance.json`에서 읽힌다
- [ ] 회귀: 획득하지 않은 사실은 어떤 화면에도 노출되지 않는다

**필수 테스트**: `.claude/docs/technical-preferences.md`의 3대 필수 테스트 중 3번
("소문 전파 — 성격 필터를 거친 정보 공개 범위"). 위 항목 3·4·6·9를 단위 테스트로
고정한다.

## Tier 2 (기록)

3자 전파(사람 → 사람 → 나), 시간 감쇠, 왜곡 누적. 컨셉 문서가 복잡도 폭발 리스크로
명시한 항목들이며 MVP에서 제외한다.
