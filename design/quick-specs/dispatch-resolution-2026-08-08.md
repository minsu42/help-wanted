## Overview

타결된 계약에 모험가를 배정하면, **파티 역량 합 vs 실제 위험도**의 비율로 성공·부상·
사망이 갈린다.

사람이 죽는 지점이므로 이 게임에서 감정적으로 가장 무거운 시스템이고, MVP 핵심 가설
(*"플레이어는 모험가의 죽음을 자기 판단의 결과로 받아들인다"*)이 검증되는 곳이다.
"받아들인다"가 성립하려면 죽음이 납득 가능해야 하고, 그것이 이 스펙의 모든 설계
결정을 지배한다.

## Core Rules

### 1. 배정

- 파티 크기는 1 ~ `contract.maxPartySize`. 큰 의뢰일수록 더 많이 받는다.
- `status === 'available'`인 길드원만 배정할 수 있다.
- 배정된 사람은 `contract.durationDays` 동안 `onMission`이 된다.
  → **그동안 길드 홀에 나오지 않는다. 파견은 곧 정보원 차출이다.**

**거부 규칙** — `goal`이 장식이 아니라 행동을 바꾼다는 결정의 실현이다.

> **2026-08-09 개정 — 이 표의 「반응」 열은 폐기됐다. 판정 조건은 그대로 살아 있다.**
>
> **거부가 게임을 멈췄다.** 가용한 모험가가 전부 거부 상태가 되면 배정 화면에
> 체크할 사람이 없어 확정이 영구히 비활성인데 나갈 문이 없었다(자동 플레이 6회 중
> 3회 정지). 원인은 임계값이 아니라 산술이다 — `guildInitialTrust`(0.5)에 대해
> `trustOnDeath`(−0.15) + `trustOnDeceit`(−0.35) = −0.5라서 **은폐 사망 한 번이면
> 길드원 전원이 정확히 0.0**이 되고, 회복 수단인 `trustOnSurvive`는 파견을 나가야
> 받으므로 회복 경로까지 닫힌다.
>
> 이제 거부는 **꺼림**이다 — 막지 않고 경고하며, 강행하면
> `forcedAssignmentTrustPenalty`(−0.1)와 `forcedAssignment` 기억을 남긴다.
> 개정판: `design/quick-specs/assignment-reluctance-2026-08-09.md`.

| 조건 | 반응 | ~~이전~~ → 현재 |
|---|---|---|
| `goal === 'survival'` 이고 공개 위험도 > `survivalRefusalRisk` | ~~배정을 거부한다~~ → 꺼린다(경고 + 강행 시 대가) | 게이트 → 경고 |
| `goal === 'glory'` 이고 공개 위험도가 높음 | 자원한다 (UI에서 강조) | 변경 없음 |
| `trust < assignmentTrustThreshold` | ~~거부한다~~ → 꺼린다(경고 + 강행 시 대가) | 게이트 → 경고 |

판정은 **공개 위험도**로 한다. 모험가도 실제 위험을 모르는 것이 정상이다 —
알았다면 그것은 소문이고, 소문은 플레이어에게 오는 것이다. 이 비대칭이 유지되어야
"내가 알고도 보냈다"는 문장이 성립한다.

### 2. 판정 공식 — 마진에 반비례하는 무작위

```
ratio       = Σ(파티원 capability) / 실제 위험도

distance    = |ratio − 1|
uncertainty = max(0, maxUncertainty × (1 − distance / certaintyBand))

effective   = ratio + rng.range(−uncertainty, +uncertainty)

effective ≥ successRatio (1.00) → 'success'
effective ≥ injuryRatio  (0.75) → 'injured'
그 외                           → 'dead'
```

기본값(`maxUncertainty` 0.25, `certaintyBand` 0.40)에서의 거동:

| ratio | uncertainty | 결과 |
|---|---|---|
| 1.5 | 0 | **확정 성공** |
| 1.2 | 0.125 | 성공 확정 |
| 1.0 | 0.25 | 성공 또는 부상 (사망 사실상 없음) |
| 0.8 | 0.125 | 부상 위주, 사망 일부 |
| 0.6 | 0 | **확정 사망** |

**양 끝에 확정 구간이 있고 가운데만 도박이다.** 이것이 이 공식의 전부다.

여유 있게 보내면 죽지 않고, 아슬아슬하게 보내면 도박이 되는데, **플레이어는 자기가
아슬아슬하게 보냈다는 것을 알고 있었으므로 죽어도 납득한다.** 완전 결정론이면 정보가
완벽할 때 아무도 죽지 않아 게임이 사라지고, 완전 무작위면 판단이 무의미해진다.

그리고 사망은 실질적으로 두 경우에만 일어난다: **유혹 의뢰에 무리했거나, 잘못된 정보를
믿었거나.** 둘 다 플레이어의 판단이며, ~~컨셉의 사망률 가설(15일당 1~2명)과도
맞는다~~.

> **2026-08-09 개정 필요.** 15일 고정 회차가 폐지되고 막 구조(캠페인 8~15시간,
> 미검증)로 바뀌면서 "15일당 1~2명"이라는 기준 자체가 무의미해졌다. 새 시간
> 단위(시간? 막? 의뢰 건수?) 기준의 사망률 가설은 `game-concept.md` Open Question 7
> 에도 없다 — 미해결.

무작위는 시드 PRNG(`src/domain/rng.ts`)를 통과한다. 같은 시드 + 같은 입력이면 언제나
같은 결과다.

### 3. 사상자 선택

부상·사망 대상은 **역량이 낮을수록 뽑힐 확률이 높다** (가중치
`1 / capability^casualtyBias`).

*"보상이 좋아서 신입을 보냈다. 안 돌아왔다."* — MVP가 목표로 삼은 그 문장이 여기서
나온다. 동시에 베테랑을 섞으면 그가 방패가 되므로 **아끼는 사람을 보호하려면 그를
보내야 하는** 뒤틀린 선택이 생긴다. 그리고 베테랑을 보내면 정보망 전체를 걸게 된다.

MVP는 사상자를 **1명**만 발생시킨다.

### 4. 결과별 처리

> **2026-08-09 개정 — 잔금 지급 판정과 선불 개념 모두 폐지.**

| 결과 | 의뢰 | 자금 | 명성 | 사람 |
|---|---|---|---|---|
| `success` | 완수 | ~~잔금 지급 판정 (`wealth`)~~ → **결정론적 전액 지급 (2026-08-09)** | `+repOnSuccess` | 전원 복귀 |
| `injured` | 완수 | ~~잔금 지급 판정~~ → **결정론적 전액 지급 (2026-08-09)** | `+repOnSuccess × repInjuryPenalty` | 1명 `injured` (`injuredDays` 후 `available`) |
| `dead` | **실패** | ~~**잔금 없음 — 선불만 남는다**~~ → **보상 없음 (2026-08-09).** 선불 개념이 없으므로 실패 시 지급 자체가 없다 | `−repOnDeath` | 1명 `dead` (영구) |

실패의 대가가 이제 이중이다 — 사람, 명성. ~~**선불을 받아뒀는지가 여기서 값을
한다.** 계약 협상의 선불 축과 파견 판정이 이 지점에서 연결된다.~~ → **폐기
(2026-08-09).** 선불 축이 사라졌으므로 이 연결점도 사라진다.

### 5. 파급 (다른 시스템으로의 출력)

> **2026-08-09 — "이중 손실" 원칙 철회.** 아래 `trust` 갱신은 살아남되, 그 하락이
> 예전처럼 "정보망(사실 공급) 축소"를 의미하지 않는다 — 길드원이 더 이상 사실을
> 공급하지 않기 때문이다 (`design/quick-specs/rumor-network-2026-08-08.md` 상단
> 개정 참조). 사망의 대가는 이제 **자금·전력 손실 + 상실의 사회적 반응**
> (`production/roadmap.md` P4 "상실 반응" — `lostComrade` 기억, 며칠간 조언·자원
> 안 함)으로 재정의된다. `trust` 수치를 그대로 이 용도에 재사용할지, 별도 축을
> 새로 만들지는 미정 — 미해결.

**`trust` 갱신** (소문 스펙 §6의 표):
생존 `+`, 부상 `−`, 사망 `−`, **알고도 고지하지 않은 계약의 사망 `−−−`**.

**`Memory` 기록**:
- 파티 전원: `sentToDanger` 또는 `sentSafe` (공개 위험도 기준)
- 결과에 따라: `survived` / `wounded`
- 생존자 전원: `lostComrade` (사망 발생 시, `subjectId`에 사망자)
- 플레이어가 실제 위험을 알고도 고지하지 않았으면: `wasDeceived`

**결과 대조(#11)에 넘길 것**:
공개 위험도 / 소문으로 들은 값(왜곡 포함 + **누가 말했는지**) / **실제 위험도** /
파티 역량 합 / `ratio` / 사용된 `uncertainty`.

마지막 두 항목이 중요하다. **`ratio`와 `uncertainty`를 보여주면 "얼마나 아슬아슬했는지"가
전달되고, 그것이 학습 루프를 닫는다.** 컨셉의 1순위 설계 리스크("창발이 무작위처럼
느껴질 위험")에 대한 최종 방어선이 이 데이터다.

## Tuning Knobs

| Knob | Default | Range | Category | Rationale |
|---|---|---|---|---|
| `successRatio` | 1.00 | 0.9–1.2 | gate | 기준점 |
| `injuryRatio` | 0.75 | 0.6–0.9 | gate | 사망 하한. **사망률 조절 1순위 노브** |
| `maxUncertainty` | 0.25 | 0.1–0.5 | feel | 도박 구간의 폭 |
| `certaintyBand` | 0.40 | 0.2–0.8 | feel | 확정 구간이 시작되는 거리 |
| `casualtyBias` | 1.5 | 1.0–3.0 | curve | 높을수록 약자가 죽는다 |
| `injuredDays` | 3 | 1–5 | gate | ~~부상의 실질 비용 = 정보원 공백~~ → **재검토 (2026-08-09).** 길드원이 사실 공급자가 아니게 되어 "정보원 공백"의 의미가 약해진다. 다만 의견·관계 관리(P4)를 위한 홀 결석은 여전히 비용이다 |
| `survivalRefusalRisk` | 90 | 60–140 | ~~gate~~ → **warning** | 위험도 0~200 스케일. 상위권 의뢰만 꺼리게 |
| `assignmentTrustThreshold` | 0.15 | 0.0–0.4 | ~~gate~~ → **warning** | ~~낮게 — 배정 거부가 잦으면 답답하다~~ → **2026-08-09**: 더 이상 게이트가 아니므로 올려도 게임이 멈추지 않는다. 답답함의 근거가 사라졌다 |
| `forcedAssignmentTrustPenalty` | −0.1 | −0.3~0 | cost | **2026-08-09 신설.** 꺼리는 사람을 강행한 대가. `trustOnDeath`(−0.15)를 넘지 말 것 |
| `repOnSuccess` | +2.5 | 1–5 | curve | 명성 0~100, 시작 10. 15일 20건이면 좋은 회차에 55 근처 |
| `repOnDeath` | −6 | 3–12 | curve | **사망 1회가 성공 2~3회를 지운다** |
| `repInjuryPenalty` | 0.6 | 0.3–1.0 | curve | 부상해도 의뢰는 완수했다 |

`src/data/balance.json`의 `dispatch` 섹션. 코드에 상수를 박지 않는다.

## Acceptance Criteria

- [ ] 같은 시드 + 같은 파티 + 같은 의뢰면 **항상 같은 결과**가 나온다
- [ ] `ratio ≥ 1 + certaintyBand`이면 **항상** `success` (무작위 폭이 0)
- [ ] `ratio ≤ 1 − certaintyBand`이면 **항상** `dead`
- [ ] `ratio == 1.0`에서 `dead`가 나오지 않는다
- [ ] 사상자는 파티 내 저역량자가 더 자주 뽑힌다 (반복 시행 통계로 검증)
- [ ] ~~`dead` 결과에서 잔금이 지급되지 않고 선불은 유지된다~~ → **개정 (2026-08-09):
  `dead` 결과에서 보상이 전혀 지급되지 않는다 (선불 개념 자체가 폐지됨)**
- [ ] 배정된 모험가는 `durationDays` 동안 길드 홀에 나타나지 않는다
- [ ] 부상자는 `injuredDays` 후 `available`로 돌아온다
- [ ] `dead`는 영구다 — 어떤 경로로도 `available`로 돌아오지 않는다
- [ ] `goal === 'survival'` 모험가는 공개 위험도가 임계 초과면 배정을 거부한다
- [ ] 알고도 고지하지 않은 계약의 사망에서 `trust` 하락폭이 가장 크다
- [ ] 결과 대조에 `ratio`와 `uncertainty`가 전달된다
- [ ] 모든 노브가 `balance.json`에서 읽힌다 — 코드에 리터럴 숫자 없음
- [ ] 회귀: 파견 중인 의뢰의 실제 위험도가 결과 발표 전에 노출되지 않는다

("파견 결과 판정 — 실제 위험도 vs 파티 역량 → 성공/부상/사망"). 위 항목 2·3·4·5를
